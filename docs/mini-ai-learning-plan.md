## 新版流程

以下能力已实现；个人计划不会被示例数值改写，旧组事实与版本保留：

- 每日目标只计最终完成的新词，组大小独立配置；到期与积压复习全部处理后才能开始或恢复新词。
- 每词独立经过完整词卡、例句回忆、单词回忆，默认五词窗口、隔三个不同词允许复现；不会退回词卡，不腾位。通过三阶段腾位，未满组时下一张优先补新词；组满先拼写和翻译，窗口尾部跨组、跨日保留。
- 阶段 1/2 初选后必须展开完整卡核对，读词后停半秒读例句；提供记错改判和下一词，下一词才正式推进阶段或退 0。移除该词卡的通用撤销与常驻保存成功提示，退出保留核对态。该流程只用于新词和复习三轮未清晰后的重学；复习窗口只补待重学复习词。
- 新词与复习拼写最多三轮首答，后续仅重测上一轮首答错误词，订正另计；第三轮仍错可继续，较近复习。复习判断三轮未清晰转三阶段重学，再拼写，不增加翻译和新词数量。
- 翻译确认下一题后直接进入下一道翻译；原答、完成事件、固定证据范围和后台评价任务先持久保存。评价当前逐题处理，不依赖整组结束，只有首页显示处理/待重试状态。
- 教学反馈和调度评价分别保存。评价理由、证据、模型与规则版本、服务端采用结果、排期前后值都可追溯；答后聊天不能改写首答。AI 提交评价，由程序决定采用与排期。
- 新词最终完成时先建立次日复习，随后采用后台评价；迟到结果不能覆盖新的实际复习。综合评价使用固定 FSRS-6，保留两类能力与支持条件，长间隔最多在 3 个自然日内错峰。
- 备课池以剩余目标加窗口大小滚动准备，区别于已进入学习的词；当前材料优先，未来储备未齐不能阻塞已经可学的内容。

旧 `three-rounds-v1`、五轮上限、十分钟提醒和当前写作反馈不改排期均是迁移与兼容背景，不作为新版本的完成标准。保留已认可的菜单，本轮更新应用包；导出、恢复和清理继续暂缓。

## 当前版本中一次学习的实际行为

本节保留旧组兼容说明。下面的整组三轮、五轮拼写和定性反馈限制仅用于旧版本；新建组采用上节的窗口和后台评价。

首页优先显示所选词库、当前计划容量、今日模式和到期复习量，提供直接调整计划的入口。容量明确按每次标注。今日记录跨所有任务按实际发生日期统计新词记忆、复习练习和写作提交，重复词按拼写与释义去重；新词记忆使用记住记录，复习练习使用实际判断或拼写，写作按实际提交去重。保留任务和四个月学习记录默认折叠，底部保留「开始／继续」和下一阶段提示。当前小窗约 360 × 300 点，启动默认不置顶，开发版默认正常流程首页。核心学习、聊天和设置按需切换，不同时挤入多栏。主要动作始终可达，长解释与详细记录按需展开；开发阶段选择继续放在现有菜单的 `dev` 二级入口，仅开发版显示。

下拉菜单的「学习计划」展示长期设置、今日调整和本次容量，保存后显示服务端回执。学习顾问也能通过同一组业务规则调整计划，并在工具提交成功后说明作用范围。用户不必理解后台模型、线程或工具配置才能学习。

| 阶段             | 程序负责                                       | AI 参与                                                  |
| ---------------- | ---------------------------------------------- | -------------------------------------------------------- |
| 复习             | 到期选择、自评、拼写、纠错、帮助记录与暂停恢复 | 核心复习完全不需要 AI；用户主动提问时才进入聊天          |
| 学习准备         | 固定当前目标和预算，检查材料是否齐备           | 按词组批量准备简单例句，尽量使用已知词和已有重点         |
| 新词观看与总拼写 | 自主观看、自评、整组门槛和真实轮次             | 不逐卡干预；闲聊或问题由用户主动发起                     |
| 写作准备         | 根据已保存进度确定可用目标、题量与支持条件     | 准备简单表达练习、中译英和英译中，围绕已有重点换语境     |
| 写作与反馈       | 先保存原答，再保存一次有效反馈与帮助事件       | 解释哪里表达得好、哪里可改进和本次重点，提交后可继续交流 |
| 小结与恢复建议   | 给出真实事实、未完成位置和当前可选任务         | 必要时解释建议或形成短小结，不控制成绩与阶段门槛         |

单卡默写已接入原生词卡。复习自评后、新词标记记住后可主动开启，撤销当前自评或最近记住标记时收起。新词标记后保留当前卡，用户明确前进后才换词。单卡练习保存额外输入、比对、揭晓与帮助，属于支持练习。新词按初见、语境、词义三轮推进，每词三个点逐轮变绿，初见即可使用按词与轮次保存的草稿。全组完成三轮后进入首轮总拼写，后续只重测首答错误词。每词最多五轮首答，订正次数另计，第五轮仍错直接暂缓并提高后续练习优先级。正确答案显示绿色，下一次回车前进。

旧整组流程的命令版本为 `memory-rounds-v1`，组内记忆版本为 `three-rounds-v1`。三轮分别是完整词卡、仅英文例句、仅英文单词，后两轮可主动展开。想起来的词完成当前轮，仍需巩固的词排到当前轮队尾，第三轮全部完成才开始拼写。草稿保留按词、轮次保存的原始输入与揭晓。已有作答的旧组沿用已保存算法，零作答组在明确开始或继续后可启用新流程。

新词与复习拼写均以每词首答为轮次单位，首轮覆盖当前组，后续只复测前轮首答错误词。首答成功的词退出本次队列，订正另行计数，正确或订正成功后保留绿色结果并等待再次回车。第五轮首答仍错立即暂缓，保存 `practicePriority: 5` 与十分钟后的 `nextProbeAt`。这两项用于后续练习选择，FSRS 状态和真实 due 保留其独立测量依据。每次合格独立 Good 降低一级额外优先级，归零后清除该提醒。只复习组采用同一五轮上限。

独立拼写检验使用中文提示和原始首答，用户从独立入口明确开始。该页面关闭自动语音和其他词卡操作，服务端按实际曝光、帮助、间隔与交错事实分类，合格的独立成功/失败分别交给 FSRS 的 Good/Again。拼写维度已接入 `ts-fsrs@5.4.2` / FSRS-6，目标保持率 0.90，关闭 fuzz，学习与重学步骤为 10 分钟。已介绍但未独立检验的词保存待检验时间，默认 10 分钟后提醒。旧排期作为历史保存，新计划从调度快照的真实 due 选择候选。

复习不依赖模型或外网；统一数据后依赖本机学习服务正常运行。模型离线时，已有材料可继续使用；未准备的内容保持待准备，不用编造结果推进阶段。

### 何时准备材料

平台先选择目标，再查已有合格材料。确认会开始本组且材料不足时，才创建一次备课任务；有复习时已在后台准备后续新词例句与所选组音频，当前复习照常进行。进入新词若例句或音频未齐，展示选词、例句、单词音频、例句音频四步的实际数量和总体进度。全部就绪后进入看词并自动读词。预取以当前组及有明确预算的下一步为限，不一次准备整个词库。

例句可以提前生成；写作题的初稿可复用同一重点，但最终题量、难度和支持方式必须结合总拼写的真实结果。用户修改计划时只调整尚未开始的内容，当前输入、已提交答案和有效材料继续保留。后台结果绑定目标集合、计划与材料版本；已取消或过期任务不能覆盖当前内容。

### 已核验原文与自拟例句

本地原文素材通过个人服务数据中的 `materials/catalog.json` 与 `materials/sources/` 保存全文、书目身份和 SHA-256，启动时核验后建立可重建句子索引。当前收录 Project Gutenberg 的《爱丽丝梦游仙境》#11 和《绿野仙踪》#55。备课上下文按目标词与用户句子等级最多提供三个原句候选，AI 可选适合当前义项的原文并翻译，也可使用自拟句。

提交带来源的例句时，服务端同时核对引用 ID、英文、书名、URL 和定位信息。原文在译文前显示书名，AI 自拟句按普通例句展示。已保存材料保留所选英文和出处，个人全文与索引继续随数据目录管理。

### 写作反馈的边界

学习例句和写作题采用不同句子与情境，允许复练同一个常用表达。先给可理解的短句，按需要提供框架或词库，逐步减少支持；不能将无支持自由写作设为初学者起点。

反馈默认包含表达正确或合理之处、一至两个优先改进点、一个可复用重点和必要解释。参考译法是示例，接受意思成立的不同表达。AI 不给译文数值分数，也不用「正确／部分正确／错误」直接驱动复习日期。反馈是教学材料，不转换为 Good、Again、过关或长期掌握；将来若需要独立语义测验，应另建题型、核对与证据规则，不借用这份写作反馈结算。

当前保存固定写作材料、题目身份、方向、用户原答、一次有效反馈及其时间；反馈含表达优点、改进点、重点和参考译法。已发布材料和已提交原答不能被重试覆盖，批改失败不丢原答，重复请求依据已有回执处理。正式反馈修订、用户修订稿和完整答案揭晓版本仍待后续实现，不能将当前一次反馈保存称作完整修订历史。

学习顾问在当前词卡回复前先保守保存 `potentialHelp` 曝光；请求关联目标与原答序号，不能事后污染已保存首答。带帮助的首答保留支持条件，不用于较长首间隔或复习晋级。既有拼写轮次仍保存支持条件，只有显式独立检验的合格首答采用 FSRS 评分。过早、有帮助、已揭晓或曝光未知的作答保存分类与原始事实，等待后续独立证据。

## 重点挂在词义上，优先复练

重点是可复用的常用搭配、短句或表达规则，关联稳定词义身份，可以同时关联多个词。它不是聊天里无法检索的一段文字，也不自动成为独立排期的学习对象。

当前保存重点 UUID、关联词义、表达与简释、来源学习组及可选原答引用、引入与更新时间、状态、原因和变更记录；写作材料与曝光可引用已有重点。词义身份按规范化拼写与当前释义生成，音标变化不另造同一词义；修改释义会成为不同身份，自动词义合并不在本步范围。展示过、练过与在新情境中独立用出仍须分别观察，不能只累计「出现次数」后宣布掌握。

AI 备课先查询该词义已有重点及近期练习，优先换语境复练。低频变体不因模型想扩写就加入今日负担。首版业务接口已限制每词义最多两个活跃重点、每个学习组最多新增一个重点；一条重点可关联组内多个词义，仍占一个新增名额。归档或暂缓不重置本组新增预算，不能通过重复创建绕过上限。这些是待使用验证的产品负荷策略，不是科学阈值。

当前支持经业务接口新增重点、修改简释与原因、暂缓、归档及在容量允许时恢复；历史材料和练习引用保留。程序校验来源组、词义身份、重复表达和容量，AI 说明为何需要扩展。合并重点及用户可调整的扩展预算仍待开发；当前不会因一句扩展请求自动突破硬上限。某个重点暂时不用时不删除已发生的学习。

## 当前长期、今日和本次计划

下述容量目前按每次服务词数执行。新规则的每日最终完成目标、每组数量和五词记忆窗口是不同概念，迁移时不能直接复用旧字段或把首次接触视为完成；恢复旧新词任务也要先检查当天到期复习门槛。

| 层级     | 用途                                         | 生效与恢复                                           |
| -------- | -------------------------------------------- | ---------------------------------------------------- |
| 长期计划 | 常态频率、每次容量、难度和偏好               | 持续生效，保存变更版本                               |
| 今日调整 | 今天少学、只复习、不学或改变今日新词量       | 仅指定本地日期生效，次日回到长期计划；不补成双倍欠账 |
| 本次调整 | 当前会话只练一个词、缩短时间、暂停或提前结束 | 绑定当前会话；保留原任务进度，不改长期设置           |

当前学习顾问已提供计划工具。用户明确说「今天少学」「今天不学」时，AI 可按其意图调用相应接口，并在保存回执后简述实际作用范围；含糊的数量或跨天意图才需要简短澄清。计划变更不撤销已保存的学习，也不将未作答记为失败。当天不学习可以取消尚未开始的准备工作，未完成学习留在可继续的位置。

应用按用户本地日期判断「今天」，计划记录时区和日期，事件保留带时区的实际时间。不能因服务端时区、跨日或更换机器而把今日调整错误延续。

隔了几天再回来时，平台查询最后活动、未完成组、真实到期量和常用容量，提供小份恢复学习，并保留「继续上次」入口。AI 可以解释为何先从某一点开始；算法选择实际目标。没有新作答时不写遗忘、不清空历史、不自动从头学，也不强迫补完全部积压。

### 计划的首版执行规则

首页只读取计划和真实候选数量，不因打开应用、刷新或查看设置创建学习组。用户明确开始或继续后，服务端才确定本次预算；默认推荐继续未完成组，也允许明确选择保留任务。新组按当前预算选词，优先分配到期复习，剩余容量用于新词。已有组的目标、队列、首答、材料和整组总拼写门槛不因减量而改写。

长期与今日计划提供每周学习日、每日新词目标和每组数量。今日调整提供正常学习、少学、只复习和休息，按日期及时区生效。所有学习时长设置、统计和限时暂停已移除。

旧词数容量仅用于兼容既有任务。新版按每日完成目标和组量组织，用户可以随时手动暂停，再从原词卡阶段继续。旧分钟设置在数据库迁移中删除，达到每日目标、手动暂停和到期复习门槛继续按学习事实处理。

新建的「只复习」组不安排新词和写作，完成实际复习即可结束；历史组的内容范围保持原样，今日只复习时走到尚未做的新词或写作会暂停，调整计划后再继续。旧组停在新词或写作时，若有真实到期复习，可以另开只复习组，旧组保留在任务列表中。允许多个暂停组，但同一时刻只有一个进行中的组；新组排除其他未完成组中尚在复习或尚未结算的新词目标，避免重复安排。同一天明确开始的不同组使用独立身份，不覆盖当天原记录。

今日休息不删除旧组，也不变更到期时间。缺席判断只读取真实用户学习事件，打开应用、修改计划、后台备课和 AI 反馈都不算用户已学习。首版按本地日期差达到 3 天建议恢复，建议本次最多 3 个词，且不超过当前容量；这是可调整的产品策略，不是记忆阈值。暂停组后来完成时，候选选择采用最新实际记录时间的排期，而不按组的创建顺序覆盖。

## 词库计划与例句等级

学习计划的「词书」将每套导入词表显示为一个封面，顶部统一选择词汇等级和乱序／顺序。牛津 3000 可选全部或 A1、A2、B1、B2，未分级词书使用全部范围。乱序在所选范围内使用稳定排列，选择全部时可跨等级混排；顺序采用来源 rank。自定义词表同样支持稳定乱序或输入顺序。选择通过回执保存，明确点「开始学习」后才建立新组。活动词书提供真实 `activeWords`，新组结合学习预算和 FSRS 到期情况选词。原始 rank 和来源信息保留供追溯，已有组保留原目标和答案。词库读写通过 `/api/mini/vocabulary/catalog`、`import`、`activate`，使用独立版本、固定请求身份和同一鉴权边界。

牛津 3000 使用官方 CEFR PDF 记录词形、词性、等级与原行，中文释义和音标来自固定 ECDICT commit 及校验清单，并保留导入时的同形异义规范记录。当前解析得到 3,313 条等级/词性记录，首次出现的来源 headword 为 3,003 个，按大小写折叠为 2,981 个拼写。按首次等级的记录分别为 A1 902、A2 801、B1 699、B2 601。个人词库已通过 HTTP 导入为修订号 1，激活完整 `oxford3000` A1→B2。实际 `activeWords` 与完整词库目标数均为 3,003，按拼写口径为 2,981，等级词库为 902/801/699/601。来源文件位于个人服务数据的 `vocabulary/sources/`，生成词条留在个人数据范围。

词表的 CEFR 等级用于说明目标词，用户英语水平用于控制例句的长度、语法与配词。顾问和备课上下文同时提供活动词库、目标等级和 `sentenceLevel`，后者优先采用明确保存的 `english_level`，缺省使用 A1。因此首轮即可按 A1 难度指引造句，结合已学词与已有重点组织表达。词条工具可查询导入词库的释义、音标、词性、等级与来源。

## 一个运行时、按任务提供工具和 Skill

mini 四类任务统一从 Node 调用本机 Codex App Server，默认明确选择 `gpt-6.1-sol` 与 `xhigh`，不安装本地文字模型。界面保留可见的模型和强度选择，任务保存实际请求配置；执行前核对运行时模型列表与支持强度，不可用时报告错误并保留选择，不静默更换。旧网页 D0 仍使用其既有配置；本轮四类任务已分别验证所选模型的真实工具提交，失败后的复测范围见验收记录。

共用一个 AI 运行时与任务管理入口，按 `prepare`、`writing`、`feedback`、`advisor` 创建持久任务，按需装载 `mini-lesson`、`mini-feedback`、`mini-advisor` 三类短 Skill。备课和写作复用课程 Skill，任务仍各自绑定目标与权限；首版不要求两个永远在线的 Agent 或持续推理的后台循环。用户思考、复习或没有新事件时不调用模型。客户端只在活跃任务期间查询已保存任务状态。

当前 mini MCP 有 `learning_get_context`、`learning_get_history`、`learning_get_word`、`learning_commit` 四个基础工具；接入语音服务时，仅 `advisor` 额外获得 `learning_get_audio` 和 `learning_generate_audio`，可查询已有录音/任务或按明确请求生成、单条重生成，不能播放或伪造播放回执。音频任务已入队不等于录音已就绪。其余教学任务仍只用四个基础工具。上下文返回本任务允许的动作，提交由服务端再校验对象、版本、原答与权限。网页学习原型仍待接入，不提供任意 SQL、文件改写或无边界权限。

以下列出当前工具的用途与边界；完整教学测量与阶段小结仍须按后续验收逐项实现。

| 能力             | 可提供的用途                                           | 必须保留的边界                                                      |
| ---------------- | ------------------------------------------------------ | ------------------------------------------------------------------- |
| 上下文与历史查询 | 计划、学习频率、实际词量、首答、帮助、轮次、重点与材料 | 按需分页并可追溯原事件；摘要不替代事实                              |
| 教学材料         | 批量例句、练习、定性反馈、小结与重点建议               | 绑定目标、题目／材料版本和预算；不改用户原答                        |
| 计划调整         | 长期、今日或本次参数，恢复建议                         | 作用域明确、保留版本、由算法重新选择未开始任务                      |
| 音频（顾问）     | 查询、请求生成、单项重生成                             | 命中已有资产即复用，失败保留旧音频                                  |
| 稳定偏好         | 用户明确偏好、常见需求和可编辑记忆                     | 可查看、改正和删除；不能伪造能力诊断                                |
| 学习事实         | 读取事实，提交教学或帮助事件                           | 用户作答和自评只能来自真实用户操作；AI 不能代写、伪造通过或改写历史 |

写接口校验请求身份、预期版本、对象范围、当前阶段及调用者能力；返回数据库已提交的回执。AI 自然语言中的「已调整」不作为成功依据。取消、重试、多个入口同时操作也不能让迟到结果覆盖新状态。

### 有限而持久的记忆

当前持久信息包括真实学习记录、用户明确的稳定偏好，以及服务端聊天。每轮只带当前目标、简短计划与最近 12 条该会话消息，需要时再分页查学习历史，不把整份历史重复发送。原生快照仅返回最近 200 条聊天和 50 个任务；更老的聊天仍保存在数据库，但本步没有完整聊天分页界面。没有向量数据库、自动长期摘要或周期性反思任务。

稳定偏好最多保存 20 条，同名可修改，也可删除；AI 写入必须引用这次已保存且被授权的用户消息，不能凭推测写能力诊断。用户可在聊天中查询、纠正或要求忘记。旧本地英语水平不会自动被伪造成用户消息；菜单改级现在先保存真实用户请求，再由顾问工具写入偏好，界面采用服务端实际回执。

清除某会话会取消其任务、删除相关聊天内容及可重试输入；已保存的学习、材料、计划与重点仍保留。偏好删除是独立操作，清聊天不会自动撤销偏好或学习事实；偏好原值不保存在 mini 的操作事件正文中。后续若引入摘要，删除时还须处理其引用，不能用摘要恢复已要求删除的信息。

新后台评价不能仅依赖这些可清除聊天或最近消息窗口。评分证据范围、原答与最小必要输入独立保存，任务归属学习事件，切词或清聊天不误删已确认的评价任务；明确删除正文时也处理对应输入副本并保留删除标记，不悄悄还原。详细规则见 [评分追溯](learning-flow-rules.md#6-评分追溯保留什么如何使用)。

## 本地音频生成与复用

第四步已实现英语单词独立发音和英语例句朗读，真实离线 MLX、音频 HTTP 和复习判断预览中的单词/例句播放已通过，其他阶段完整界面与主观听感仍待验收。共用已安装的 Qwen3-TTS 1.7B CustomVoice MLX 8-bit，模型环境仍集中在 `~/sdks/lingoweave-tts/`；正常学习生成的 WAV 则进入对应应用服务的 `data/audio/`，不与 SDK 手工样音混放。声音克隆、中文讲解声线与强制音素控制不在本步范围。

复习判断卡进入时自动读词，任一自评展开后按单词、例句顺序再次播放。新词初见和后续主动展开完整词卡时同样顺序播放，语境轮与词义轮收起时保持对应提示范围。点击单词或句子可手动重播。单词播放完成后停顿 0.5 秒再开始例句，每段分别保存授权与实际开始回执。例句的读取与授权可在停顿内准备，实际播放以单词完成后的半秒为最早时点。换词、静音、隐藏、暂停和手动播放会取消剩余自动队列。新词首次进入须先通过四步准备，迟到音频继续校验原访问身份。

首页和计划预览不启动 TTS。明确开始/继续或连接已有进行中组后，客户端按当前词优先顺序预取组内单词与已有例句，复习期间即准备后续新词。观察按目标区分等待、请求、排队、生成、就绪和失败，实际缓存或完成任务对应资产才计为就绪，预取不写学习事实。失败只补缺项重试，切组隔离迟到观察，重连复用现有资产和任务。开发阶段预览可实际生成、播放与重生成当前词或例句，复用开发服务的持久音频缓存和当前版本。试听跳过真实学习授权、帮助、开始回执及恢复 outbox。正常流程待确认开始回执在预览中暂停保留，回正常流程按原身份和时间继续确认。预览/正常模式及词卡切换使旧访问结果失效，迟到资产可保留为缓存。

`ensure` 优先复用当前有效资产，同目标活跃任务合并，不因每次播放重新随机音色。首次生成或明确单条重生成时，从 `ryan`、`aiden`、`serena` 随机选取，所选音色随资产保存；重生成也可明确选择声线，随机不保证轮流。单词与例句拥有独立身份；规范化英文文本、词形、释义、音标、模型 revision、引擎版本、生成规则和参数共同决定缓存身份，避免同形异音仅因拼写相同就复用。读词正文由程序直接读取单词拼写，例句朗读使用已保存的英文句子。单词生成采用 `word-2` 规则，风格参数为空，temperature 为 0.3，codec 上限按短词时长窗口计算，至少 64。首个候选使用单词正文，未通过检查后仅补结束句点再尝试一次。撞上 codec 上限、异常时长或无效声音均拒绝发布。短词时长窗口为 `max(2.5, 拼写长度 × 0.12 + 1)` 秒，用于拦截异常续读。已有可用短词和例句继续复用各自真实参数对应的缓存。发音与词义准确性通过试听和单条修正核对。

`mini-audio.sqlite` 保存资产及任务，WAV 使用小写 UUID 文件名，数据库只记录相对文件名、文本/规范化文本、音色、模型/引擎/参数、时间、时长、采样率、字节数和 SHA-256。每个缓存身份仅有一个当前指针。新音频先写临时文件，校验完整、非静音的 24kHz 单声道 PCM16 WAV 后重命名，再事务切换当前指针；生成失败或中断时旧音频保留。旧版本元数据和文件当前也保留，应用内旧版本清理尚未实现。文件与数据库使用可恢复协调，不宣称跨介质原子事务。

正常流程播放分成两份事实，播放器开始前先请求授权，服务端核对当前词卡、读音身份和阶段，并保存保守的 `potentialHelp`；`authorized` 不表示实际听到。`AVAudioPlayer.play` 成功后再保存带实际开始时间的 `started` 回执，原生将未确认回执持久化并按原身份重试。即使从浏览词表请求音频，只要内容含当前拼写答案，也会关联当前目标的帮助。较晚播放不反写已保存首答，支持下练习不产生独立 Good 或较长首间隔。音频生成、播放授权、实际播放都不伪造用户作答。

本地 worker 按需启动、串行处理；首次启动校验 manifest 中全部文件 SHA-256，启动后的配置身份固定。跨开发/正式实例用 SDK 缓存目录的 `fcntl` 锁避免同时加载两份模型；空闲约 30 秒退出。MLX allocator 缓存上限为 256MB，每次生成后清理闲置缓存，这不是整个模型内存上限。运行只使用本地权重并禁用下载，超时/退出释放自有进程。已完成文件在模型不可用时仍可复用；新的生成保持失败/待重试，不假冒现成录音。

`generate.sh` 继续作为独立手工试听入口，拒绝覆盖旧样音；应用队列、缓存和播放事实由 Node 服务管理，不靠该脚本维护另一份状态。

## 存储、迁移与删除

可替换运行环境集中在 `~/sdks/`：共享 Python 放 `python/`，工具放 `tools/uv/`，语音运行环境与模型放 `lingoweave-tts/`。保留系统 Python 与 shell 配置，自己创建的目录和文件统一小写，第三方包内部文件名保持原样。

学习事实、材料、音频资产与可重建缓存分开管理。学习数据库和资产根目录应可配置并有清晰清单；数据库引用稳定 ID 与相对路径，不将某台机器的绝对音频路径当作资产身份；当前音频已按此结构保存。开发预览的示例学习、聊天和文字 AI 内容只保留在内存，语音与开发正常流程共用持久音频资产。开发和正式应用各自使用独立服务目录。

后续导出包应包含格式版本、数据库或一致性快照、词义与材料关系、原始事件、计划与重点版本、需要保留的音频、文件清单及校验值。大模型、Python 运行环境和可重建缓存可不随包导出；恢复时先校验完整性与支持版本，再原子启用。虚拟环境不可直接迁移，需要按锁文件重建，模型文件可按固定清单复用。

删除范围必须清楚：单条音频、音频旧版本、可重建缓存、某段聊天／偏好、全部学习数据、语音运行环境分别处理。删除模型或运行环境不应顺带删除未来正式学习资产；当前手动样音仍在 `~/sdks/lingoweave-tts/audio/`，删除该环境前须保留需要的样音。项目文件、学习事实和下载目录不维护多份可写副本。

完整导出、恢复与清理按用户本轮选择暂缓。当前 `mini.sqlite` 保存学习事实，`mini-ai.sqlite` 保存文字任务与聊天，`mini-audio.sqlite` 保存音频资产、任务、版本指针与播放回执，`mini-vocabulary.sqlite` 保存词库及活动选择，`audio/` 保存相对路径 WAV。`materials/catalog.json` 与 `materials/sources/` 保存本地原文目录、文件与校验值，可重建句子索引。文字工具和音频授权各自先持久固定命令，再由学习库提交，重启按学习业务回执对账；各库分别事务提交，使用固定回执恢复协调。旧学习与聊天原文件、迁移请求和回执继续保留。手工备份先停止对应服务并保留整个数据目录，包括四个 mini 业务数据库、音频和词库来源，不只复制运行中的主库。

阶段预览的学习、聊天、草稿和示例 AI 回复仅在内存，文字教学模型使用示例回复。预览语音则复用开发服务的真实生成、缓存、鉴权文件和播放器，写入开发音频库及文件，显式重生成可更新同目标的当前资产。开发正常流程和正式版还各有独立服务目录。实际位置以 [mini 本地服务说明](macos-mini.md#本轮本地服务接入)为准；应用包现携带 Node 与服务，Codex/TTS 环境和学习数据仍分别管理，应用内导出恢复本轮暂缓。

## 体验和质量优先的执行方式

当前为单用户个人学习工具，学习效果和小窗体验优先；不为压低费用而降低已选旗舰模型或勉强接受不舒服的声音。缓存、预取和批量处理用于减少等待、方便反复学习。高能力文字模型用于有必要的批量备课、阶段后反馈与用户主动聊天。算法、自评、拼写比较、快照查询、计划日期作用域和资产命中由程序完成，不为确定性工作调用模型。

复用已有例句、重点、写作素材和音频；一次准备一个有明确需求的词组，避免每卡一次请求。根据真实新事件合并需要分析的记录，不重复分析已确认的结果。对话使用精简上下文与按需历史查询，Skill 只包含本任务相关规则；当前不生成自动持久摘要。

任务配置、状态、公开文本、失败原因、时间与业务回执已持久化；重试先查既有结果，最多同时运行两个 mini AI 任务，同一范围的准备任务可复用。原四类教学任务在服务重启时不自动调用模型，未完成任务按实际结果标为完成或中断，用户可主动重试；新版已确认翻译的后台评价另有持久队列，启动后自动续处理，失败需显式重试；已发布的部分材料保留并只补缺项。单次模型轮次最长等待 6 分钟，超时仍以实际保存结果为准，不保证每次按时返回。完整用量和费用统计尚未接入，不编造估价。本地 TTS 已实现按需启动、连续复用与约 30 秒空闲退出，实际内存和等待时间以本轮验收为准。

## 实施顺序与验收

第一步已统一 mini 学习数据与业务接口，第二步已实现三层计划与缺席恢复；第三步已实现 AI 教学并分别验证四类真实文字任务。第四步已实现音频资产、播放与重生成，通过真实离线 MLX、顾问六工具、四条 Swift/HTTP 流程和工程检查。复习预览的真实单词和例句播放已核对，其他阶段界面与主观听感仍待验收。本轮继续推进单卡练习、独立检验、词库计划和独立应用包，导出清理暂缓。完整阶段安排仍见 [Demo 实施计划](demo-plan.md#开发顺序与每步交付)。

### 第一步：服务端成为 mini 学习的唯一事实源

1. 在共享契约中定义 mini 快照、业务命令、保存回执、版本冲突及旧账本导入结构。快照包含版本、导入状态与每日／复习记录，界面从已保存阶段展示相应动作；Swift 只映射协议，不复制调度真相。
2. 将现有 mini 每日学习状态转换移至 Node 业务层，保留可核对的选词、复习间隔算法和规则版本。服务端管理真实时间、任务身份、材料、作答、暂停恢复与排期；本步停止新的 AI 写作反馈驱动排期，保留历史翻译排期事实。迁移不同时接入 FSRS 或重写总拼写算法。
3. 导入旧账本前保存原文件备份，校验格式版本、身份、时间、数量与必要关联。已有数据按实际来源导入；缺失帮助、轮次或事件不补造。重复导入同一份数据返回既有回执，冲突或未知版本明确拒绝，不能静默覆盖。
4. mini 改为读取服务端快照并提交业务动作。迁移成功后停止向旧账本写学习事实；UI 可保留未提交草稿与待确认请求，但不能退回第二套可写账本。服务未连接时显示真实状态，不声称已保存。
5. 每个写请求带稳定请求身份、预期版本和首次操作时间，内容、状态、事件与回执事务提交。响应丢失后可查询或按原请求重试；同身份不同内容拒绝，旧版本操作先刷新，不能重复作答或重复推进。
6. 保留原账本、原始备份、固定导入请求与回执用于核对和恢复。失败回滚，不留部分导入；成功后只有服务端可写。需要回退到旧应用时先停服务并明确恢复版本，不能让两端继续分别积累历史后自动拼接。

本步迁移范围为旧每日账本与旧手动复习 current/history，聊天 `StudyChat.json` 与偏好仍沿用原存储。开发版和正式版各有独立服务、端口与数据目录。真实开发版旧账本已迁入并核对，正式版在首次打开新版应用时迁入，原文件均保留；网页学习原型尚未加入这套业务模块。

本步已通过 `pnpm check` 和 `pnpm test:mini`。后者用隔离数据验证真实 Swift → HTTP → SQLite 的导入、复习、错误首答／订正／全组再轮、翻译原答、重试、反馈不改排期、版本冲突和关闭重开持久一致；真实开发版完成旧账本无损导入，随后真实 AI 生成五条例句并经服务命令保存。个人账本没有写入测试答案或代替用户过关。具体数量、服务启停及 Node 版本限制见 [mini 验收记录](macos-mini.md#2026-年-11-月-13-日验收)。

### 第二步：三层计划与缺席恢复

长期、今日、本次计划与会话保存到同一 SQLite 事实源，共享命令沿用版本校验与幂等回执。`plan-preview` 只读返回本地日期、有效预算、真实候选、缺席建议及可继续的保留组，Swift 不另算权威计划。容量优先级为本次、今日、长期；今日休息与只复习仍约束可进入的阶段。

隔离验证覆盖今日跨日失效、跨午夜重试、继续不重置预算、单词后续练习不重复扣量、新词上限、无候选不建组、真实活动判断及恢复建议。第二条真实 Swift → HTTP → SQLite 闭环从带错误首答和订正草稿的旧组出发，保留旧组、另开到期只复习组，再按稳定身份恢复旧组；两组原答和草稿保持一致，两个测试数据库均通过关闭重开核对。旧手动复习仍沿用自己的流程，本次每日组计划预算不扩展宣称到该入口。

### 第三步：AI 工具、重点与教学材料

Node 统一管理例句备课、写作准备、定性反馈和学习顾问任务。真实学习状态保存在 `mini.sqlite`，任务和聊天保存在 `mini-ai.sqlite`，Swift 仅负责显示、提交真实用户操作、保存待确认请求和草稿；原来 `StudyChat.json` 通过原字节备份及固定导入身份迁入，未知旧消息时间保留为空，不补造历史。

新增领域验证覆盖 AI 不能替用户答题、真实导入历史分页、版本与幂等、重点新增和活跃上限、偏好来源与删除、独立写作材料的原子/部分发布、反馈不改原答或排期、聊天帮助的时序关联。受控运行时已跑通原生四任务全链；真实 `gpt-6.1-sol` / `xhigh` 分段验证已保存顾问的今日计划与明确偏好、备课例句、独立写作和定性反馈回执。期间发生前置 RPC 拒绝与写作等待超时，后续另行复测成功，不称为单次无中断四任务全链。完整原生点击与布局仍待验收，具体命令、回执及两库重开证据见 [mini 验收记录](macos-mini.md#第三步实现与待补验收)；手工真实调用脚本用法见 [开发指南](development.md#数据与中断)。

### 第四步：语音资产、播放与单条重生成

本轮后续调整前，第四步通过 39 项原生测试，其中新增 9 项覆盖自动播放、迟到丢弃、隐藏/暂停、当时的预览隔离和回执恢复。Node 统一管理语音队列、文件校验、资产当前指针和播放回执，Swift 维护访问生命周期、播放器与未确认开始回执。后端独立边界验证包括缓存离线复用、同形异音/旧阶段拒绝、浏览答案仍记录帮助、授权不冒充实际播放、事后不污染首答、文件鉴权与损坏校验。真实 MLX 单词/例句、缓存、重生成、关闭重开，以及第四条 Swift → HTTP 音频流程已通过，生产播放器样音、工程检查与真实顾问音频工具已验证。本轮后续调整通过 41 项原生测试，其中音频 11 项，复习预览已核对真实生成及单词/例句播放。个人学习快照保持原基线，音频库保存两个已完成资产且播放回执为零，主观听感和其他阶段界面仍待验收，见 [第四步验收](macos-mini.md#2026-年-11-月-16-日第四步实现与待补验收)。

本轮继续新增复习期间后台备课和新词四步准备页，已通过 47 项原生测试、四条真实 HTTP 流程、六库重开及最新构建。360 × 300 点实际准备页核对真实数量从 6/12 开始，MLX 完成后自动进入词卡。自动读词有控制器测试覆盖，现场听感与发音准确性另行核对。记录见 [准备流程验收](macos-mini.md#复习期间备课与新词准备流程)。
