# macOS 悬浮词卡

LingoWeave Mini 是独立的 macOS 应用，源码位于 `apps/macos`。窗口默认约 360 × 300 点，打开后在首页显示本机学习进度和四个月的活动热力图，后台恢复未完成的任务或准备当天的任务。热力图按日历月展示本月和前三个月，按实际操作日期统计记词、自评、拼写和翻译作答。本月还没到的日期用淡色显示。点「开始学习」或「继续学习」进入任务，学习中可用房子按钮返回首页，当前题和已保存的输入会保留。

词卡、AI 聊天、阶段菜单和图钉与系统窗口按钮同在标题栏。窗口加宽后可在中间看到应用名。点菜单栏的语织图标可找回被挡住或已隐藏的小窗，右键图标可打开隐藏和退出菜单。界面采用 macOS 的系统浅色和深色外观，滚动区域使用细款浮动滚动条。

在仓库根目录运行以下命令构建并打开应用。需要 macOS 14 或更新版本和 Swift 6 工具链，本机可用 Xcode Command Line Tools。

```sh
./apps/macos/build-app.sh --open
```

应用生成在 `apps/macos/dist/LingoWeave Mini.app`，之后可以直接双击打开。需要换版本时，先从菜单栏退出正在运行的实例，再打开新构建的应用。

从右上角阶段菜单进入「浏览词表」，可以逐词查看释义，也可用左右方向键和空格键操作。浏览时，阶段菜单里的「编辑词表」可粘贴自己的单词，每行一个，用 Tab 分隔单词和释义。仅含英文的词可浏览，但中文提示拼写需要先补释义，才会纳入每日任务。词表和当前位置保存在本机偏好中。内置词表沿用项目的 30 个基础词。来源与许可见 [词条来源](lexicon-sources.md)。

每日任务先做已到期的复习词，再做新词，最后做句子翻译。复习和新词各最多 5 个，空阶段自动跳过。当天的词组固定，改词表不替换进行中的任务。未完成时重新打开会续做原组，跨日也一样。

1. 复习：先看英文判断记忆。选档后显示释义和该词已有的例句，点「记错了」按遗忘处理，点「下一个」采用所选档位。遗忘和模糊合计满 3 次后退出判断循环，清晰的词直接退出。所有复习词随后进入中文提示的逐词拼写。
2. 新词：每次显示一个词、释义和一句英中例句，确认看完后进入下一个。全组看完才逐词拼写。AI 在打开小窗时后台准备例句；等待或重试不影响已能开始的复习。右上角可设置英语水平，默认 A2；备课同时参考近期真实作答。例句目前为 AI 原创，后续再接有核验出处的原文。
3. 句子：题目在作答前固定，每次只显示一道，包含两个翻译方向。先把原答写入本地，再请求 AI 批改。批改后显示参考译法、反馈、改进建议和实用表达；断线或退出后可继续批改同一份答案。参考译法是示例，批改允许意思相同的表达。

两组拼写都按回车确认。首答错时保留原答案并显示正解，直接键入可替换选中的旧答案。订正正确后前进。复习的错词排到队尾，直到某次首答正确；新词需要一轮全组首答正确，有错则下一轮重拼全组。右上角可暂停。

小窗的首版排期采用本地日历：新词首轮拼写一次通过的词两天后复习，其余隔天；复习首次判断清晰且首答拼对时延长间隔，否则隔天复习。间隔档位为 1、3、7、14、30 天。翻译部分正确或错误可把复习日期提前，正确不单独延长。排期保存时间、来源和规则版本，当前属于练习排期，不等同于项目 [测量规则](measurement-rules.md) 的独立掌握证据，也未接入 FSRS。

判断和拼写上方各有一排进度标记，每个词的位置固定。判断时，实心圆是当前词，绿边是通过，红边是需要再次出现，灰边表示未轮到或达到判断次数上限。拼写时，当前词是三角形，实心圆是首答正确并已通过，空心圆是尚未通过。切换时轮廓在圆形和三角形之间快速过渡。旁白会读出具体状态。

每日记录保存在 `~/Library/Application Support/com.lingoweave.mini/DailyStudy/ledger.json`，包含词组、阶段时间、暂停恢复、自评初选和最终档位、拼写首答与订正、例句、翻译原答、反馈和实用表达，可用于后续报表。旧手动复习数据保留在 `~/Library/Application Support/com.lingoweave.mini/Review/`，未退出的旧组仍可接着做。旧组不作为新版排期的历史证据。

AI 备课、批改和自由聊天共用已登录的本机 Codex CLI。聊天页右上角可选模型和推理强度，选择会保存到本机。候选项来自 Codex 模型目录，实际可用性由请求结果确认。聊天保存到本机；请求携带当前词、该词最近 12 条消息和有限条数的近期学习记录，重启后仍能延续。独立浏览词表和已有材料的复习可离线使用。

构建时会记录终端中 Codex 的路径，迁移 CLI 后可以重新构建。可用 `codex login status` 检查本机登录。小窗通过独立子进程运行聊天，显式传入界面选择的模型与推理强度。子进程会使用 macOS 当前的 HTTP 和 HTTPS 代理，环境中已有的代理设置优先。聊天失败时会恢复问题草稿，可直接重试。

窗口由 AppKit 的 `NSPanel` 管理，界面由 SwiftUI 渲染，Swift Package Manager 构建应用。三类 AI 请求各用固定提示词，通过隔离的 `codex exec` 子进程运行；备课和批改使用 [OpenAI 官方文档中的结构化输出方式](https://developers.openai.com/cookbook/examples/codex/build_iterative_repair_loops_with_codex)，应用另做校验。模型不能执行命令、替用户提交答案或直接修改记录和排期。网页、Node 服务和网页数据库与小窗各自独立。
