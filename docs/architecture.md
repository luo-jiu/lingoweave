# LingoWeave 架构

LingoWeave · 语织是独立的个人英语读写学习应用。当前交付基础工程：网页、Node.js 服务、共享接口契约及开发检查。学习流程、数据保存和 Agent 接入按 [Demo 计划](demo-plan.md)逐步实现。

## 当前工程

采用一个 Git 仓库和 pnpm workspace，前后端分别构建和运行。这样可以统一管理接口、依赖版本和变更，同时保留清楚的运行边界。

```text
apps/web              React + TypeScript + Vite
apps/server           Node.js + TypeScript + Fastify
packages/contracts    Zod 运行时结构与 TypeScript 类型
docs                  产品、架构、开发与验收计划
```

`apps/web` 是浏览器程序，只通过 `/api` 请求服务。`apps/server` 是 Node.js 程序，负责 HTTP 和未来的学习业务。`packages/contracts` 为两端提供相同的数据结构，不能依赖浏览器或 Fastify。跨包引用通过 `@lingoweave/contracts` 入口，不直接导入另一个包的内部文件。

开发时有两个进程：Vite 在 `127.0.0.1:5173` 提供页面，把 `/api` 代理到 `127.0.0.1:4310`。生产构建后由 Fastify 同时提供网页静态文件和 API，只需启动一个 Node.js 服务。未知 API 返回 JSON 错误；网页路径回退与 API 错误分开处理。

当前 API 为 `GET /api/health`。前端用共享 schema 校验响应，并显示连接、失败和重试状态。此接口验证前后端联通，不代表数据库或 Codex 已接入。

## 计划中的职责

| 部分          | 职责                                           | 当前状态                       |
| ------------- | ---------------------------------------------- | ------------------------------ |
| 网页          | 学习卡片、总拼写、句子练习、聊天和历史         | 基础页面已建立，学习界面待实现 |
| 学习服务      | 阶段转换、答案保存、评价采用、预算与事实查询   | 待实现                         |
| 调度器        | 基于真实历史选择新学和复习目标                 | 待实现；计划采用 FSRS-6        |
| SQLite 与文件 | 保存事件、来源、材料、会话、任务及导出包       | 待实现                         |
| Codex 接入    | 管理 App Server 进程、角色线程、事件与失败恢复 | 待实现                         |
| 学习 MCP      | 将受控工具调用转换为同一套学习业务命令         | 待实现                         |
| 教学 Skill    | 描述备课、教学、证据与工具用法                 | 待实现                         |

先在服务端实现稳定的业务边界，再按实际复用需求拆出 `domain`、`scheduler`、`agent-bridge` 等包。不会为了规划目录提前建立没有实现的空模块。

算法决定学什么、复习什么和本次负荷；AI 查询历史，决定如何解释和出题；平台保存事实并执行规则。页面、Agent 和调度器都不能各自维护另一份学习成绩。

## 计划中的 Agent 通信

```text
网页 ──HTTP──> Node.js ──stdio──> Codex App Server
网页 <──SSE── Node.js <──事件─── 出题 / 陪伴线程
                  ↑                    │
                  └──业务服务──学习 MCP 工具
```

用户只在网页开始学习、答题和聊天。Node.js 在后台管理本地 Codex 运行时，在同一平台学习会话下关联出题与陪伴两个角色的线程。角色可以采用同一个模型；具体模型和协议版本在实际联调时确定。

公开聊天通过运行时消息事件转发，不要求 Agent 为每句话调用专用回复工具。题目、提示、评价与小结则通过结构化业务工具提交，校验与保存成功后才改变学习状态。简短进度对应真实工作，不展示后台参考答案或内部日志。

用户思考时不轮询模型。新消息先保存，再为相应角色排队；同一角色线程串行执行，停止操作中断当前轮。重试先查已保存回执，迟到结果必须验证题目与计划版本。

Skill 负责指导 Agent 使用能力，不替代解析器、评分规则、数据库或界面实现。未来增加词根 PDF、句式学习或其他材料时，需要同时补齐平台能力、来源记录、教学说明和验收。

## 保存与恢复边界

以下是后续实现必须满足的约束，当前基础工程尚无学习数据库。

- 学习对象按词目和义项保持稳定身份；不同词表、材料和计划关联同一历史。
- 原始作答、显示过的帮助、实际时间及评分版本都保留。自评、练习完成和独立回忆成功分别记录。
- 确定性评分与对应调度变更可靠提交后再确认成功。AI 评价先保存待评分答案，结果回来后再结算。
- 同一请求重发不产生新尝试；真实的新一次练习生成新证据。两个角色不能重复结算同一次作答。
- 平台拥有学习会话；Codex 线程只是可替换的教学上下文。模型断线不删除已保存成绩。
- 网页快照附带一致的事件序号，SSE 从该序号续接；最终消息更新原草稿，重连不重复追加。
- 未开始、未作答或缺席不记失败。暂停不清空教学包、当前拼写轮次或已提交答案。
- 导出和恢复需覆盖数据库、来源、规则版本和关联材料，不能只有一份聊天摘要。

## 运行范围

首版面向单用户、单机，服务默认只监听回环地址。公开代码仓库不等于公共托管服务。多用户、远程登录、跨设备同步与离线同步不在本轮工程范围。

前端不得携带服务端凭据、私有参考答案或完整内部日志。实际学习数据、导入材料和生成产物不随代码提交。SQLite、音频服务与 Codex 接入完成前，界面和文档均应明确其待实现状态。
