# LingoWeave 架构

LingoWeave · 语织是独立的个人英语读写学习应用。当前实现 D0：平台提供一个固定词组，Node.js 调用 Codex 备课，学习工具把材料保存到 SQLite，网页展示材料和任务进度。完整学习流程按 [Demo 计划](demo-plan.md)推进，验证结果见 [D0 验收](d0-acceptance.md)。

## 工程与职责

采用一个 Git 仓库和 pnpm workspace。`apps/web` 使用 React / Vite，`apps/server` 使用 Fastify / Node.js，`packages/contracts` 提供 Zod schema 与类型。包之间通过公开入口引用。

| 模块                     | 当前职责                                                            |
| ------------------------ | ------------------------------------------------------------------- |
| `apps/web`               | 首页、备课工作区、运行时状态、材料与来源、停止和重试                |
| `learning-store.ts`      | SQLite 迁移、词库、固定组、备课任务、材料、公开消息、事件和幂等回执 |
| `preparation-service.ts` | 任务调度、运行时生命周期、当前任务凭据、取消与关闭                  |
| `learning-routes.ts`     | HTTP 命令、工作区快照、SSE、受限的内部工具入口                      |
| `codex/`                 | App Server JSONL 协议、状态与模型、工具范围检查、公开消息映射       |
| `learning-mcp.ts`        | stdio MCP，将两个工具转换为同一备课业务调用                         |
| `skills/lesson-author`   | 当前词组的初学者例句要求、来源与保存回执规则                        |
| `measurement.ts`         | 第一版独立回忆证据分类器；尚不参与备课或产生学习成绩                |

服务端已有清晰模块边界；后续按复用需求再拆出 `domain`、`scheduler` 等 workspace 包。

## 一次真实备课

```text
网页 ──HTTP 命令──> Fastify / PreparationService ──stdio──> Codex App Server
网页 <──SSE 通知── SQLite 事件 / 工作区快照       <──公开消息── Agent
                              ↑                              │
                              └──受限内部接口──学习 MCP <──stdio
```

用户点击准备后，服务端先创建任务与请求回执，再启动后台工作。Agent 先调用 `learning_get_context` 读取这一任务的五词组，然后调用 `learning_publish_materials` 提交完整例句集合。工具校验词义身份、目标集合、句长、目标词使用和当前任务状态；五条材料、完成状态、事件与回执在同一事务提交。普通聊天文本不能改变这些结果。

开发页面由 Vite 在 `127.0.0.1:5173` 提供，`/api` 代理到本地 Fastify；代理保留原 Host，以便服务端验证网页写入来源。生产构建后 Fastify 同时提供页面和 API。服务端默认只监听回环地址。

SSE 传输持久化事件的序号、类型和任务身份。页面收到通知后读取最新快照，公开回复随快照逐步更新。前端合并刷新并丢弃过期响应，避免旧请求覆盖新状态；重连从事件游标补接。SSE 是平台状态通知，不是对模型轮询。

## Codex 与工具范围

适配器以 `codex app-server --listen stdio://` 启动独立进程，完成初始化后查询登录与模型列表。每次备课显式停用继承的其他 MCP 与插件、关闭命令执行等无关能力，并在开始模型轮次前验证只有本应用的两个学习工具可用。其设置只作用于这次子进程和线程，不修改用户全局配置。

MCP 子进程获得一个当前任务的临时凭据，只能调用回环地址的内部学习入口。取消或进程结束后凭据失效。公开消息只来自 Agent 公开文本及平台的已知进度；内部推理、原始运行日志、账户身份和凭据不发到网页。

本轮按 **Codex CLI 0.153.4** 的实际生成协议验证。模型来自本机运行时的当前可用列表；验证时默认返回 `gpt-6.1-sol`，代码没有把它作为永久型号。App Server 本身仍属于实验性接口，升级 CLI 后需要重新验证协议和工具行为。协议依据：[App Server](https://learn.chatgpt.com/docs/app-server)、[MCP](https://learn.chatgpt.com/docs/extend/mcp)。

D0 备课采用临时线程（`ephemeral: true`）。平台保存实际线程 ID、模型、公开消息和材料以便追查；重试从平台事实构建新的上下文，不恢复已退出的 Codex 线程。持续陪伴会话和两个教学角色的线程续接留到 D3。

## 保存与恢复

数据库默认位于 `data/lingoweave.sqlite`，使用 WAL 和事务。当前 `PRAGMA user_version = 1`，初始化时自动迁移并写入 30 个稳定义项；来源与改写范围见[词条来源](lexicon-sources.md)。打开高于当前支持版本的数据库会明确失败。

同一数据目录通过进程锁限定单服务实例。任务与消息在重启后从数据库恢复；此前仍在准备的任务标为中断，已提交材料保持可用。材料提交后，即使最终自然语言小结未完成，也不会回滚已完成任务。

请求身份与操作内容绑定：相同提交返回原回执，身份被用于不同内容则拒绝。取消后的迟到写入无效；取消也不会撤销此前已经提交的材料。五词材料批次失败时整批回滚，不产生半组完成。

## 当前边界与后续

D0 只有一个固定起步组：apple、book、water、read、write。30 词种子是来源资料，当前页面还不能选择后续组；固定排序不代表频率排序、测评或动态调度。

自评、总拼写、成绩、FSRS、用户答题与陪伴聊天尚未实现。[测量规则](measurement-rules.md)目前是有回归样例的纯分类器，后续过关判断与调度采用同一证据结果。材料已准备不等于单词已学会。

后续继续沿用平台拥有事实、原始答案与帮助记录不可覆盖、重复请求不重复结算的约束。数据导出恢复、多用户、远程服务、跨设备同步、音频和 PDF 导入均不在当前 D0 交付范围。
