# LingoWeave 架构

2026 年 11 月 17 日的 [新流程与后台评价](learning-flow-rules.md)已落实为 mini 的 `sliding-window-v2` 状态机、持久后台评价与独立版本的双能力调度。本文区分这些实现、保留兼容的旧 mini 流程与网页 D0；测试和原生验收状态以 [macOS mini 记录](macos-mini.md)为准。

LingoWeave · 语织是独立的个人英语读写学习应用。当前实现 D0：平台提供一个固定词组，Node.js 调用 Codex 备课，学习工具把材料保存到 SQLite，网页展示材料和任务进度。完整学习流程按 [Demo 计划](demo-plan.md)推进，验证结果见 [D0 验收](d0-acceptance.md)。

上述 D0 实现指网页备课模块；mini 已完成学习事实、业务命令、三层计划与缺席恢复的服务端统一，并新增 Node 管理的 AI 任务、聊天、历史工具、词义重点、有限偏好、独立写作材料与定性反馈。旧学习及聊天可分别备份导入，Swift 不再直接运行 Codex。四类任务已分别完成真实模型与工具保存验证，原生完整点击与布局仍待验收，见 [macOS 悬浮词卡](macos-mini.md)。第四步已接入本地单词/例句语音、版本化资产、播放与单条重生成，真实离线 MLX 和隔离 Swift/HTTP 音频流程已通过。网页学习原型仍未接入 mini 模块；本轮已补显式独立检验/FSRS、单卡练习、词库与应用资源，导出清理暂缓，具体验收按 [mini 学习、AI 与语音方案](mini-ai-learning-plan.md)推进。

## 一次真实备课

```text
网页 ──HTTP 命令──> Fastify / PreparationService ──stdio──> Codex App Server
网页 <──SSE 通知── SQLite 事件 / 工作区快照       <──公开消息── Agent
                              ↑                              │
                              └──受限内部接口──学习 MCP <──stdio
```

用户点击准备后，服务端先创建任务与请求回执，再启动后台工作。Agent 先调用 `learning_get_context` 读取这一任务的五词组，然后调用 `learning_publish_materials` 提交完整例句集合。工具校验词义身份、目标集合、句长、目标词使用和当前任务状态；五条材料、完成状态、事件与回执在同一事务提交。普通聊天文本不能改变这些结果。

开发页面由 Vite 在 `127.0.0.1:5186` 提供，`/api` 代理到本地 Fastify；代理保留原 Host，以便服务端验证网页写入来源。生产构建后 Fastify 同时提供页面和 API。服务端默认只监听回环地址。

SSE 传输持久化事件的序号、类型和任务身份。页面收到通知后读取最新快照，公开回复随快照逐步更新。前端合并刷新并丢弃过期响应，避免旧请求覆盖新状态；重连从事件游标补接。SSE 是平台状态通知，不是对模型轮询。

## Codex 与工具范围

适配器以 `codex app-server --listen stdio://` 启动独立进程，完成初始化后查询登录与模型列表。每次任务显式停用继承的其他 MCP 与插件、关闭命令执行等无关能力，并在开始模型轮次前核验实际工具集合：网页 D0 为两个备课工具，mini 教学任务为四个基础工具，接入语音服务的顾问任务额外有音频查询与请求生成两个工具。其设置只作用于这次子进程和线程，不修改用户全局配置。

MCP 子进程获得一个当前任务的临时凭据，只能调用回环地址的内部学习入口。取消或进程结束后凭据失效。公开消息只来自 Agent 公开文本及平台的已知进度；内部推理、原始运行日志、账户身份和凭据不发到网页。

网页 D0 的既有生成协议按 **Codex CLI 0.153.4** 验证。2026 年 11 月 13 日 mini 使用内置运行时 `0.167.0-alpha.4.1`，当时模型目录确认提供 `gpt-6.1-sol` / `xhigh`，四类任务也已分别通过真实调用与工具回执验证。期间出现前置 RPC 拒绝和写作等待超时，后续分段复测成功；不将这些结果描述为单次无中断四任务全链，具体证据见 [mini 验收记录](macos-mini.md#第三步实现与待补验收)。2026 年 11 月 16 日实际运行时为 `0.169.0`，已用 `gpt-6.1-sol` / `xhigh` 一次通过顾问六工具实际清单校验和音频查询/单条重生成验证。App Server 本身仍属于实验性接口，升级后需要重新验证协议和工具行为。协议依据：[App Server](https://learn.chatgpt.com/docs/app-server)、[MCP](https://learn.chatgpt.com/docs/extend/mcp)。

D0 与 mini 任务采用临时线程（`ephemeral: true`）。平台保存实际线程 ID、模型、公开消息和材料以便追查；重试从平台事实及有限近期聊天构建新上下文，不依赖已退出线程继续存活。mini 默认明确请求 `gpt-6.1-sol` 与 `xhigh`，执行前核对支持能力，不可用时失败并保留选择，不静默降级；真实分段验证使用了该配置。三类 mini Skill 按课程、反馈与顾问任务装载，不要求两个常驻教学 Agent。

## 保存与恢复

数据库默认位于 `data/lingoweave.sqlite`，使用 WAL 和事务。当前 `PRAGMA user_version = 1`，初始化时自动迁移并写入 30 个稳定义项；来源与改写范围见[词条来源](lexicon-sources.md)。打开高于当前支持版本的数据库会明确失败。

同一数据目录通过进程锁限定单服务实例。任务与消息在重启后从数据库恢复；此前仍在准备的任务标为中断，已提交材料保持可用。材料提交后，即使最终自然语言小结未完成，也不会回滚已完成任务。

请求身份与操作内容绑定：相同提交返回原回执，身份被用于不同内容则拒绝。取消后的迟到写入无效；取消也不会撤销此前已经提交的材料。五词材料批次失败时整批回滚，不产生半组完成。

mini 学习事实使用独立的 `mini.sqlite`，由对应开发／正式服务实例管理；数据库 `user_version = 13`，保留旧版本的迁移路径，快照协议仍为 `schemaVersion: 1`。Swift 通过 `/api/mini/snapshot`、`/api/mini/plan-preview`、`/api/mini/import` 和 `/api/mini/commands` 读取快照、预览计划、迁移旧账本与提交业务命令；共享契约位于 `packages/contracts/src/mini.ts`。学习状态只由服务端转换，写入校验请求身份、预期版本及实际操作时间，并原子保存状态、事件与回执；重复请求返回当前快照，不重复应用动作。客户端保留待确认命令和草稿用于恢复，不维护第二套可写学习账本。

`plan-preview` 虽使用 POST 传入词库与 IANA 时区，仍是只读查询。首页和计划窗口不会开始学习或调用 AI；用户明确开始或继续后，`begin` 才选择学习组并创建本次预算，客户端才准备所需材料。长期与今日计划的 `dailyNewGoal`、`groupSize` 分别决定新词最终完成目标和每组数量；今日覆盖绑定当地日期和时区。学习时长字段和按时间暂停已移除。新版不受旧 `wordLimit`/`newWordLimit` 的固定组截断，旧流程继续读取原容量字段。正在输入或展开核对的卡片不会因改计划而被丢弃；结束本次只关闭预算并暂停原组。

`planning.activeDayId` 是当前学习组的唯一选择指针，组 ID 是稳定身份，不能只按日期或数组最后一项推断。多个未完成组可以同时保留为暂停，最多一个未完成组处于继续状态。今日只复习且原组停在新词或写作时，可以另开实际到期复习组，并以 `writingRequired: false` 跳过写作；恢复原组仍保留其材料、答案与轮次。连续至少 3 个当地日无实际学习时，保留原缺席提示和旧流程的恢复容量建议。同日可接续原窗口。跨日先清完实际到期复习，未完成词按当天词书重新进入新词候选；当前恢复入口不会自动改写新词日目标或组量。计划不补记缺席失败、不伪造学习，也不改写真实到期时间。旧手动复习仍独立保存与操作，尚未纳入每日计划预算。

旧学习文件先按原字节备份，导入请求与回执固定保存；未知结构、关联不一致或冲突导入明确失败。历史翻译排期保持原样，旧 `qualitative_feedback` 仍只保存教学结果；新版确认后的后台评价另走 `mini-assessment` 与 `mini-flow-scheduling-v1`，由程序采用调度结果。真实开发版迁移与隔离 Swift → HTTP → SQLite 闭环见 [mini 验收记录](macos-mini.md#2026-年-11-月-13-日验收)。完整导出恢复及网页共用 mini 学习模块仍待开发。

### mini AI 任务、教学与两库协调

`mini-ai.sqlite` 与 `mini.sqlite` 位于同一服务数据目录，各自使用本地 SQLite 事务。前者保存四类任务（`prepare`、`writing`、`feedback`、`advisor`）、聊天、配置、公开进度、状态和固定工具请求；后者保存真实学习、计划、材料、重点、偏好、曝光及业务回执。它们通过固定请求身份和业务回执对账，属于可恢复协调，不是一个跨库原子事务。

工具先在任务库保留完整待确认命令，再由 MiniStore 校验版本与对象范围并事务提交。若学习提交后、任务回执保存前进程退出，启动时依据学习库的请求回执补认；部分材料保留，任务只有满足真实目标完整性才算完成。重试先检查已有结果，不重复发布，不用自然语言声称的保存状态代替业务回执。取消令临时凭据失效，已提交事实仍有效；服务重启只恢复状态和对账，不自动重启模型。

新建正常组采用 `writingMode: prepared`：学习例句和写作材料分别保存，后者有独立 UUID、方向、重点引用与创建时间。无写作材料时保持待准备；不能为了继续而直接复用看词句。已提交作答绑定原始题目，后续发布与重试不覆盖。旧组无该模式时仍兼容历史学习句任务。新反馈包含优点、改进、重点与参考译法，禁止 `outcome` 等级；旧反馈只为历史可读保留，该教学反馈接口不修改排期。新版用于排期的评价由独立后台任务读取冻结证据并提交结构化结果，不复用这项反馈命令。

重点以规范化拼写和释义生成稳定词义身份，最多两个活跃重点/词义、每个 `MiniDay` 最多新增一个；新版一个 `MiniDay` 可承载多个组，当前新增预算尚未细分到子组；暂缓和归档保留历史引用，不重置新增预算。稳定偏好最多 20 条，AI 写入须引用本次已保存且授权的用户消息，可改正和删除。聊天在回复当前词卡前保存保守帮助条件，后来的帮助不反写原首答；带帮助首答不能用于较长间隔。旧 mini 轮次算法保持原样；新版记忆和近期拼写是支持练习，不能直接转换成独立 Good。

学习历史按真实原始事实投影，包含旧记录、新版窗口初选与确认、复习重学及所有归档组的拼写。归档前后同一拼写事件引用不变，词条查询另给出 `flowMemory` 双能力调度快照。支持有限分页和稳定引用；游标绑定版本与筛选条件，记录变化后须重新查询。提示词仅带当前目标、精简计划、有限偏好及最近 12 条会话消息，更多事实按需查；当前没有向量检索、自动持久摘要或独立语义测验。

原生通过 `/api/mini/ai/` 的运行时、快照、任务、开始、停止、重试、导入与清除接口管理任务，活跃任务期间查询平台保存的状态。开发阶段预览的学习与聊天全部仅在内存，文字 AI 使用示例。语音另行复用开发服务的生成、缓存、文件与原生播放器。完整原生交互与真实模型验收记录见 [mini 说明](macos-mini.md#第三步实现与待补验收)。

### mini 本地语音资产与播放

`mini-audio.sqlite` 与学习库、AI 库位于同一服务数据目录，保存语音资产、生成任务、当前版本、播放授权和实际开始回执。WAV 位于 `data/audio/`，以小写 UUID 相对文件名引用。缓存身份包含规范化英文、词义、音标、固定模型 revision、引擎版本、生成规则和参数。首次生成或明确重生成时选取 `ryan`、`aiden`、`serena`，缓存命中沿用原音色。同目标活跃任务共享，生成和查询不写入学习事实。

新版本先写临时文件，通过完整 RIFF/WAVE、非静音、24kHz 单声道 PCM16、长度和 SHA-256 校验后重命名，再事务切换当前指针。重生成失败继续提供旧资产，旧版本文件和元数据目前均保留。重启将未完成任务标为中断，后续明确请求再继续；模型不可用时仍可使用已验证缓存。文件和数据库分别提交，通过持久身份恢复协调，旧版本清理及完整导出恢复留待后续。

播放开始前由服务端核对当前阶段、访问与读音身份，并保守保存 `potentialHelp`。授权回执只表明可开始播放。原生播放器开始成功后，才按实际开始时间提交 `started`，未确认请求以原身份和时间持久重试。浏览词表的音频若包含当前答案也关联帮助，较晚播放保留原首答的支持条件。AI 仅能查询、生成和重生成，播放授权及开始事件来自原生真实操作。

每日组明确开始或继续后，客户端在复习期间后台准备缺少的新词例句与音频。新版准备池按剩余日目标加窗口容量预留，`learningWords` 只包含已真正入窗的词；准备、查询和音频生成都不记作学习。音频按目标独立入队，服务端 worker 串行生成，客户端区分等待、请求、排队、生成、就绪和失败。就绪依据有效缓存或完成任务对应的精确资产，材料、音频进度都来自现有服务事实。当前要进入的新词材料未齐时，界面展示单词选择、例句、单词音频、例句音频四步及真实数量。准备观察与组身份绑定，切组取消旧观察，重连通过 `ensure` 复用资产与任务。复习保持可操作，首页、计划、浏览词表和旧手动复习不会启动新的文字备课任务。

Swift 控制当前词卡访问、自动一次播放、手动例句播放、静音和停止，并丢弃旧卡或隐藏/暂停后迟到的结果。拼写和翻译仅接受主动请求的英文提示。首页和计划查询不触发 TTS，正常学习可优先预取当前组的单词和已有例句。阶段预览可实际生成、播放和单条重生成，资产与开发正常流程共享缓存和当前版本。预览试听绕过学习授权、帮助、开始回执和恢复 outbox，学习、聊天和文字 AI 示例仅在内存。正常流程未确认的开始回执在预览中暂停保留，回正常流程继续按原身份和时间确认。切换预览/正常模式或词卡均使旧播放结果失效。

`MINI_TTS_ROOT` 默认指向 `~/sdks/lingoweave-tts/`，只复用已安装的 Qwen3-TTS 1.7B CustomVoice MLX 8-bit。worker 懒加载、串行生成，每次启动核验 manifest SHA-256，通过 `fcntl` 锁协调开发/正式实例，约 30 秒空闲退出。256MB 限额作用于 MLX allocator 缓存，模型总内存另计。运行禁用下载，模型和依赖仍集中在 SDK 目录。真实离线生成、缓存、重生成、文件鉴权和关闭重开证据见 [第四步验收](macos-mini.md#2026-年-11-月-16-日第四步实现与待补验收)。

### 单卡练习、独立检验与 FSRS

`mini-scheduler.ts` 共用 `measurement.ts` 分类真实作答，`mini.sqlite` 保存单卡练习、展示曝光、检验原答、评分前后状态、参数和真实 due。单卡默写只在自评或记住后主动开启，撤销标记收起，原输入和揭晓保留。显式独立检验采用中文提示，关闭自动音频，只有符合无帮助与时间条件的原始首答调用 `ts-fsrs@5.4.2` 的 Good/Again。已介绍未检验对象采用待检验时间，旧排期仍可追溯，新计划以调度快照选取到期词。

### 词库与应用资源

`mini-vocabulary-store.ts` 使用独立的 `mini-vocabulary.sqlite` 和修订号，公开 catalog、import、activate 接口。条目关联来源、词形、释义、音标、词性、等级及原行，活动词库按所选词书和等级范围返回去重后的真实目标，可用稳定乱序或来源顺序；完整范围乱序覆盖各等级，原 rank 保留供追溯。学习组创建继续由 MiniStore 管理，切换词库后新组采用新的候选范围，保留组继续关联原目标。AI 上下文同时提供词表等级和用户句子难度，词条工具按需查询来源记录。

`build-app.sh` 把 Node 22.22.0、编译后 server/contracts、生产依赖、Skill 和语音 worker 放入应用资源，通过包内相对路径启动。`package-mini-service.mjs` 固定运行时版本并核对归档校验值，构建缓存位于 `~/sdks/node/`。全局快捷键通过 macOS Carbon 注册，默认 Control+Option+Space，可切换 Control+Option+L 或关闭，冲突状态显示在菜单。Codex 登录、本地 TTS 环境和个人词库数据继续按各自外部位置使用。最终应用包与个人词库启用结果见 [本轮验收](macos-mini.md#单卡默写独立检验词库与应用包验收)。

## 新窗口与后台评价

`MiniDay.flow` 保存版本 `sliding-window-v2`，并区分候选准备池、实际入窗词、活动窗口、当前组待拼写词、冻结写作目标、已归档组和最终完成事件。窗口默认 5 个词；每词独立经历完整词卡、例句回忆、词义回忆三个阶段，回访穿插不同目标，并照顾尚未初见的窗口成员。答错退回阶段 0，仍占窗口；三阶段确认通过才腾位补词，组满则暂停记忆窗口，先做这一组拼写与翻译。组结束保留尾词进度，最后一组按剩余日目标缩小。旧 `three-rounds-v1` 记录不被改写成新流程。

阶段 1/2 的 `window_choose` 保存初选与展开时间，`window_correct` 保存“记错了”；只有 `window_advance` 才确认结果、推进阶段和队列。阶段 0 可直接确认。服务端保留访问 UUID、草稿、初选、改判、曝光和确认时间，拒绝旧访问上的迟到命令。缩小计划在安全边界生效；重启及普通恢复保留尚未确认的卡片。展开词卡后读词，结束半秒后读例句；隐藏回忆阶段不自动播放答案。

复习由实际 due 选择，并与新词日目标分开。所有到期复习清完后才能开新词；显式新建组也不能绕过门槛。判断三轮均未清晰的词进入同样的三阶段重学窗口，只能补入该复习池中的词。总拼写只重试上一轮首答错误的词，订正不增加轮数，第三轮首答错误可跳过；正确和订正后的绿色状态均等待下一词确认。复习无需翻译，新词须确认翻译才计入当地日的完成数。

### 冻结输入与任务恢复

`submit_translation` 保存原答，并在同一学习库事务内写入 `mini_assessment_drafts`：固定题目、提交时间、该词此前的窗口/拼写事实、答前帮助、历史投影与证据资格。点击下一题时，`advance_translation` 原子保存确认时间、词级完成事件与 `assessmentSources` outbox；在已固定草稿上追加截至确认时的相关词卡讨论，消息标明答前或答后，当前最多取最近 24 条。旧作答若没有提交时草稿，兼容回填会明确取消独立证据资格，不反推它曾经无帮助。

`MiniAssessmentStore` 使用 `mini-ai.sqlite` 中的独立表，按作答 UUID 创建一题一个任务。服务自动领取持久 outbox，当前串行运行；运行中重启会回到可领取状态，失败在首页重试。已确认作答、完成计数和下一题均不等待评价。普通四类聊天/备课任务重启后不自动调用模型的既有规则不变；这条持久评价队列是单独的后台恢复路径。

后台任务仅能读取本题冻结证据和提交评价，不能查用后来发生的实时事实来替换输入，也不能代答、完成学习或指定 due。模型分别判断目标词义、拼写、用法，引用真实证据 ID；服务验证 source ID、输入哈希和引用范围。完整输入与结构化结果保存下来，另记录实际模型、推理档位、线程、规则版本、Skill/提示哈希与起止时间。聊天清除不会级联删除这些学习评价证据；评价输入副本的清理尚未实现。

工具先持久保存评价候选，再由 `MiniStore.applyAssessment` 在学习库事务中保存采用结果、调度变更与幂等回执，最后任务库补认。进程在任一侧提交后退出，恢复时用同一身份对账，已有有效候选优先重放而不重复调用模型。这是两个 SQLite 数据库间的可恢复协调，不是跨库原子事务。当前支持单题失败重试及迟到结果采用，尚无已采用评价的修订命令或合并多题批量评价。

### 新版调度与追溯

`mini-flow-scheduling-v1` 使用锁定的 `ts-fsrs@5.4.2` / FSRS-6、目标保持率 0.90、默认权重和空的短期步骤，为同一词义分别保存 meaning 与 spelling 卡。没有合格证据时能力卡可为 null；词级 due 仍可由完成或困难事实决定。复习清晰/模糊/遗忘是自报来源，采用 Good/Hard/Again 时保留来源；初选前的语义帮助会阻止清晰或模糊被算作成功，初选后的自动朗读不会反写初选。音频曝光另记 `audioKind`：普通复习初见已展示英文，单独读词不作为 meaning 帮助，但仍是 spelling 曝光；句子音频及旧版未标类型的音频保守视作帮助。拼写与模型评价另按原答、帮助及实际间隔决定资格。旧 `measurement.ts` 的 `d0-v1` 分类不变。

新词确认完成先安排下一自然日复习；同日独立检验或正面 AI 评价不能移走这次首次复习。支持下出错不伪造独立 FSRS 失败，但会产生保守的初学间隔上限：一般记忆/拼写困难为 2 天，累计三次记忆错误或三轮拼写首答错误为 1 天；明确的目标词翻译拼写错误为 1 天，其他明确目标错误为 2 天。上限约束首次真实复习之后的间隔，第二次实际复习解除初学上限，再按新证据安排。它是本产品策略，不是论文证明的最优间隔。

事件同时保存原发生时间、入库时间、证据来源、采用分级、规则与当时负荷；调度变更保存前后卡及参数。迟到评价按原确认时间插回该词的事件序列重放，保留随后真实复习的顺序。词级 due 综合本次测到的能力及尚未到期的另一能力；已服务但本次未测的过期能力不会单独制造无限次日复习。默认关闭库内随机 fuzz，在至少 3 天的间隔附近按已保存负荷选择日期，半径为约间隔的 5%、至少 1 天且最多 3 天；次日约束和初学上限继续优先。错峰不会清掉既有积压，也不能保证长期新增量大于学习能力时没有积压。

## 当前边界与后续

D0 只有一个固定起步组：apple、book、water、read、write。30 词种子是来源资料，当前页面还不能选择后续组；固定排序不代表频率排序、测评或动态调度。

网页 D0 尚未接入真实自评、总拼写、用户答题与陪伴聊天；独立学习原型仍只保存页面内存状态。mini 已接入单卡支持练习和显式独立拼写检验，合格首答采用 FSRS-6，完整 D1～D3 的其余规则继续按分项验收。[测量规则](measurement-rules.md)的分类器已用于显式独立拼写检验，调度采用同一分类结果，其余教学过关规则继续分项接入。材料已准备不等于单词已学会。

后续继续沿用平台拥有事实、原始答案与帮助记录不可覆盖、重复请求不重复结算的约束。当前优先服务个人单机小窗体验。本轮新增 FSRS、原生单卡默写、词库计划、快捷键与包内 Node，工程、隔离窗口流程、个人乱序首组与真实备课已验证，快捷键按键动作仍待人工确认。声音克隆和 PDF 导入仍在后续范围，数据导出恢复与清理本轮暂缓。浅色新词预览及声线菜单已有实际点击检查，复习判断预览的真实生成及单词/例句播放已通过，360 × 300 点新词准备页的真实计数与自动跳转也已核对。250 点高失败页滚动、其他阶段完整布局和主观听感仍待验收。此前工程验证使用 Node 24，本轮应用包固定 Node 22.22.0，搬移后已通过拒绝读取仓库的包内服务鉴权验证。

新版排期在数据库打开和导入边界执行完整重放校验。已有状态经过完整验证后，日常受信任命令仅追加事件：保存前仍校验全局身份与关联，只重放本次新增事件涉及的词；无排期事件不重复计算 FSRS。后台评价同样只核对对应词。此优化不暴露给客户端，也不改变事件、到期时间或采用回执；依据见 [规模与曲线检查](research/mini-scheduling-scenarios-2026-11-17.md)。
