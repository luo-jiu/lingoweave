# 学习流程、复习排期与后台评价规则

确认及实施日期：2026 年 11 月 17 日。状态：**新版流程已接入服务端与 mini，隔离验收见 Demo 计划和 macOS 说明**。新建任务使用 `sliding-window-v2`，已作答的旧组继续原版本，不重判过去答案，也不替用户修改个人目标。

本文是 mini 新流程的统一依据，取代旧方案中的整组三轮记忆、每词五轮拼写、按首次接触数计算新词目标，以及写作评价完全不参与后续排期的目标约定。产品分工见 [产品约定](product.md)，实施顺序仍统一维护在 [Demo 计划](demo-plan.md)。

旧任务兼容 `three-rounds-v1` 整组记忆和五轮拼写；显式独立拼写检验及旧版定性写作反馈继续保留。历史验收记录见 [mini 方案](mini-ai-learning-plan.md)和 [macOS 说明](macos-mini.md)，当前实现、真实模型、界面及连续使用的验收分别记录。

## 1. 计数、计划与完成条件

| 名称           | 含义                                                                  | 本次约定                                          |
| -------------- | --------------------------------------------------------------------- | ------------------------------------------------- |
| 每日新词目标   | 当地当天最终完成的新词数量                                            | 用户可设置；50 只是流程示例，不替用户修改现有设置 |
| 每组数量       | 通过三阶段记忆后，集中参加拼写和翻译的词数                            | 用户可设置；20 为示例，日目标 50 对应 20、20、10  |
| 记忆窗口       | 同时进行三阶段记忆、尚未进入待拼写集合的词                            | 默认最多 5 个，与每组数量分开                     |
| 再现间隔       | 同一词两次记忆操作之间处理的其他不同词数                              | 默认至少 3 个，交错次序由程序决定                 |
| 复习任务       | 已到期或逾期、尚未完成本次复习的词                                    | 独立于新词目标，不挤作“完成新词”                  |
| 最终完成的新词 | 三阶段记忆完成，拼写阶段已结束，所分配的翻译题已提交并确认下一题/结束 | 不等待 AI 后台评价；拼写第三轮失败不阻止翻译      |
| 进行中的词     | 已接触但未满足最终完成条件                                            | 保存进度，不计新词完成数                          |

每日先完成全部到期与积压复习，再开始或恢复新词学习。复习可以分组、分次完成；用户可以随时手动暂停，但不能因为只完成了预算内一小批就解锁新词。到期集合按服务端采用的当地学习日期计算，明确记录 IANA 时区；跨日先保存当前操作，再检查当日复习门槛，不打断尚未保存的输入。

今日少学、休息、只复习继续有效。调整新词目标不抹除已经完成的数量，不重置进行中的词；降低到低于当前完成量时停止补入新词。学习安排只使用每日新词目标和每组数量，所有分钟设置、学习时长统计和按时间自动暂停均已移除。休息或未达到新词目标不制造新词欠账，尚未处理的到期复习仍保留真实到期日期。

新词最终完成后的下一个当地自然日必须进入首次复习。这是产品规则，不是 FSRS 自带的“必定一天”保证；记录完成时间、学习日期与时区。词卡看过、三阶段完成或拼写结束都不能提前触发这条完成规则。

## 2. 每个词独立推进，窗口交错出现

### 三个记忆阶段

本节用于新词学习，以及普通复习判断三轮仍未清晰后进入的重学。普通复习最初的「清晰／模糊／忘记」判断保留自己的流程，不把所有复习词一开始都送进三阶段。

| 阶段        | 初始显示                             | 本次操作与核对                                   | 确认后的阶段                           |
| ----------- | ------------------------------------ | ------------------------------------------------ | -------------------------------------- |
| 0：初见记忆 | 完整单词、释义、例句与译文，可用草稿 | 点「记住了」先亮一颗绿点，停留 0.3 秒后自动前进  | 进入阶段 1；仍不会则留在 0             |
| 1：语境回忆 | 英文例句，隐藏中文释义与译文         | 先选是否想起，展开核对；记错后清零并延迟自动前进 | 确认记对进入 2；想不起或记错退回 0     |
| 2：词义回忆 | 英文单词，隐藏释义与例句             | 先选是否想起，展开核对；记错后清零并延迟自动前进 | 确认记对进入待拼写；想不起或记错退回 0 |

### 阶段 1、2 必须先核对，再前进

收起时用「想起来了／想不起来」表达初选，避免单独的「展开」让程序猜测用户此前是否想起。两个入口都展开完整词卡并自动读词，单词播放完成后停半秒，再读例句。初选、展开、改判与确认是同一次词卡访问中的不同动作，不是新轮次。

- 点「想起来了」会保存初选，立即多亮一颗绿点，并展开完整词卡供核对。点「下一个」时确认阶段推进、出窗、补词或组满。
- 核对发现记错时点「记错了」，保存修正并立即清零三个点，停留 0.3 秒后自动确认退回阶段 0 并换词。
- 核对无误：点「下一个」，正式完成当前阶段并换词。阶段 2 到此才腾位；未满组时下一张补新词，恰好满组时转拼写。
- 原本想不起来时，立即清零三个点并展开学习，待确认结果为退回 0，点「下一个」继续。原初选保留为未想起。「记错了」只在初选想起且尚未改判时作为有效操作。

这一核对界面移除通用「撤销」按钮和常驻「已按学习规则保存」提示。改判由「记错了」完成，正常保存安静进行；真实保存失败或尚未确认成功仍须简短提示并保留当前位置，不能假装已前进。输入框的正常文本编辑不受影响。

每个词用三个点反馈最新阶段结果，进入时显示已经通过的阶段，当前初选想起立即多亮一颗，想不起或核对后记错立即清零。恢复核对页面时，由保存的初选和改判恢复相同绿点。历史已经发生的观看、初选和改判仍保留。自动展开和答后朗读不把原初选改写成答前受帮助；用户实际的改判另存，展示与朗读计入后续曝光。阶段 0 的“记住了”只是学习推进，不伪装成无提示回忆成功。

初见完整词卡提供“记住了”，用户可以停留到记住再点击。点击后先保存选择并亮一颗绿点，停留 0.3 秒后自动确认进入下一词。自动切词期间重复点击只处理一次，离开词卡会取消待执行的切词，恢复同一词时按已保存选择继续。句子中的目标词使用强调色与加粗高亮，备课可返回 `targetForms` 标明句中实际出现的词形，服务端校验原文中的完整匹配。旧材料按原词和可识别的英语词形匹配显示。

单卡草稿和默写可主动使用，保存原始输入、比对与揭晓，属于支持练习，不替代全组拼写，也不额外点亮阶段。改判时收起依赖原“想起”状态的单卡练习，已输入内容继续保留。已经前进后，不通过通用撤销倒退并覆盖后续答案。

初选与展开事实发生时就保存，绿点随初选和改判即时更新。阶段、队列和组计数在手动或自动确认下一词的同一有效操作中更新。双击或重发只确认一次。核对中暂停或退出，恢复同一词的展开状态、初选/改判、绿点和草稿。初见已点记住或已改判记错时，恢复后继续 0.3 秒自动确认；其余核对状态继续等待用户操作。

用户可以在音频尚未结束时前进，不设置强制听完门槛；离开时取消剩余播放，旧卡音频不得跟到下一词。同一访问的普通刷新不重复自动播放。

### 调度顺序

窗口容量 5 与再现间隔 3 是两个参数。严格五词环形轮流展示会隔四词再现，因此采用有循环基底的交错调度，不要求所有词先完成同一阶段。

1. 组已满时，先进入该组拼写；不再展示下一张新词卡。
2. 一个词完成阶段 2 且本组未满时，释放一个位置，下一张优先展示补入的新词。有候选但缺材料时准备该新词，不另塞第六个词。
3. 一个词回答不会或核对后记错时，先停留完整词卡，待确认「下一个」后退到阶段 0 并转向窗口内其他词；不释放位置、不立即连续考同一个词。
4. 达到间隔的词可提前复现；存在尚未初见的窗口词时，不能连续插入复现词而一直饿死未展示词。初始轮转允许一次提前复现，然后服务仍未展示的词。
5. 其他候选按实际等待顺序和保存的循环位置选择，同等条件采用稳定顺序。刷新、暂停、重启不重抽整条队列。

间隔按实际完成的词卡访问计算，同一词的初选、展开、改判和下一词合计为一次，相同词重复刷新、播放音频、订正或聊天不增加“不同词”数量。正常窗口有足够词时至少隔 3 个不同词；词库不足或窗口实际不足 4 个时，处理完可用的其他词后允许再现，记录实际间隔，不为凑数伪造曝光或无期限空等。

例如以下是允许的一段顺序，数字表示**这次展示的阶段**：

```text
a0 → b0 → c0 → d0 → a1 → e0 → b1 → c1 → …
                       ↓ 不会
                  a 退到 0；下一张仍可为 e0

a2 选想起 → 展开核对 → 下一个确认记对 → a 进入待拼写 → f0 补位
```

这里每个箭头都包含当前词核对后确认前进，e 早已属于五词窗口；a 答错没有释放位置。五个词都始终不会，就继续在这五个词内学习，不跳过记忆门槛引入窗口外的新词。用户始终可以暂停。

### 组边界和跨日

本组累计足够数量的三阶段通过词后，冻结本组目标集合，进入这些词的拼写和翻译。窗口剩余词保留阶段、队列位置、间隔证据和草稿，不加入本组拼写。

在窗口为 5 的情况下，组满时最多留下 4 个进行中的词。完成本组翻译后回到原窗口，接着下一组；日目标完成后也保留尾部。例如可以最终完成 50 个，另有最多 4 个进行中。次日先处理到期复习，再恢复这些词。它们在最终完成前不算新词成绩，也不因跨日成为“已完成后的次日复习”。

阶段与组数量应能从原始事件重建。改计划、换词书或换顺序只影响未进入学习的候选，不能重新标记当前词或替换已经提交答案的组。

## 3. 复习判断与必要的重学

复习先展示英文单词，隐藏释义和译文。用户选择「清晰」「模糊」「忘记」后揭晓完整卡片；发现自己判断有误可以修正，初选、揭晓和最终选择均保存。

- 清晰：退出本次判断队列，等待拼写。
- 模糊或忘记：揭晓后进入下一词；下一轮重新隐藏答案，继续考察这个词。
- 每轮第一次遇到该词算这一轮初见。看释义、订正或重复点卡不增加轮数。
- 三轮仍未清晰：进入与新词相同的三阶段记忆窗口，完成后再参加拼写。重学没有“三次后假定会了”的出口，仍可暂停。

重学词始终属于复习，不能计为新词或新词目标。正常复习不增加翻译环节，也不需要 AI 才能完成；优先复用历史例句。少量旧词若从未保存例句，重学阶段 1 使用明确标注的“词义提示回忆（暂无例句）”，不能冒充语境独立成功，也不为普通复习强制调用模型。用户主动聊天另行保存帮助。

只有判断三轮仍未清晰的词进入上述阶段 0/1/2；阶段 1/2 也必须初选后展开朗读，允许记错改判，再确认下一词。复习重学窗口腾位时只能补入本批尚待重学的复习词，不能从词库补新词绕过复习门槛；没有剩余重学词时窗口自然缩小。其余普通判断通过的词继续等待本批拼写。

一批复习词结束判断和必要的重学后，集中拼写。本批每词拼写成功或第三轮失败退出后，才算完成本次复习。三轮失败表示本次流程可以结束，不表示记忆良好；原始失败用于后续较近的安排。

## 4. 新词与复习共用的三轮拼写

题目使用中文提示，输入前不自动播放答案音频。首轮覆盖本组；**下一轮只包含紧邻上一轮首答错误的词**。

| 当轮结果               | 本轮后续                                                       | 是否进入下一轮                     |
| ---------------------- | -------------------------------------------------------------- | ---------------------------------- |
| 首答正确               | 完整单词变绿并停留，再按回车/下一词继续                        | 否，即使更早的轮次错过             |
| 第 1 或第 2 轮首答错误 | 保存原答，显示正确拼写与错误位置；订正正确后绿色停留，确认继续 | 是                                 |
| 第 3 轮首答错误        | 保存失败及结束原因，显示正解与错误位置，允许继续下一词         | 否，本次拼写结束；不要求再订正成功 |

订正不增加失败轮数，也不能把当轮首答改成正确。空白输入不自动记失败；明确选择不会可以作为本轮失败。绿色确认与“下一词”需有稳定请求身份，重试不重复提交或跳两词。

错答反馈显示正确拼写，开始重新输入后立即收起参考答案，订正输入区按正常拼写呈现。再次提交错误时显示该次反馈，提交正确时绿色停留并允许下一词。反馈区域始终预留位置。

首答和订正每次提交出结果后，正确与错误均自动朗读一次单词。普通刷新和进入下一道未答题沿用去重约束。答后音频保留实际曝光记录，原始首答及其答前帮助条件继续按发生顺序保存。

例如第一轮错 a/b/c，第二轮 a 首答正确、b/c 首答错误，第三轮只能考 b/c。即使 a 的第一轮错过，也不再回来。第三轮结束后，新词继续翻译，复习结束该词本次流程。旧五轮上限、固定优先级 5 和十分钟补测不能直接套入新规则。

## 5. 翻译继续做，评价在后台完成

教学反馈与调度评价分开：反馈帮助用户理解和讨论；调度评价分析目标词表现，形成供程序采用的结构化结果。参考译法是建议，没有强制订正通过的步骤。AI 可查询记忆、拼写和历史复习，讨论不会抹掉原答。

### 下一词的含义

“下一词/下一题”表示**立即进入下一道待翻译题**，不是等这一题评分完再显示反馈页。

1. 提交时先保存原题、原始答案、实际时间和此前帮助；用户可以查看已有反馈，或停留与 AI 讨论，也可以直接前进。
2. 点击下一题或最后一题的结束动作时，服务端原子保存该题完成确认、适用的词级完成事件、评分证据范围与待处理记录，再返回成功回执。
3. 回执后展示下一题；最后一题可结束本组并继续下一组/返回首页。AI 未启动、还在打分、失败或暂时离线都不阻塞这一步。
4. 如果连本地答案保存也失败，保留输入并说明保存失败，不能假装已经完成。这与后台评分等待不同。

默认每题确认后进入持久队列。运行时可把尚未执行的任务合成小批请求，也可以处理整组，但每题仍有独立身份、结果和重试状态。不能把“用户必须先做完整组”当成开始或保存评分的条件；最后一题、半组后退出、暂停、应用重启都要能继续处理已确认的题。

提交后尚未点击下一题而关闭应用时，恢复该题原答案与停留位置，不自动伪造完成动作。已经确认下一题的待评分工作不因关闭聊天、切词或暂停学习而取消。

### 只在首页显示处理状态

首页汇总显示例如“学习评价处理中 · 3 题”或“2 题待重试”，可展开查看关联词、失败原因和重试入口。全部处理后收起处理中提示，评价仍可在词的历史中查询。

翻译页面不显示后台评分的转圈、进度条、待评分角标、失败提示或等待页；评分任务也不触发弹窗或抢走当前输入。用户主动提问的聊天回复、已有教学反馈与原答案仍正常显示。首页自身只读取状态，后台任务由已保存的完成事件触发，不靠打开首页才开始执行。

新词完成数按用户的完成事件统计，不按 AI 返回时间统计。跨日收到的评价仍属于原来的学习，不在评分当天重复加词。首次次日复习在完成时就建立，即使 AI 尚未返回也不能漏排；后台返回后再依据同一段学习补充评价。

## 6. 评分追溯：保留什么、如何使用

有必要保留评分记录。它应能回答“当时答了什么、用了哪些帮助、AI 为什么这样判断、程序实际采用了什么、下次复习日期为何变化”。聊天记录是证据来源之一，不能成为唯一账本。

| 记录       | 至少保存的内容                                                                     |
| ---------- | ---------------------------------------------------------------------------------- |
| 原题与原答 | 题目/材料版本、方向、目标词义、原始文本、答案身份、提交和确认时间                  |
| 学习证据   | 各阶段实际操作、退回、各轮拼写首答与订正、复习自评、帮助和曝光事件引用             |
| 相关讨论   | 本题会话与消息身份、与评价有关的最小片段、发生时间，明确在首答之前还是之后         |
| 评价输入   | 证据快照身份/版本与哈希、包含的事件范围、必要的规范化字段、补查历史的引用          |
| AI 结果    | 目标词的意义/拼写/运用表现、错误分类、简短依据、证据引用、不确定或未测到的部分     |
| 模型与规则 | 实际模型、推理强度、提示/Skill 版本及内容哈希、评价规则版本、调用时间              |
| 程序采用   | 采用/部分采用/拒绝/待核对、原因、采用规则版本、对应的能力和调度事件身份            |
| 排期变更   | 调度状态与到期时间前后值、算法/库/参数版本、理想到期与实际到期、次日规则或错峰原因 |
| 重试与修订 | 任务与请求身份、重试关系、旧结果与新版本、修订原因、替代关系和提交回执             |

既保存结构化结论，也保存简短、可读的依据；不要求或保存模型隐式思维过程，不记录凭据。无需每次复制完整终身聊天：不可变事实以稳定引用复用，模型实际采用的最小输入包单独保存。仅保存哈希不能重建依据，因此还要保留必要原文或可解析的持久引用。

证据在确认下一题时确定范围。原答案与答前帮助先固定，答后讨论单独标注；后续另一词的聊天、后来发生的复习或新的提示不能串入旧题首答。后台补查历史也按该时间范围查询。新回复或用户申诉需要改变评价时，生成修订版本，不能覆盖旧记录。

清除聊天与删除学习/评价记录是不同操作。学习记录保留必要的原答、帮助事实、评价与采用结果；不靠“最近 12 条聊天”继续推断旧评分。若用户明确要求删除相关聊天正文，关联输入包中的正文副本也要按范围处理，保留删除标记和已采用结果，不从备份输入静默恢复聊天。缺失证据的重新评价显示不可完整重现，不让 AI 补造原文。应用内数据导出、恢复与清理功能仍按用户要求暂缓，本轮只规定保存与引用边界。

相同输入与规则版本的重试复用原结果和回执，不再次增加完成数或叠加一次 FSRS 复习。评价修改是同一事实的新解释，不是新发生一次作答。迟到评价按原事件顺序重算受影响状态，保留后续真实复习，不能直接拿旧状态覆盖现在的 due。重算校验失败时保留待核对结果及现有有效排期。

## 7. 统一排期与负荷控制

### 评价的作用与资格

复习采用固定、可解释的自评/拼写规则；新词结合相同类别的学习事实和 AI 对翻译的分析。两者都可以影响下次复习安排，不设置“复习成绩低一等”或“AI 分天然优先”的关系。

算法输入必须区分词义理解、拼写和运用，不把一句译文的整体好坏复制给所有词。题目未要求目标词而用户用了正确同义词时，目标词可能未测到；其他词或冠词错误不自动让当前目标词变成遗忘。目标词拼写错误则保留为该词的复习证据。

服务端统一采用规则，而不是让模型直接写 `due` 或修改记忆状态。可明确独立回忆成功、费力但确实成功、未能回忆的，才分别对应适当评级；不因回答慢、窗口隐藏或打断而扣分。Hard 表示成功但费力，不能把未回忆出来的答案仅因后来订正而转为 Hard。[Anki 回答按钮说明](https://docs.ankiweb.net/manual/studying#answer-buttons)

观看、自评、近期重复、带提示练习和独立测验保留各自证据类型。已有 `d0-v1` 独立测量分类器继续按原语义解释历史；新的综合调度评价另设版本，不能放宽旧分类器后把支持练习改称客观独立成功。自评属于用户报告，AI 语义判断属于模型评价，来源如实记录。

同一学习过程的多次订正不机械增加多个 Good 或多个失败；首答错误不被后续成功抵消。各类错误保留不同原因，程序依据有版本的规则合成，不做次数无限相加的惩罚分。三轮判断失败后重学、三轮拼写失败退出都标记为需要较近复习，下一自然日再安排。没有新作答则不制造遗忘事件。

当前采用一个有界的初学保守规则：记忆退回或拼写首答错误，将第一次真实复习后的间隔限制在最多 2 个自然日；累计至少三次记忆失败或三轮拼写失败时为 1 日。模型明确识别目标词拼写错误时上限为 1 日，其他明确目标错误为 2 日。第二次真实复习起解除这项初学限制，交给后续表现和 FSRS；不会把订正次数累加成多次失败。支持条件下只加保守上限，不伪造独立 Again/Good。这些上限属于可审计的首版产品规则，不宣称由研究证明最优。

AI 不确定、题目有问题、帮助范围不明或目标未测到时，保留待核对或仅教学结果；采用其他已经明确的事实和完成时的次日安排，不因一份不确定报告惩罚或延长间隔。

### FSRS 基线与错峰

实现起点沿用仓库锁定的 `ts-fsrs@5.4.2` / FSRS-6，目标保持率先用 0.90；不在这次流程调整中静默升级模型。显式拼写检验和新版综合排期均采用该锁定基线；新版综合排期使用空的分钟级学习步骤，完成后的首复习由当地次日规则控制。保留理解/拼写能力边界，词级入口合并相同词的到期任务，避免一次学习被多个能力重复拉回。具体采用边界见 [测量规则](measurement-rules.md)，已覆盖固定样例和隔离验证；支持条件不会被忽略后直接喂给库。

90% 是调度目标而非个人效果保证；更高目标通常带来更多复习，应根据真实跨日数据评估。[Anki FSRS 设置](https://docs.ankiweb.net/manual/deck-options#fsrs)

首次次日复习和上述严重失败后的次日复习不为削峰而随意后移。之后较长间隔可在合理的小范围内错峰，参考候选日期负荷，保存原建议、调整后日期与规则；不为清空积压批量篡改 due。随机扰动与基于扰动范围的负载均衡有现成实践，但不保证消除所有峰值。[FSRS Helper 负载均衡](https://github.com/open-spaced-repetition/fsrs4anki-helper#load-balance)

今天完成 50 个新词，明天至少有这 50 个首次复习，另加历史到期量。首页应显示预计负担；积压大时先复习，建议降低当天新词目标，由明确计划调整生效。长时间停学后可以分次处理积压，不能把没做的词自动顺延并声称复习已清空。

窗口 5、间隔 3、三轮上限、组大小和首次次日规则属于已确认的产品设计；不能说这些数值由研究证明最优。跨日记忆、工作量和支持依赖需要实际使用验证，文献依据与旧实验范围见 [调度研究](research/learning-scheduler.md)。

## 8. 材料、音频与暂停恢复

准备池与活动窗口、待拼写集合、最终完成集合分开。目标 50、窗口 5 时，可先准备 55 个候选；途中按剩余目标和缓存补缺，不固定只取 20 个，不把储备词全塞进拼写或翻译。

明确开始学习后，在复习期间后台准备新词；当前需要展示的材料优先，未来储备未全部准备好不能挡住已有完整材料的学习。需要的当前词尚未准备好时使用既有四步真实进度；互不依赖的步骤可以同时转圈，完成变绿，有依赖的步骤等待前置结果。首页只读预览不触发整库备课。

单词音频输入由程序固定为单词，例句使用保存后的实际句子；生成后持久缓存，单条重生成有版本。完整词卡进入或展开时按单词、完成后半秒、例句的顺序播放，点击可重播。句子回忆页自动播放该例句，单词回忆页自动播放该单词。正式拼写首答和订正出结果后自动读一次单词，并保留主动听音入口。语音帮助、实际播放和曝光继续如实记录。

暂停保存窗口成员与阶段、轮转/间隔、待拼写集合、组身份、回忆初选/展开核对/改判待确认、首答/订正/绿色确认、翻译原答与停留位置、完成事件和评分队列。继续时读取服务端事实；后台评分可以继续，但不能因此把用户当前题切走。切词、隐藏和暂停仍终止当前播放队列。

本轮实现会重新构建应用并更新现有开发版入口，已经认可的菜单实现与外观保持不变。导出、恢复、清理和声音克隆仍暂缓。

## 9. 迁移与验收要求

新规则必须使用新的流程/评价版本，不能复用 `three-rounds-v1` 重放旧事件。已有答案、组进度、音频和调度事实不丢失；已经作答的旧组可继续原规则，或通过显式迁移检查点保存原状态后转换，不能按新规则重判过去的错误。目标计数从真实完成事件投影，缺少证据的历史不能补造“完成”。

以下场景是实施验收要求。已有固定事件、SQLite、HTTP 与原生闭环验证；证据及真实模型结果见 [Demo 实施计划](demo-plan.md)和 [macOS 验收](macos-mini.md)。主观布局、听感及真实连续跨日使用不以测试时钟替代：

| 场景                           | 必须观察到的结果                                                   |
| ------------------------------ | ------------------------------------------------------------------ |
| 窗口 5，先处理 a/b/c/d         | a 可在 e 初见前复现，随后 e 得到服务；没有整组阶段栅栏             |
| a 在阶段 1 回答不会            | a 退到 0，不腾位、不马上连考；其他词正常出现                       |
| a 阶段 2 通过                  | 未满组时下一张补入新词；恰好满组时进入拼写                         |
| 阶段 1/2 点想起来了            | 立即多亮一颗绿点，展开完整词卡并读词、停半秒、读例句，等待核对确认 |
| 展开后发现记错                 | 保存初选与改判，立即清零，停留 0.3 秒后自动确认退回 0 并换词       |
| 原本想不起来，看答案后懂了     | 仍保留这次未想起；确认后退 0，不能变成本次首答成功                 |
| 核对卡退出或重复下一词         | 恢复同一核对状态；确认仅推进一次，不重新隐藏造初见                 |
| 核对卡的正常保存               | 无通用撤销与常驻保存成功提示；真正保存失败仍可见且不丢输入         |
| 复习重学词通过阶段 2           | 仅补本批待重学复习词，没有则缩窗，不能提前补词库新词               |
| 五词始终不会                   | 窗口仍是这五词，允许暂停，不伪造通过                               |
| 日目标 50、组 20               | 最终完成组为 20/20/10，剩余窗口进度保留且不计完成                  |
| a 首轮错、第二轮首答对         | 第三轮不再出现 a，首轮错误仍可追溯                                 |
| 前两轮中反复订正               | 不额外增加首答失败轮数                                             |
| 第三轮拼写仍错                 | 可确认继续；新词进入翻译，复习结束本次，保存较近复习依据           |
| 复习三轮不清晰                 | 转三阶段重学再拼写，不增加新词完成数、不强制 AI 翻译               |
| 未清到期复习                   | 新词未解锁；暂停或只完成小批不绕过门槛                             |
| 翻译下一题时 AI 未连接         | 答案和评分任务已保存即可进入下一题，翻译页不显示评分进度           |
| 只翻译半组便退出               | 已确认题的评价仍可处理，当前未确认题原样恢复                       |
| 后题评价先于前题返回           | 按正确题与词义保存，不覆盖当前输入，不串用聊天                     |
| 重复下一题、重试评价、重启服务 | 完成和排期采用均不重复；持久任务不丢失                             |
| 次日评价仍未返回               | 昨日最终完成的新词已经出现在当日复习中                             |
| 先有次日复习，随后旧评价迟到   | 保留新复习，按原顺序重算或待核对，不用旧快照覆盖                   |
| 用户讨论后写出了更好表达       | 原答、答前帮助与答后讨论可区分，不冒充首次成功                     |
| 查询某词为何明天复习           | 能定位原答、证据、AI 理由、采用规则和排期前后值                    |
| 材料已齐但储备池未齐           | 已有材料可学习；储备数量不成为全组等待门槛                         |
| 旧组、旧评价迁移               | 原事实和版本可读，不以新三轮上限重写旧五轮历史                     |

实施依次覆盖服务端状态与命令、材料池与 UI、评价流水与调度、迁移和隔离真实闭环；分步范围与完成证据只更新 [Demo 实施计划](demo-plan.md)，不在本文建立另一份进度账本。

## 10. 首版交付边界

后台评价当前逐题持久执行，失败可从首页重试；已保存结构化结果的采用重试不会再请求模型。模型批量合并请求、人工申诉后创建修订版、聊天正文跨输入包删除、完整未来负荷预览和应用内数据管理暂未提供。已有结果不能被相同身份覆盖。评价详情可查看原题原答、结构化结论、模型和规则、采用原因及前后到期日期。跨日学习效果与长期积压仍须实际使用评估。
