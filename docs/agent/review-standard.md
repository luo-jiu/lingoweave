# 评审与验证

从用户能观察到的变化开始检查。学习者在哪里点击或按键，哪一笔操作会成为学习事实，离开页面、重开应用、服务迟回时会看到什么。

| 改动范围               | 重点核对                                                                                                         | 验证入口                                                                                                                        |
| ---------------------- | ---------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| 学习流程、契约、SQLite | 旧记录能否读取。重复提交是否只记一次。切词后到达的回复是否仍对应原词、原题。                                     | `pnpm check`，再用 `pnpm test:mini` 走 Swift → HTTP → SQLite 和数据库重开。                                                     |
| 窗口与词卡交互         | 在实际尺寸下试键盘焦点、连按、切词、亮暗外观，以及后台回执到达时的布局。大量数据的列表要试首尾页、筛选和空结果。 | `pnpm test:mini` 覆盖原生客户端与窗口测试。用隔离数据复走本次修改的界面路径。                                                   |
| 排期、统计和曲线       | 对照词义与拼写证据。检查日期、过期任务、证据缺失和累计口径。只读操作前后比较学习版本和排期。                     | [记忆查询测试](../../apps/server/src/mini-memory.test.ts) · [曲线场景报告](../research/mini-scheduling-scenarios-2026-11-17.md) |
| AI 或音频              | 核对任务能调用的工具、原始答案、重复回执、切词后的迟到结果。分别记录受控运行时和真实模型或扬声器的验收范围。     | [mini 集成测试入口](../../scripts/test-mini-service.mjs) · [已有实机验收](../macos-mini.md)                                     |

`pnpm check` 运行格式、lint、类型检查、测试和构建。macOS 原生流程另由 `pnpm test:mini` 运行。测试作答、排期和重置使用隔离数据。

提交评审意见时写明能复现的操作、实际后果与代码位置，然后列出跑过的检查，以及仍需实机核对的部分。
