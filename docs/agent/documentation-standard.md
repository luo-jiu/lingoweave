# 文档维护约定

开发前由[交接索引](handoff.md)找到负责这个行为的专题。开发后从用户的入口再读一遍那段说明，如操作步骤、数据含义或验证方式已变，就在同一次改动里修正。

| 内容                         | 维护位置                                                                                                                            |
| ---------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| 开发入口与目录导航           | 根 [AGENTS.md](../../AGENTS.md) 和 [文档首页](../README.md)                                                                         |
| 代码入口、评审方法、文档分工 | `docs/agent/`                                                                                                                       |
| 当前产品规则、架构、运行方法 | [学习流程](../learning-flow-rules.md)、[架构](../architecture.md)、[开发指南](../development.md)及对应专题                          |
| mini 的独立窗口与功能        | 从 [macOS mini](../macos-mini.md) 进入。需要独立描述交互、接口和验证的功能放入 `docs/mini/`，例如[记忆曲线](../mini/memory.md)。    |
| 后续工作、实验和历史记录     | 阶段范围写入[实施计划](../demo-plan.md)。研究资料和可复跑的样例放入 [research](../research/)，退役方案放入 [archive](../archive/)。 |

同一条规则在负责它的专题里解释，其他入口链接到该处。接口字段和校验以共享契约为准，专题记录调用场景、数据由谁产生、失败后怎样恢复。把“已接入”“已通过隔离测试”“已实机验证”和“计划中”写清楚。

**新增专题时**，用小写英文与短横线命名，以用户能找到的功能命名标题。在文档首页或所属模块入口加链接。如果拆出已有章节，保留原标题作为跳转入口，检查正文、脚本和研究资料里的引用。

**记录验证时**，写清使用的入口、数据规模、观察到的结果和未覆盖的边界。示例使用合成数据，命令中的个人路径用仓库相对路径或 `~`。账号、凭据和个人学习内容留在本机。
