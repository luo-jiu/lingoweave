# 开发指南

## 环境与启动

工程固定 Node.js `22.22.0`、pnpm `11.25.0`，依赖以根目录 `pnpm-lock.yaml` 为准。使用 nvm 时在仓库根目录执行：

```sh
nvm install
nvm use
corepack enable
pnpm install
codex --version
codex login status
pnpm dev
```

此前 mini 集成与检查使用本机 Node.js `24.22.x`。本轮应用资源固定携带 Node `22.22.0`，该运行时已独立通过乱序调整前的 173 项服务端全量测试，以及乱序后的三项词库专项测试，其中一项为新增用例。最终工程检查通过 174 项服务端与 25 项网页测试，搬移包内服务也完成拒绝读取仓库的鉴权 HTTP 验证。

真实备课需要可执行的 Codex 运行时及已有登录状态；网页默认查找 PATH 中的 `codex`，也可用 `CODEX_BIN` 指定完整路径。mini 构建及启动器在没有显式配置时还会查找默认安装位置内的 Codex 运行时，包括 `/Applications/Codex.app/Contents/Resources/codex` 和本机实际使用的 `/Applications/ChatGPT.app/Contents/Resources/codex-cli/CodexCLI.app/Contents/MacOS/codex`，可用时无需再安装一份 CLI。D0 既有协议验证版本为 `0.153.4`；2026 年 11 月 13 日 mini 使用 `0.167.0-alpha.4.1` 分别验证四类文字任务。11 月 16 日实际运行时 `0.169.0` 已验证 `gpt-6.1-sol` / `xhigh`、六工具清单和真实音频查询/重生成，复习预览已核对真实生成和播放，其他阶段完整界面与主观听感仍待验收。登录和账户管理由 Codex 负责。查看已保存材料不要求调用模型。

浏览器打开 <http://127.0.0.1:5186>，服务默认位于 <http://127.0.0.1:4310>。根目录 `dev` 先构建共享契约，再启动契约监听、Vite 和 `tsx watch`。按 Ctrl+C 结束开发进程及其当前 Agent 任务。

mini 优先的后续路线见 [mini 学习、AI 与语音方案](mini-ai-learning-plan.md)。mini 构建先生成 contracts/server，并封装固定 Node、生产依赖与服务资源。应用 `launch` 从包内相对路径确保本地 Node 服务就绪。开发版使用 `4311`，正式版使用 `4312`，现有网页服务仍用 `4310`；不同 mini 版本各自使用 bundle ID 对应的 `service/` 数据目录。AI 备课、写作、反馈与顾问均由 Node 任务入口管理，默认 `gpt-6.1-sol` / `xhigh`，执行前核对能力，不可用时保留选择并失败，不静默换模型或强度。启动、停止、凭据与迁移限制见 [mini 本地服务说明](macos-mini.md#本轮本地服务接入)，分步证据见其验收记录。

mini 单次模型轮次等待上限为 6 分钟，与手工真实模型验收脚本一致；超时保留已提交结果，未完成内容可主动重试。该上限不改变网页 D0 的既有设置，也不保证模型每次都在上限内产出完整结果。

mini 每次启动默认不置顶，图钉可在本次运行中切换。开发版默认进入正常流程首页，阶段预览通过 `dev` 二级菜单主动选择。

启动器比较 Node/Codex 可执行路径、版本、编译后 server/contracts、语音 worker 和 `MINI_TTS_ROOT` 的构建指纹。同一构建和运行时会复用现有服务；指纹变化时，先验证服务进程身份，再重启旧编译版本，避免新界面继续使用旧接口。打开首页或学习计划仅查询只读 `plan-preview`；只有用户明确开始或继续才创建本次预算，并按需准备材料。

应用资源中的 `service/` 包含 `runtime/node`、服务与共享契约产物、生产依赖、任务 Skill、语音 worker 和清单。构建器 `scripts/package-mini-service.mjs` 从固定版本下载并校验 macOS Node 22.22.0，在 `~/sdks/node/` 缓存，再复制进应用。移动构建好的应用时按包内相对位置启动，已有 Codex 登录和 `MINI_TTS_ROOT` 指向的本地语音环境继续复用。debug/release 应用包构建及隔离搬移服务已验证，快捷键按键动作仍待人工确认。

全局唤出/隐藏默认使用 Control+Option+Space，菜单栏的「全局快捷键」可选择 Control+Option+L 或关闭。注册冲突在菜单显示，可改用另一个组合。启动仍默认不置顶。

## 配置

可选地把 `.env.example` 复制为 `.env`。服务端从仓库根目录加载它，已有进程环境变量优先。`.env` 不提交 Git。

| 名称                 | 默认值                  | 用途                                                                                     |
| -------------------- | ----------------------- | ---------------------------------------------------------------------------------------- |
| `NODE_ENV`           | `development`           | 开发、测试或生产方式                                                                     |
| `HOST`               | `127.0.0.1`             | 服务监听地址                                                                             |
| `PORT`               | `4310`                  | API 及生产网页端口                                                                       |
| `DATA_DIR`           | `data`                  | 数据目录；相对路径相对于仓库根目录，也可使用绝对路径                                     |
| `CODEX_BIN`          | `codex`                 | Codex 可执行文件名称或完整路径，不是 shell 命令                                          |
| `MINI_TOKEN_FILE`    | 未设置                  | 可选的本地 mini Bearer 凭据文件；配置后启用原生 API，所有读写校验凭据并拒绝浏览器 Origin |
| `MINI_TTS_ROOT`      | `~/sdks/lingoweave-tts` | 已安装本地语音环境根目录，包含 runtime、models 和校验清单；服务不下载模型                |
| `LINGOWEAVE_API_URL` | `http://127.0.0.1:4310` | Vite 开发/预览代理目标，需作为启动 Vite 的进程环境变量传入                               |

修改开发端口时同时设置服务端端口与前端代理，例如：

```sh
PORT=4311 LINGOWEAVE_API_URL=http://127.0.0.1:4311 pnpm dev
```

`LINGOWEAVE_API_URL` 当前直接由 Vite 配置读取 `process.env`；仅写入后端加载的根目录 `.env` 不会自动设置 Vite 进程。前端组件继续使用 `/api` 相对路径。不要将密钥或 MCP 任务凭据放入前端环境变量。

## 常用命令

| 命令                                | 行为                                                                 |
| ----------------------------------- | -------------------------------------------------------------------- |
| `pnpm dev`                          | 启动前后端及共享契约监听                                             |
| `pnpm dev:mini`                     | 构建并打开 mini 开发版及其本地服务                                   |
| `pnpm typecheck`                    | 检查各包 TypeScript 类型                                             |
| `pnpm lint`                         | 检查代码规范                                                         |
| `pnpm format` / `pnpm format:check` | 格式化 / 只检查格式                                                  |
| `pnpm test`                         | 运行前后端行为测试，不调用真实模型                                   |
| `pnpm test:mini`                    | macOS 原生、客户端恢复与四条 Swift/HTTP 流程及学习/AI/音频库重开验证 |
| `pnpm build`                        | 按依赖顺序生成契约、网页和服务产物                                   |
| `pnpm check`                        | 运行格式、lint、类型、测试和构建检查                                 |
| `pnpm start`                        | 以生产模式运行已构建的服务及网页                                     |

生产运行使用 `pnpm build` 后执行 `pnpm start`，打开 <http://127.0.0.1:4310>。修改源码后需重新构建；`start` 不监听源码。开发和生产默认共享数据目录，切换前先停掉原服务。

## 在 WebStorm 中运行

推荐打开整个 `lingoweave` 仓库，前后端仍是两个独立子项目。共享契约、锁文件和根启动命令都在同一个 workspace，打开根目录便于一起管理。单独打开 `apps/server` 也可以编辑后端，但安装依赖和准备共享包仍在仓库根目录完成。

在 WebStorm 的 Node.js 设置中选择项目 `.nvmrc` 指定的 Node 22.22.0，包管理器选择 pnpm。也可在 IDE 终端进入仓库根目录后运行 `nvm use`。打开根 `package.json`，点击脚本旁的运行按钮，或创建使用该文件的 npm/pnpm Run Configuration：

| 目的                 | 运行方式                                                                                          | 页面入口                           |
| -------------------- | ------------------------------------------------------------------------------------------------- | ---------------------------------- |
| 体验已构建页面       | 先运行 `build`，再运行 `start`                                                                    | `http://127.0.0.1:4310`            |
| 修改前后端并即时预览 | 运行根 `dev`                                                                                      | `http://127.0.0.1:5186`            |
| 只开发后端 API       | 先执行 `pnpm --filter @lingoweave/contracts build`，再执行 `pnpm --filter @lingoweave/server dev` | `http://127.0.0.1:4310/api/health` |

`start` 由后端同时提供编译后的网页，不需要另开 Vite。只启动后端开发脚本时，后端不托管网页；若需要网页联调，再启动前端。共享契约修改后需重建它，或单独运行 `pnpm --filter @lingoweave/contracts dev`。

开发脚本会在任一子进程退出后结束整组。若其他项目已占用 5186，前端会因端口冲突退出；可先停掉占用端口的项目，或在保留后端与契约监听的情况下，用 `pnpm --filter @lingoweave/web dev --port 5187` 单独启动前端。不要同时启动使用同一数据目录的两份后端。

服务应由自己的终端或 IDE Run 窗口管理，日志也在该窗口中查看；临时 Agent 执行会话不作为常驻服务管理器。后端是独立 Node.js 进程，不要求 Codex 桌面应用保持打开。当前 AI 备课使用本机 Codex CLI 及其已有登录状态；Codex 不可用时可以继续查看已保存材料，生成新材料会显示不可用或失败。

以上进程管理方式指网页服务；mini 由应用启动脚本管理其本地服务，退出 mini 不关闭服务。开发版通过 `node scripts/mini-service.mjs --dev --stop` 正常停止，正式版去掉 `--dev`；下一次打开应用自动恢复。`service/` 内的 `token`、`process.json`、`service.log` 和数据库属于本机运行数据，不提交仓库。

## 界面显示设置

首页和学习页的页头均可选择「跟随系统」「浅色」「深色」，默认跟随系统，并实时响应系统外观变化。手动选择浅色或深色后，以该选择为准；切回跟随系统即可恢复自动切换。

主题偏好以 `lingoweave.theme` 保存到当前浏览器的 `localStorage`，刷新、切换页面后仍保留，同源标签页会同步。浏览器禁止存储时仍可在当前页面切换。主题属于本机界面偏好，不写入服务端学习记录。浅色主题保留原有配色；后续新增界面沿用 `apps/web/src/theme.css` 的语义颜色变量，为新状态同时定义浅色与深色表现。

显示设置中的简约模式以 `lingoweave.compact` 保存到当前浏览器，隐藏整段学习标题与说明、装饰性小标题和聊天介绍等辅助引导文字；真实错误、暂停、轮次、进度、演示未保存与 AI 未连接等必要提示保留。关闭后恢复文字，不重置当前自评、练习、轮次或草稿。普通控件采用 2px 焦点圈与 2px 间距，组合选择框和聊天输入框通过外壳显示单圈焦点，不能因压缩样式而移除键盘焦点。

`/study` 的学习操作仍只在当前页面内存中保留，和持久化的显示偏好分开。复习任一自评后、新词标记记住后可主动开启单卡默写，撤销标记时收起；单卡比对不计掌握、整批轮次或通过数量，不替代整组总拼写。接入服务端时须保存这些额外原始输入、比对和答案揭晓，并纳入支持条件与最近曝光，不能产生独立 Good。

## 数据与中断

SQLite 使用 Node.js 自带的 `node:sqlite`，Node 22 当前会输出实验性 API 提示。数据目录中包含 `lingoweave.sqlite`、运行时 WAL/SHM 文件、进程锁与 Agent 工作目录。当前迁移随服务启动执行，数据库版本为 `user_version = 1`；后续表结构变更必须新增迁移版本，不能靠删除数据库更新。

同一数据目录只允许一个服务实例。遇到“already open in another LingoWeave process”时，先停止仍在使用该目录的进程；独立测试可以设置另一个 `DATA_DIR`。不要在服务运行时删除锁或数据库。进程退出后正常释放锁；异常退出留下的锁会在下次打开时检查原进程是否仍存在。

重启后可重新查看已提交材料。未完成的准备任务显示中断，用户主动重试；不会在启动时自动调用模型。重试复用当前五词组并创建新的尝试。D0 不续接临时 Codex 线程，已保存平台记录负责重建上下文。

应用内导出、恢复与清理本轮暂缓。如需手动备份，先停止服务，再复制整个数据目录；不要只复制仍在写入的 SQLite 主文件。个人数据、来源文件、凭据和生成产物不提交 Git。

mini 的学习模块单独保存为对应服务目录下的 `data/mini.sqlite`，当前数据库版本为 `user_version = 4`；旧版本自动保留历史迁移，学习、计划、重点、偏好和曝光仍使用 `schemaVersion: 1` 快照。`DailyStudy` 与 `Review` 旧文件通过备份和幂等导入保留历史，导入后不再双写。新建组的写作题需单独准备，不能在测试或界面里继续把看词例句当作新写作材料；旧组保持历史兼容。

同目录的 `mini-ai.sqlite` 保存 AI 任务、聊天、配置、请求与待确认工具命令。旧 `StudyChat.json` 先按原字节备份，再以固定请求身份迁入；没有原时间的消息保持为空。原生端仅保留不可变迁移备份、待确认请求和草稿，不再写另一份聊天真相。旧本地英语水平不会自动伪造成用户偏好；菜单改级通过真实顾问请求和业务回执保存。

学习库与 AI 任务库各自提交事务，通过固定工具身份和学习库回执恢复对账。若学习命令已保存而任务库未记录完成，重启时补认该回执；部分材料保留，未满足实际目标的任务保持可重试。启动不自动重发模型任务。停止任务只取消后续工作，不撤销已经提交的学习和材料。手动备份先停止对应 mini 服务，再保留整个数据目录，包括学习、AI、音频、词库四个数据库、`audio/` 与词库来源文件，不只复制仍在写入的主库。

mini 的 AI HTTP 接口集中在 `/api/mini/ai/`，与原生学习接口使用同一 Bearer 和 Origin 边界。MCP 临时凭据按任务开放四个基础工具；接入语音服务的顾问额外获得 `learning_get_audio` 与 `learning_generate_audio`，可查缓存及请求生成/单条重生成，任务入队和资产就绪分别返回。播放与开始回执由原生端提交。写入由 MiniStore 再校验版本、对象范围与白名单。原生只在活跃任务期间查询任务快照，不通过重复模型调用维持进度。学习历史支持分页；聊天快照当前只返回最近 200 条消息和 50 个任务，提示词只携带对应会话最近 12 条消息，没有自动长期摘要或向量检索。

`pnpm test:mini` 先构建契约和服务，再由 `scripts/test-mini-service.mjs` 启动隔离临时数据与随机端口，验证四条 Swift → HTTP → SQLite 流程，分别覆盖完整学习与导入、保留旧组并另做只复习组、顾问至定性反馈的四类任务，以及音频生成/缓存/授权/开始回执。第三条使用受控文字运行时，第四条使用受控 TTS 与播放器，均经真实 HTTP 保存业务结果。运行器关闭、重开四个学习库、一个 AI 库和一个音频库，逐字段核对快照。最新已通过 47 项原生与客户端测试和四条 HTTP 流程，测试使用隔离数据。真实模型生成与扬声器播放需分别验收。

真实模型验收脚本为 `scripts/test-mini-ai-live.mjs`，须在构建后手动执行，会使用已有 Codex 登录和所选模型的实际调用额度，不纳入 `pnpm check`。默认依次验证顾问、备课、写作和反馈四类任务：

```sh
pnpm build
node scripts/test-mini-ai-live.mjs
```

只需复测写作与反馈时，在已构建的仓库运行：

```sh
MINI_LIVE_TEACHING_ONLY=1 node scripts/test-mini-ai-live.mjs
```

第二种模式先注入明确标识的隔离学习例句，再实际调用写作与反馈；该种子例句不是本次 AI 生成。两个模式均使用临时学习库与任务库，在 `finally` 中关闭并删除，不读取或写入个人学习数据。脚本核验独立写作、定性反馈、原答与排期不变及关闭重开一致。当前真实证据来自分段运行与复测，不是一次无中断的四任务全链；失败和成功结果见 [mini 验收记录](macos-mini.md#第三步实现与待补验收)。

### 单卡练习、独立检验与词库

本轮工程检查通过 199 项行为测试，隔离原生和 HTTP 已通过 51 项及四条流程，六库重开结果一致。单卡至写作完成、重启记录及独立检验的中文题面/过早回答已实际点击验证。隐藏窗口边界补充后的 51 项原生与四条 HTTP、六库重开核对也已再次通过。个人词库已启用，乱序新组的真实旗舰备课与十条单词/例句音频已保存，快捷键动作仍待人工确认。

`mini.sqlite` 新增 `practice` 与 `scheduling` 事实。单卡默写在复习自评后或新词记住后主动开启，保存输入、比对、揭晓与帮助。记住后保留当前卡，明确前进再切词，撤销自评/记住关闭对应练习。

显式独立检验通过共享命令的 `begin_probe`、`submit_probe`、`reveal_probe`、`end_probe` 保存，原生仅显示中文提示，关闭自动音频。服务端共用测量分类器，合格独立成功/失败调用 `ts-fsrs@5.4.2` / FSRS-6 的 Good/Again，记录评分前后、参数与 due。曝光、支持练习、过早回答与揭晓继续保留事实和分类。新计划读取调度快照，历史旧排期可继续核对。

词库接口为 GET `/api/mini/vocabulary/catalog`、POST `/api/mini/vocabulary/import` 与 POST `/api/mini/vocabulary/activate`，共享契约位于 `mini-vocabulary.ts`，沿用 mini Bearer 与 Origin 边界。词库使用 `mini-vocabulary.sqlite` 和独立修订号。激活后原生使用 `activeWords` 创建后续新组，完整课程按 A1→B2 排级，同等级采用稳定乱序，原 rank 和来源元数据保留供追溯。既有组保留原目标。

`scripts/build-oxford-vocabulary.py` 从个人 `service/data/vocabulary/sources/` 中的牛津官方 CEFR PDF 和固定 ECDICT 来源构造导入请求，输出文件也保留在个人数据目录。脚本提供 `--source-dir`、`--output`、`--revision` 与可选 `--activate`，默认只生成请求文件。来源保留 URL、commit/版本、SHA-256、原词条和本地词义规范记录，生成资料与源文件不进入应用资源。个人 HTTP 导入与启用已完成，`activeDeckId` 为 `oxford3000`，`activeWords` 为 3,003 个拼写/释义目标，拼写口径为 2,981。已验证使用保留的来源子集复建，原 66MB CSV 临时下载文件已清理。

AI `curriculum` 返回活动词库、目标词等级和 `sentenceLevel`，句子难度优先使用已保存的 `english_level`，缺省 A1。词条工具可查所导入的中文释义、音标、词性与等级。词表等级与用户水平分别传给模型。

### 每日复习期间备课与新词准备

用户明确开始或继续每日组后，`MiniStudyView` 在复习期间补发缺少的例句准备任务，导入就绪、前次任务提交结束或学习状态变化后会重新检查。入口限定在真实每日词卡学习，首页、计划、词表浏览和旧手动复习只保留各自流程。文字任务仍走现有 Node 持久任务和工具权限，音频使用现有协议。

`MiniAudioController.prefetch` 按组作用域观察每个目标，分别显示等待、请求、排队、生成、就绪和失败。独立请求可快速入队，由本地 worker 串行生成。有效缓存直接就绪，完成任务须在快照中找到对应资产才计数。失败后只重试等待或失败项，活跃任务和已有资产继续复用。换组使旧观察失效，重连用 `ensure` 恢复，服务端已经创建的任务仍可完成。

`MiniLessonPreparation` 将服务端已选单词、已有例句和音频观察映射为四个步骤，`MiniDailyView` 展示各步实际数量及总体进度。进入新词时若未齐则显示可滚动准备页，全部就绪后自动转入看词。例句齐备且音频确已失败时，可明确选择「先学文字」，仅作用于本次组作用域并关闭自动读词，仍可主动试听。准备观察的真实 HTTP、材料并发恢复与 360 × 300 点界面已验证，详细范围以 [mini 记录](macos-mini.md#复习期间备课与新词准备流程)为准。

背景例句或重点保存可能导致学习命令收到明确 `409`。客户端仅对记忆判断、判断前进、拼写和记住四种动作检查安全重试资格，要求原操作时间存在，且版本差异仅增加材料，计划、帮助、会话、原答和其他学习事实均一致。符合时使用新请求身份及原操作时间重试一次。未确定 HTTP 结果和恢复 outbox 沿用原身份，其他冲突刷新后保留输入。新增客户端测试与真实 HTTP 已验证新请求身份、原操作时间和仅一次重试。受控文字运行时还覆盖旧版本材料提交被拒绝后重新读上下文、分批补齐例句，用户已保存的错误首答和阶段均保留。

### mini 音频生成与播放

音频状态、快照、任务和请求位于 `/api/mini/audio/`，文件通过 `assets/:id/file` 鉴权读取，播放授权和实际开始分别使用 `playback`、`playback/started`。所有入口沿用 mini Bearer 与 Origin 边界，文件入口仅接受 UUID。音频库为 `mini-audio.sqlite`，实际 WAV 位于同目录 `audio/`；学习、AI、音频和词库四个业务库与相对文件应一并备份。旧资产目前保留，应用内清理尚未实现。

配置 `MINI_TTS_ROOT` 可更换已安装的 SDK 根目录。Node 的 `mini-audio-runtime.ts` 通过 `scripts/mini-tts-worker.py` 调用该环境的 Python，服务启动只校验环境，生成时才加载模型。worker 每次启动校验本地文件 SHA-256，离线串行生成，通过跨实例 `fcntl` 锁避免重复加载，约 30 秒空闲退出。256MB 是 allocator 缓存限额，模型总内存另计。缺少环境时缓存仍可播放，新生成返回真实不可用原因。

缓存命中沿用已存音色和版本。明确重生成在新 WAV 校验完成后切换当前版本，失败保留旧资产；请求返回 `queued` 只表明已创建任务。首次生成随机池为 `ryan`、`aiden`、`serena`。词义、音标与引擎参数参与身份，发音软提示仍需试听验证。

正常流程在实际看词卡自动播放一次，例句手动播放，拼写/翻译仅主动请求提示。旧卡、隐藏、静音或暂停后的结果失效。授权先保守保存帮助，`AVAudioPlayer.play` 成功后再保存实际开始时间，未确认开始回执在本地恢复文件中按原身份重试。支持条件与原首答时序由服务端校验。

开发阶段预览也使用真实语音生成、缓存、鉴权文件和播放器，生成与单条重生成持久保存到开发版音频库并共享当前版本。预览试听跳过学习授权、帮助、实际开始回执和恢复 outbox，学习操作及聊天仍只在内存。正常流程未确认开始回执在预览期间暂停，回正常流程按原身份及时间恢复。模式或词卡切换会取消旧访问，迟到任务可在服务端形成缓存，旧结果无法补播到新访问。最新调整已通过 47 项原生测试，其中 15 项音频测试覆盖预览试听、同身份模式切换、迟到授权、损坏 outbox 与真实待确认回执恢复。开发版实际窗口已核对复习判断预览的真实生成和单词/例句播放，学习快照与帮助保持原基线。

默认工程和原生测试使用受控运行时。单独运行音频客户端 HTTP 测试时，可传入 `MINI_TEST_AUDIO_SERVICE_URL` 和 `MINI_TEST_AUDIO_TOKEN_PATH`，根测试运行器自动提供隔离服务。真实离线模型验证另行手动执行，使用临时学习/音频库及临时文件，结束后删除，不读取个人账本，也不播放扬声器。

```sh
pnpm build
node scripts/test-mini-audio-live.mjs
```

该脚本已验证真实单词和句子生成、缓存不新建任务、指定音色单条重生成保留旧文件、鉴权 WAV 校验、授权与实际开始分开，以及两库关闭重开一致。

验证顾问的真实音频工具链可在构建后手动运行下列脚本。它复用已有 Codex 登录，实际调用 `gpt-6.1-sol` / `xhigh` 和本地 MLX，可用 `CODEX_BIN`、`MINI_TTS_ROOT` 指定既有运行环境。

脚本先在临时目录生成一个 `aiden` 缓存，再让真实顾问查缓存并指定 `serena` 单条重生成，核对六工具清单、生成回执、旧文件保留、作答/计划/排期与播放记录边界，以及学习/AI/音频三个数据库关闭重开一致。结束后删除临时数据，需使用真实模型调用额度，独立于 `pnpm check`。本轮该脚本已一次通过。最新 `pnpm check` 通过 154 项服务端和 25 项网页测试及格式、lint、类型和构建，`pnpm test:mini` 通过 47 项原生测试、四条 HTTP 流程与六库重开核对。复习判断预览已实际核对生成及播放链路，其他阶段界面与主观听感仍待验收。具体记录见 [第四步验收](macos-mini.md#2026-年-11-月-16-日第四步实现与待补验收)。

## Node.js 与 TypeScript 后端

浏览器运行 React，Node.js 运行 HTTP 服务、保存和 Agent 管理。前后端各有 `package.json` 与构建产物，统一使用根目录依赖锁和开发工具。`@lingoweave/contracts` 的 TypeScript 类型检查开发代码，Zod schema 校验实际网络输入输出。

开发使用 `tsx` 运行 TypeScript；构建时 `tsc` 生成 JavaScript，生产入口由 Node.js 执行。项目采用 ESM，服务端相对导入写 `.js` 扩展名；TypeScript 开发时解析对应 `.ts`，构建后 Node.js 直接解析 `.js`。

主要入口：

- `src/index.ts`：加载环境、打开数据目录、组装运行时并启动/关闭服务。
- `src/app.ts`、`src/learning-routes.ts`：HTTP 边界与统一错误结构。
- `src/learning-store.ts`：事务、迁移和持久化事实；测试使用临时数据库。
- `src/mini-store.ts`、`src/mini-study.ts`、`src/mini-planning.ts`：mini 事实、阶段转换、三层计划、预算与保留组恢复。
- `src/mini-teaching.ts`：重点预算、有限偏好、帮助曝光与真实历史查询。
- `src/mini-ai-store.ts`、`src/mini-ai-service.ts`：任务、聊天、取消重试、上下文重建与业务回执对账。
- `src/mini-audio-store.ts`、`src/mini-audio-service.ts`、`src/mini-audio-runtime.ts`：语音任务、资产、播放回执和本地 worker 生命周期。
- `scripts/mini-tts-worker.py`：离线 MLX 生成与跨实例锁。
- `src/mini-routes.ts`：mini 快照、只读 `plan-preview`、导入、业务命令与音频边界。
- `src/preparation-service.ts`：任务与 Codex 生命周期；测试注入可控运行时。
- `src/codex/`：JSONL 适配与子进程测试。
- `src/learning-mcp.ts`：只调用平台内部业务接口，不另写数据库逻辑。

网页备课 Skill 通过协议显式传入 `skills/lesson-author/SKILL.md`，提供两个学习工具；mini 按任务传入 `skills/mini-lesson`、`skills/mini-feedback`、`skills/mini-advisor`，提供四个基础工具，音频顾问增加两个查询/生成工具。它们不需要安装到用户全局技能目录。更改工具、Skill 或 Codex 协议后，除自动测试外，还需完成真实模型验证并记录结果；本轮第三步四类任务已分别验证真实工具保存，完整原生点击与布局仍待验收，阶段预览和受控运行时测试不替代该证据。

## 增加功能

先明确用户行为、服务端事实与恢复要求，再更新共享契约、业务服务与界面。关键状态和保存边界添加行为测试；前端处理加载、失败、取消和重试，遵守[产品规则](product.md)与[测量规则](measurement-rules.md)。完成后运行 `pnpm check` 并验收实际交互。

新增依赖使用 `pnpm --filter @lingoweave/web add 包名` 或 `pnpm --filter @lingoweave/server add 包名`；开发工具使用 `pnpm add -Dw 包名`。不要混用 npm/yarn 生成另一份锁文件。

修改前阅读根目录和对应应用的 `AGENTS.md`。分支使用 `feat/`、`fix/`、`docs/` 或 `chore/` 前缀。完整产品路线与当前差距见 [Demo 计划](demo-plan.md)。
