# AI 英语学习构思与落地评估

> 2026-11-03 已迁入项目。本文件保留立项时的完整构思、选型与调研依据；正文中的阶段描述属于当时记录。当前产品规则见 [产品文档](../product.md)，实施进度见 [Demo 计划](../demo-plan.md)和 [D0 验收](../d0-acceptance.md)。后续资料统一维护在项目 `docs/` 中。

状态：立项基线 v0.6，更新于 2026 年 11 月 3 日。已确定“复习 → 自助看词与自评 → 整组总拼写循环 → AI 分析 → 句子练习”的主流程，以及双 Agent、网页通信和首个 Demo 实施范围。总拼写前不安排拼写题，背词循环中没有 AI 实时干预。材料 Skill、词根 PDF 和句式学习纳入后续扩展方向。尚未启动应用编码或 Agent 接入联调。

目标是建立一个长期陪伴个人提高英语读写能力的工具：算法根据学习历史确定合适的任务，AI 组织材料、解释和反馈，用户通过阅读、回忆、拼写及受控表达完成练习。学习记录应能长期保存、解释和迁移。

首版确定为独立网页应用，不依赖 OmniFlow，也不以未来接入插件为设计目标。核心分工是：算法决定学什么、复习什么和每日负荷；AI 可查询全部学习数据，决定怎么教、怎么出题和反馈；程序负责可靠记录与状态更新。

用户全程在学习平台开始、聊天、答题和查看反馈。Node.js 在后台管理本地 Codex Agent，使用教学 Skill 和业务工具完成教学；日常学习无需切换到 Codex 桌面或终端。前台默认由陪伴 Agent 交流，出题 Agent 准备课程并处理需要深入判断的问题；两者查询同一套学习记录。

算法和教学流程的详细依据见 [英语词汇学习算法与 AI 教学流程研究](learning-scheduler.md)。该专题包含真实时间与记忆状态、每日学习量剧烈波动、停学恢复、分组中断及可复现实验；具体参数中哪些属于研究结论、哪些是产品假设分别标明。

首个 Demo 的页面、模块、工具接口、数据、开发顺序、验收及项目名候选见 [首个 Demo 实施方案](../archive/demo-plan-2026-11-03.md)。先用 30～50 个核对过的词义完成能连续使用的小规模流程，再扩展材料类型。

## 已确定的目标与边界

- 以通用英语读写能力为目标，已经毕业，不围绕四级、六级考试安排学习。考试词表暂不纳入首版主线。
- AI 贯穿学习过程。用户在平台内输入“开始学英语”或点击开始按钮，由平台启动或恢复后台 Codex 教学会话。
- 以有出处的词表确定学习范围；每个词关联历史学习表现，系统能查询今日新学和到期复习项目。
- 允许从基础较弱的水平开始，使用中文讲解、英译中、带支持的简单中译英，逐步过渡到独立翻译、较长文本和自主输出。
- 阅读理解与英文输出可以难度不同，例如同时练习稍难的英译中和简单的中译英；不要求先具备自由英文写作能力。
- 希望使用有趣的真实材料，例如《哈利·波特》，但材料难度需要适合当前能力。
- 支持点击单词查看释义，逐步增加其他交互。
- 需要一份简洁的个人英语能力说明，供 AI 理解目标、已有基础和当前困难。
- 错误反馈不能无限扩展学习量：一个词拼错或一句话写错，不应自动变成一堂额外的语法课。
- 支持今天学习很多、明天只练一个词、停学后再回来；未完成目标不伪造失败，也不按昨日完成量强制增加今日任务。
- 默认 5 个词组成教学包，整组未完成不抹去其中已发生的学习；组大小不是最低学习量。
- 新词先由用户观看、回忆并自评；全组均标记记住后进入总拼写，未通过则回看再测。此阶段由平台执行，AI 在结束或暂停后分析数据，为后续教学提供依据；拼写未过关不进入该组正式句子练习。
- 语音本轮暂缓，只保留查询发音、生成语音和缓存音频的接口位置；没有语音服务时仍能完成核心学习。

每日时长、新词上限和默认口音可调整；具体题型、支持程度和讲解方式由 AI 根据学习历史安排。词典数据源组合在导入抽查后确定。

| 产品形态              | 独立网页应用                                            | 浏览器中完成聊天、阅读、点词、翻译和学习记录查看                  |

| Agent 接入层          | Node.js 管理子进程，以标准输入输出交换结构化协议消息    | 创建及恢复会话、发起教学轮次、消费事件、处理退出和重连            |
| 网页消息通道          | 首个 Demo 采用 HTTP 提交和 SSE 事件推送                 | 统一显示聊天、公开进度和业务结果，关联学习会话、题目及消息身份    |
| 教学 Skill 与业务工具 | Skill 定义教学要求，本地 stdio MCP 薄层包装平台业务接口 | 查询计划与历史、发布课程、读取作答、提交评价；业务规则由平台执行  |
| 文件                  | 服务端普通文件存储                                      | 导入材料、导出包以及后续音频缓存，数据库保存关联信息              |

首版使用单用户、单服务实例，学习服务与 Codex 运行时先在同一台电脑上运行。其他电脑或手机访问时，统一访问该服务，并增加登录与访问控制；运行 Codex 的主机必须可用。以后迁到服务器，需要同时安排 Agent 的运行位置和认证，不能只部署网页就假定能调用用户电脑上的 CLI。浏览器关闭不会删除已提交的学习记录；数据库和材料需要一致的备份与恢复方式。

PWA 安装入口可以后加，不等同于已经实现离线学习。首版不建设设备之间的离线同步，不引入 Electron 或第二套 Go 后端。学习规则独立于页面和模型调用，方便验证与维护；不提前开发 OmniFlow 适配层。

开发依赖锁定版本，复习评分映射、数据库结构和课程协议保留版本。算法用固定历史验证可重复结果，界面验证从开始学习到提交、恢复的完整流程。

## 后台 Codex Agent 与平台交互

### 用户只使用学习平台

开始学习、阅读讲解、提交翻译、请求提示和追问均在同一页面完成。平台显示准备课程、等待回答、正在批改或暂停待恢复等状态。首次使用所需的安装、登录或授权由设置流程处理；正常学习不要求用户在 Codex 与平台之间转述消息。

首版采用官方 [Codex App Server](https://learn.chatgpt.com/docs/app-server) 的会话与事件接口。Node.js 管理后台进程，通过标准输入输出的结构化协议通信；在同一平台学习会话下管理出题与陪伴角色各自的 Codex 线程。具体协议结构随选定 CLI 版本锁定，不通过解析终端自然语言判断业务结果。

Codex 程序运行在本机，模型通常仍通过配置的在线服务调用。平台表达登录、服务不可用和额度不足等状态；认证使用 Codex 支持的方式，不把教学 Skill 当作凭据载体，也不承诺订阅之外的通用 API 权限。

### 出题与陪伴两个角色

| 角色       | 职责                                                                                 | 调用时机                                       |
| ---------- | ------------------------------------------------------------------------------------ | ---------------------------------------------- |
| 出题 Agent | 读取算法选出的目标和完整历史，准备例句、练习、参考答案、提示与评价标准，调整教学方案 | 课程准备、明显的难度变化、评价争议和阶段分析   |
| 陪伴 Agent | 在后续句子练习中解释、提示、回答追问与给反馈，读取背词结果并生成阶段小结             | 背词结束或暂停后的分析、后续教学交互和组结束时 |
| 平台程序   | 选择新学与复习目标，控制预算，执行卡片流程与明确的拼写判定，保存事实并更新调度       | 每次相关交互发生时                             |

出题和复杂评价优先考虑能力更强的模型，陪伴优先响应速度；具体模型以账户实际可用列表和教学表现确定。两个角色可以先使用同一模型，角色分工不要求同时运行。前台默认只有陪伴 Agent 发言，出题 Agent 的备课与参考答案保留在后台。

Skill 分别说明角色、教学要求与工具用法。两个角色均可按需查询完整学习历史，长期记忆由平台保存，不依赖某个无限增长的聊天上下文。阶段小结帮助出题 Agent 快速了解情况，同时保留回查原始答案、提示和评价的入口。

新词卡片可以使用提前准备的 AI 例句，但开始看词后，观看、自评、总拼写与错误回看均由平台执行，不逐词调用 Agent，不实时插入 AI 提问、讲解或加测。阶段结束或暂停时，平台汇总真实记录供 AI 分析。AI 分析失败不影响已保存进度，也不阻断之后继续自助背词。

### 网页消息与业务动作

```text
学习网页 ⇄ Node.js 后端 ⇄ Codex App Server
                           ├─ 陪伴 Agent 会话
                           └─ 出题 Agent 会话
```

普通聊天不要求每个 Agent 再调用专用的“回复网页”工具。Node.js 接收 App Server 的 `item/agentMessage/delta` 等消息事件并推送到网页，用 `item/completed` 核对完整消息，用 `turn/completed` 表达该轮完成、中断或失败。两角色共用平台消息通道，接入层关联角色、学习会话和消息身份；传输能力来自 App Server，角色路由和展示规则由平台实现。[官方事件接口](https://learn.chatgpt.com/docs/app-server)

| 输出                       | 传递与展示方式                                                                  |
| -------------------------- | ------------------------------------------------------------------------------- |
| 面向用户的聊天解释与反馈   | Node.js 转发允许展示的 Agent 消息，聊天框流式显示并保存完整内容                 |
| 简短进度                   | 根据真实任务事件或 Agent 的对外进度说明显示“正在查看历史”“正在准备例句”等状态   |
| 题目、提示、评价与学习小结 | Agent 通过 MCP 业务工具提交结构化内容，平台校验、保存并返回回执，再更新相应界面 |

界面不依赖完整内部推理；后台备课答案、工具原始日志和角色之间的内部交流不直接广播给用户。进度必须对应真实工作，失败或中断时保留明确状态。若聊天反馈中声称已换题或已保存评价，平台仍以业务提交回执为准。

### 一轮教学的事件流程

1. 用户在平台开始或继续。Node.js 恢复平台学习会话，并按需要创建或恢复各角色的 Codex `threadId`；算法确定本次目标和预算。
2. 接入层加载对应教学 Skill，提供目标、题目版本和必要历史。出题 Agent 通过工具查询详情并准备材料；平台校验、保存后展示。
3. 准备完成后结束该 Agent 轮次。用户思考时由 Node.js 等待输入，不反复调用模型轮询答案。
4. 网页提交自评、答案或聊天，附带当前学习会话、题目及版本。平台先保存原始内容；自助背词和总拼写由程序处理，结束或暂停后再交给 AI 分析。后续教学中的普通追问默认交给陪伴 Agent，需要重备课或核对争议时再调用出题 Agent。
5. 对需要 AI 的事件，接入层把消息送入对应角色的线程。公开回复流式回到聊天框；显示提示、发布题目或提交评价走业务工具，平台记录实际生效结果。
6. AI 根据阶段记录分析后续应重点练习哪些目标及采用什么支持；陪伴 Agent 在句子练习中提供反馈。平台只对符合测量规则的证据更新 FSRS，并执行总拼写门槛和预算限制。
7. 组结束或暂停时保存阶段状态并生成小结，出题 Agent 可读取小结及其依据，安排后续教学；未提交成功的小结可重试，不影响已经保存的作答。

点词释义、切换已有卡片、拼写比较和显示进度由平台即时完成。Agent 可提前准备材料，阶段结束或暂停后再分析表现，用户不必每翻一张卡都等待模型。进入 AI 教学后，用户聊天时无需手动复制当前题目，也无需额外向 Codex 说明已完成哪一步。

### 状态归属与恢复

- 学习会话由平台拥有，各角色的 Codex `threadId` 是可恢复、可替换的教学上下文关联。更换任一角色线程后从平台重建必要上下文，学习历史不随线程消失。
- 事件、题目、作答和评价关联明确的学习会话及内容版本。同一事件重试不得重复发布题目或推进复习；迟到结果不能覆盖已经切换的当前题。
- 同一教学线程的处理由接入层排序；跨角色的题目修改和评价也要检查版本，确保同一次作答只结算一次，避免两个 Agent 重复评分或覆盖彼此的结果。
- 答案保存不依赖 Agent 在线。进程退出、网络中断或批改失败时保留待处理状态，恢复后继续；提交结果不明确时先查询已有业务结果。
- 网页重连从平台恢复已保存消息和业务状态；流式片段按消息身份合并，最终完整内容不重复追加，中断的半条回复不标成完成。
- Codex 一轮处理结束，只表示该轮 Agent 工作结束，不代表整个教学包完成或目标词已掌握。这些结论来自平台的业务状态与作答证据。

Skill 承载教学方法和工具用法，Codex 承担 Agent 运行，平台负责可靠执行算法与业务规则。首版复用官方运行时，不复制 OmniFlow 整套 Agent，也不以修改 Codex 源码或实现完整 A2A 协议为前提。Demo 先采用本地 stdio MCP 业务工具；以后若增加 CLI，也应调用同一套平台能力，不维护第二份学习规则。

## 词表与词典来源

词表确定学习范围与优先级，词典提供词义、音标和词形。二者分别管理，避免把“词典收录了这个词”误当成“现在应该学习这个词”。

| 资料             | 用途                                                                      | 当前取舍                               |
| ---------------- | ------------------------------------------------------------------------- | -------------------------------------- |
| Oxford 3000      | 3,000 个核心词，提供 A1–B2 分级，结合词频和学习相关性选词                 | 作为通用学习主线与分阶段参照           |
| Oxford 5000      | 包含 Oxford 3000，另增加约 2,000 个 B2–C1 词汇                            | 随阅读与表达需求逐步扩展               |
| NGSL 1.2         | 发布者列出 2,809 个通用核心词，提供频率排名、词形归并和简单英文释义等版本 | 检查高频基础缺口，辅助选择优先学习的词 |
| 用户实际阅读材料 | 文章、技术文档、书籍等反复出现的词与搭配                                  | 提供与个人兴趣、实际使用相关的扩展词汇 |

牛津词表可在官方页面浏览并下载供学习；整部词典的接口、离线数据及随应用分发的授权属于另外的产品与许可范围。首版不以获得整部牛津词典授权为前提，也不将网络上的非官方整理包标成牛津授权数据。[牛津词表说明](https://www.oxfordlearnersdictionaries.com/us/about/wordlists/oxford3000-5000)、[Oxford Dictionaries API 说明](https://developer.oxforddictionaries.com/faq)

NGSL 使用 CC BY-SA 4.0。官方还单列了 52 个没有频率排名的补充词，导入时需要按实际发布文件核对词目、词形和去重规则，不直接用页面总数代替导入结果。其“覆盖率”指相关语料中的词汇覆盖，不等于读懂同等比例的内容。[NGSL 官方来源](https://www.newgeneralservicelist.com/new-general-service-list)

同一个词可以同时属于多个词表，但只保留一份对应的学习历史。词表名称、版本、来源、等级和原始词条身份都应保留。掌握 Oxford 3000 或 5000 不直接等于达到对应 CEFR 整体语言水平。

词典底库候选如下，正式采用前做抽样核对：

- **Wiktionary 与 Kaikki**：提供可下载的结构化词性、义项、IPA、口音标签和词形数据。词条完整度不同，需要清洗；来源许可须随数据保留。[下载入口](https://kaikki.org/dictionary/rawdata.html)、[字段说明](https://github.com/tatuylonen/wiktextract#pronunciation)
- **ECDICT**：便于获得中文释义、音标及词形信息，可作中文辅助来源。音标以英音为主，不能假定具备完整的英美双音标；聚合来源与数据质量需要抽查。仓库中的音频字段也不代表已经有完整可用的发音库。[项目来源](https://github.com/skywind3000/ECDICT)
- **AI 讲解**：基于已找到的义项解释当前句子、生成练习和中文辅助说明。生成内容与词典原文分别保存，不自动提升为权威词条。

读音可以从词典的 IPA 及已有录音资源获取；覆盖率和录音使用条件需逐项核对。单词发音与整句 TTS 分开处理。每个拼写允许多个发音，并保留口音及词形条件，例如 read 的现在时和过去式不能压成一个读音。

### 点词释义与输入纠错

建立自己的本地词典数据层，导入有来源和许可记录的词条，关联词形、义项、词性与音标；AI 负责当前语境解释，不凭空生成整套权威词典。材料和用户提交的英文答案都可渲染为可点击文本，优先展示当前义项，其他义项按需展开。

输入时保留普通答题框，提交后显示可点击的反馈文本和错误标记。`borrowed` 应能关联 `borrow`；`borow` 可标出拼写问题并给出建议，原始输入仍保留；`lend` 本身拼写正确，是否用错由句意判断。合法词形不能因词典未直接收录而判错；查不到的词标为待查，不直接标红为错误。

测验中不在提交前持续纠正拼写，以免提示答案；若练习模式启用了此类帮助，明确记录支持条件。查阅目标词答案、首字母或相关释义时，按当前待测能力记录帮助，随后不能误算无提示成功。查阅其他词不会自动把它加入本次学习范围。

## 学习对象与 AI 的职责

长期计划不能只有一个单词数组。它还应说明学习目标、词表版本、每日负荷和当前阶段；今日计划则是从中选择出来的一次任务快照。

首版建议按“单词及当前目标义项”组织学习，保留对应的练习能力。比如 available 的一个常用义可以分别有理解、拼写和句中运用的记录。搭配作为该目标的教学材料出现，除非用户选择扩展，否则不自动变成新的待学项目。

| 部分       | 负责的事情                                                                     |
| ---------- | ------------------------------------------------------------------------------ |
| 学习算法   | 根据学习历史选取新学与复习目标，控制总量，计算下次复习时间                     |
| AI         | 查询全部学习数据，在目标范围内决定题型、难度、提示、材料与教学顺序，讲解并批改 |
| 确定性程序 | 校验课程范围和数据格式，保存答案、提示与评分，按固定规则更新调度并恢复现场     |
| 用户       | 选择目标与材料偏好，调整学习负荷，查看和纠正不合理评价                         |

AI 可以建议调整计划，但不能仅凭自己的总结把词标成已掌握，也不能在用户提交答案后决定是否顺便记账。作答保存是系统的固定动作。

界面可以提供“新词”和“学过的词”两个入口，后台仍区分未接触、已介绍待首次检验、正在巩固和已有复习状态。没通过的词也有后续安排，不等全部通过才进入调度候选；复习失败不清空原历史。首次有效回忆前使用待检验记录，之后按真实结果初始化或更新 FSRS，不因教学展示就伪造成功。

自助背词与总拼写按明确的平台流程执行。后续句子教学的支持程度、翻译方向和何时尝试更长文本，由 AI 根据阶段证据调整；目标范围、总量和数据提交规则由程序执行。AI 想增加计划外的新词或专项语法时，先作为建议，由用户选择后再变更计划。

## 一次学习如何进行

默认顺序是“本次预算内的复习 → 可选择开始新词 → 看词与自评 → 总拼写，未过则回看再测 → AI 分析 → 正式句子练习 → 小结”。新词上限、时长和难度可配置；设置 10 个新词时可以拆为两个 5 词组，不要求一次全部完成。

1. **开始或继续。** 用户在平台点击开始或输入“开始学英语”。Node.js 启动或恢复后台 Codex 会话；平台检查未完成会话或教学包，保留当前题和草稿，跨日或长时间中断后按当前状态和本次容量刷新未开始任务。
2. **选择并执行复习。** 算法按当前预算挑选到期目标，先尝试回忆，再做有限纠正与补测。待首次检验的新词恢复其原教学包；尚在看词阶段的不能绕过“全组自评记住”就单独考拼写。不要求清空全部积压才允许新学。
3. **选择开始新词。** 用户可结束，也可继续。算法在剩余预算和新词上限内确定目标；提供个人能力摘要与历史，出题 Agent 再组织材料。页面区分准备中、可练习与准备失败，先准备当前小组。
4. **自助记忆与总拼写。** 先观看词条和例句、回忆并标记是否记住；全组均自评记住后才进入总拼写，之前不出现拼写输入。总拼写未过则回看错词，再开始下一轮；平台处理和记账，不调用 AI 实时干预。
5. **分析并进入句子练习。** 总拼写过关后，AI 读取各词实际轮数、首次结果、错误和支持情况，决定后续英译中、带支持中译英等练习的重点与难度。暂停时也可分析已有数据，但不能因此绕过拼写门槛。句子练习中由陪伴 Agent 交流，用户可调整难度。
6. **提供有限反馈。** 说明目标词是否用对、哪里需要改正。补练与附带讲解计入预算；额外短语或语法进入可选主题，不自动扩展本次计划。
7. **记录并结束或暂停。** 每次作答先保存，再评分；有效证据更新对应复习状态。完成约定流程时标为组完成，提前结束或总拼写未过关时保留进行中或暂停；小结区分首次成功、回看后在后续轮次成功和待巩固项目。

聊天负责开始、解释与协商；点词、输入、提交、继续等高频交互由稳定的学习界面承担。AI 生成结构化课程内容，界面渲染受控组件，不执行模型生成的任意 HTML 或脚本。

### 复习先检查再有限补练

1. 给出明确中文义项，必要时加词性与短中文语境，隐藏英文答案及包含答案的材料。用户可提交、请求提示或表示暂时想不起来。
2. 保存首次结果。无提示正确记作该能力本次成功；有效测验中未能独立完成按规则记失败。题目歧义、合理同义表达或有争议的评价先核对，不直接惩罚目标词状态。
3. 对错误展示答案和简短差异，提供一次订正输入；用户仍可跳过或暂停。订正正确不覆盖首次失败，也不当作新的独立成功。
4. 隔开其他项目或留到后续合适时机，默认最多安排一次额外补测。再次隐藏答案后真实回忆的证据按学习或再学习规则处理；仍不会则留待巩固，不自动无限循环。

例如首测 a、b、c、d、e，b 和 d 错误，就针对两词纠正并在间隔后补测；d 仍不会也可以结束本次复习。模型按历史和实际时间计算下次日期，不固定采用答对翻倍、答错减半。拼写失败只说明本次词形回忆未通过，不能同时清除已有理解证据。

### 自助看词与自评

| 环节       | 页面展示                                   | 用户操作与记录                                                   |
| ---------- | ------------------------------------------ | ---------------------------------------------------------------- |
| 看词       | 单词、当前常用义、词性、音标、简单中英例句 | 阅读、点词或重新查看，记录实际接触                               |
| 回忆与自评 | 可隐藏中文或例句，只保留部分线索，按需揭晓 | 在心里回忆，标记“记住了”或“还没记住”；不要求输入单词、填空或翻译 |
| 准备总拼写 | 本组所有目标都已自评记住                   | 用户进入整组总拼写，自评本身不记为客观成功                       |

看词可以交错，例如认识 a、b、c 后再回看 a，随后加入 d、e；具体观看次数和隐藏哪些信息属于可调整的交互参数。总拼写之前全部是观看、回忆与自评，不插入拼写或其他答题检查。自评表示用户准备接受检查，不等于平台已确认掌握。AI 可提前准备例句，此时不分析每次点击、不实时出题或调整队列。

### 整组总拼写循环

```text
看词与自评 → 全组标记记住 → 整组总拼写
                              ├─ 过关 → AI 分析 → 正式句子练习
                              └─ 未过 → 回看错词并重新自评 → 下一轮总拼写
```

首版按每轮覆盖本组全部目标组织总拼写，顺序可打乱。题面给出明确中文义项和必要语境，隐藏英文词形、包含答案的例句及历史答案；每题保存一次真实提交，不能就地覆盖首次错误。整轮结束后集中反馈，未通过词回到观看与自评，再由用户开始下一轮。回看阶段不另加订正输入，新的拼写发生在下一轮总拼写中。

同一轮全部目标获得合格的无答案提示拼写成功，才算该组总拼写过关；自评“会了”、模型肯定或揭晓后抄写都不能替代。整轮可中途暂停、跨会话继续，不要求一次坐完；若有错误，新一轮保留旧轮全部记录并重新检查本组。已在前轮答对的词再次出现是新轮检查，不是历史被清空。

用户可以继续循环，也可以随时暂停；预算耗尽时提示暂停，主动继续需更新本次预算，不自动无休止加轮。每天只有一个词的容量也能推进观看或当前拼写轮次，下次恢复到未完成的位置。只有进入新一轮时重新覆盖全组，不因退出或跨日就重置当前轮。

刚揭晓答案后立即隐藏重输不算合格检查。通过改变顺序、穿插其他目标或稍后继续安排分隔后的回忆，并保存实际间隔和近期帮助；只有一个目标时也不通过添加计划外新词来凑间隔。总拼写是初学阶段的检查，过关不等于跨日记忆稳定。词级调度按有效作答及时处理，不等整组过关；重复进入总拼写也不能不分条件地累加独立成功。

### 阶段数据交给 AI 分析

平台在背词循环结束或暂停后汇总数据，AI 再据此调整下一阶段教法。每词保留观看和回看次数、自评变化、参加过的总拼写轮次、首次拼写结果、第一次无提示拼对发生在哪轮、各次原始错误、提示与揭晓、真实时间，以及当前是否仍未通过。

区分整组轮数和每词难点：全组到第 3 轮才过关，不代表每个词都需要 3 轮；某词第 1 轮就正确，应保留这个事实。尚未答题记未测，不能记失败；轮数不能脱离暂停、间隔和支持条件直接变成掌握分数。AI 可以据此给困难词安排更简单的句子、更多上下文或适量支持，但选词和预算仍由算法控制，阶段分析不直接改写 FSRS。

### 句子练习与可调整难度

总拼写过关后，出题 Agent 根据阶段数据选择练习：经过多轮才拼对的词可配简单英译中或更多语境，理解较好而输出较弱时用句式框架或填空，顺利时再用简单整句中译英。理解水平还需要实际证据，不能仅从自评或拼写推定。不要求每词做遍全部题型，也不强行把全组词塞进同一句。已有材料只有在义项、难度和支持条件适合时才复用。

用户可在设置或聊天中调整难度，先保留当前答案和草稿，再修改尚未开始部分；需要立即换当前题时保留旧题版本与退出记录。降低难度不抹去成绩，不自动扩成语法课。句中目标词的表现与冠词、时态等附带问题分开评价，题量和反馈始终受预算约束。

## 5 个词组成一个教学包

默认每组 5 个词，目标词义集合固定，材料与题目可以按历史调整并保留版本。组完成表示完成本轮学习流程，不表示所有词均已掌握。

如果学完前 3 个退出，该组仍未完成，但这 3 个词的作答立即保存。下次可从整组概览继续，重点处理需要回顾和未完成的词；不把词级进度清零。如果本次只愿意学 1 个，也可以继续推进，避免每次从第 1 词开始、后面永远轮不到。

允许主动整组重练。同一个答案请求重发只记一次，跨日真实的新回忆则正常记录。若先重新看过英文答案，再立即拼写，属于支持下练习；复习模式不在作答前自动展示待测答案。

## 如何判断掌握程度

### 重复次数不是固定毕业条件

“一个词见十次就成为长期记忆”可以保留为需要验证的直觉，不能写成算法规则。同一天看十遍、揭晓后抄写十遍、隔几天独立想起，代表不同的学习证据。重复接触有帮助，但效果受间隔、参与方式、已有水平和测试形式影响。[重复接触元分析](https://onlinelibrary.wiley.com/doi/10.1111/lang.12343)、[提取练习研究](https://pubmed.ncbi.nlm.nih.gov/18276894/)

系统应分别记录“接触过”和“尝试回忆”，重点观察间隔后的独立表现，而不是累计一个统一的见面次数。状态使用“理解较稳定、拼写待巩固、运用证据不足”等可更新描述，不设置永久毕业标记。

### 拼写是核心指标之一

用户重视拼写，因此首版应包含无答案提示的词形回忆，但拼写不能代表词汇能力的全部。至少分别观察以下三项：[接受性与产出性词汇研究](https://journals.sagepub.com/doi/10.1177/0033688209343854)

| 能力           | 可以使用的练习                       | 不能据此推断的事情                 |
| -------------- | ------------------------------------ | ---------------------------------- |
| 理解当前义项   | 在句子中选义、解释大意、判断用法     | 能认出答案不等于能主动写出         |
| 回忆并拼写词形 | 给出明确语境和义项，隐藏目标词后输入 | 拼写正确不等于掌握其他义项与搭配   |
| 受控运用       | 按给定句式造句、改写短句、完成短回答 | 一次成功不等于能在所有情境自由使用 |

听辨和口语没有测验时标为未评估。获取或播放了发音，不等于已经掌握发音。

点词查看答案、首字母提示、揭晓、重试都需要记录。揭晓后的输入属于练习，不算独立回忆成功；选择题与自由拼写也不能不加区分地更新同一个分数。拼写题要预先规定大小写、英美拼写、可接受词形及答案范围，避免把可接受表达判错。

开放句子的评分应分开判断目标词和附带问题。例如 available 用对了但冠词有误，可以记录目标词运用成功并给出简短冠词反馈，不因此判定该词遗忘。评分不确定时保留待确认状态或提供用户纠正入口，不能让模型自报的置信度直接成为掌握事实。

### 从翻译逐步走向表达

AI 分别观察英文理解和英文输出，可以同时安排稍难的英译中和简单的中译英。下表是可采用的教学方式，不是必须按序解锁的固定等级。

| 当前需求             | 可用练习                       | AI 应控制的难度                            |
| -------------------- | ------------------------------ | ------------------------------------------ |
| 还难以理解完整句子   | 中文解释、句中选义、短句英译中 | 少量陌生词、短句、可展开解释               |
| 能读懂一些，但写不出 | 词库填空、提供句式框架的中译英 | 常用词、明确场景、允许提示                 |
| 能完成简单英文表达   | 简单短句中译英、句式模仿       | 逐步减少提示，一次集中处理少量困难         |
| 理解强于输出         | 较难英译中搭配较易中译英       | 两个方向分别调整，不用阅读表现推定写作能力 |
| 短句较稳定           | 数句相连的翻译、带提纲的短段落 | 再增加长度、衔接或句法复杂度               |
| 能持续组织内容       | 较长翻译、摘要、短自由写作     | 逐步训练信息组织，区分翻译与自主写作证据   |

例如围绕 available，AI 可以先让用户理解 “Is this seat available?”，再解释“可使用”的意思；之后用句式支持练习一个简单中译英任务。刚看过英文答案后的回译属于教学练习，后续换语境、减少提示的表现才提供更强的独立运用证据。

译文按含义判断，接受自然的不同表达。英译中关注主要信息、否定、时间和人物关系，不追求中文文采；中译英分别反馈意思、目标词、语法和拼写，不与唯一参考答案逐字比较。

题目若未事先要求某个目标词，用户使用正确同义词可以算翻译成功，但该目标词的回忆仍可能没有测到。整个句子翻译错误不能让其中所有单词都被判遗忘。歧义题、错误参考答案或不确定评分暂不用于调度和能力结论。

AI 尝试更难任务时应参考跨日、不同句子中的表现；不因原题重复成功就认定能力提高。遇到困难时可以缩短句子、增加支持或换教法，每次优先解释一两个影响意思或目标词的关键问题，额外教学仍受当天负荷限制。

## 算法决定学什么与复习什么

算法的输出是一份带理由的学习目标清单，包括目标词义、此次是新学还是复习、需要观察的能力及剩余负荷。它不输出固定教案，也不强制使用哪种翻译方向。AI 自主选择能提供所需证据的练习；若实际只练了理解，没有测到计划中的拼写，就保留拼写未测状态，不因为完成了一道题而一并结清。

### 保存可追溯的历史

| 数据           | 定义与用途                                                       |
| -------------- | ---------------------------------------------------------------- |
| 接触次数       | 用户实际查看包含目标词义的学习材料；后台生成、组件重复渲染不计数 |
| 学习次数与日期 | 该目标实际参与过的不同学习会话；能区分同日密集接触和跨日学习     |
| 回忆尝试       | 测了什么、实际答案、首次结果、是否请求提示、是否揭晓和重试       |
| 历史教法       | 英译中、中译英或其他题型，材料、难度、提示方式及反馈             |
| 独立表现       | 无答案提示时理解、拼写或运用是否成功，是否存在评分歧义           |
| 记忆状态       | 对应能力的上次有效复习、下次复习时间和 FSRS 参数                 |

计数由事件汇总，保留原始时间线。AI 可以看到“出现过十次”，也能继续追查这十次是如何发生的。计数是输入之一，不能替代间隔和有效回忆结果。

### 目标选择与复习调度

1. 恢复已提交进度与当前草稿；跨日或久未学习时，按当前时间和本次预算重新生成尚未开始部分，保留计划版本与教学包身份。
2. 优先选择到期目标，按当前预计可提取性参考排序，并为久未安排的词保留轮转位置；限制总量，不一次塞入全部积压。具体规则见研究专题。
3. 还有预算时，从已选核心词表与当前学习范围中加入新目标，跳过已有充分熟练证据的部分。
4. 给每个目标附上入选理由和简要历史，保存计划版本，再交给 AI 组织教学。
5. 完成后根据有效证据计算下次复习。新目标需有初学练习和后续独立回忆机会；仅看过讲解，不推断已经学会。

首版采用 FSRS-6 计算间隔，选取新目标和控制每日量由普通业务规则完成。FSRS 利用复习历史估计难度、稳定性和可提取性，不负责选择教材或评作文。目标保持率用 0.90 起步，属于默认参数，不宣称是个人最优值。[FSRS 算法说明](https://open-spaced-repetition.github.io/ts-fsrs/guide/model/fsrs-6)

时间经过时，当前可提取性可以降低，之前熟练的词会再次到期；没有新作答时不重写难度与稳定性，也不新增失败记录。今天学 100 个、明天只练 1 个时，只更新实际完成的目标，其余保留真实历史和到期时间。长期容量不足可能导致更多遗忘，算法不能同时保证任意低投入和全部词汇的目标保持率。

理解和拼写维护各自的复习状态；句中运用、翻译和篇章表现先保存独立证据。首版有效回忆主要使用 Again（未能独立完成）和 Good（独立完成）的明确映射；Hard 与 Easy 不由 AI 凭感觉自动指定。采用实现提供的默认参数起步，个人化参数优化留待积累足够记录之后。

只有题目明确测量了目标能力、结果可归因、评分已确认时，才更新对应调度。正式回忆尝试中无法回答并请求揭晓，可以记录该次回忆失败；随后抄写正确是练习，不能覆盖原结果。教学阶段主动提供的提示不自动算失败。提示是否泄露答案按待测能力判断，例如拼写题预先给出的中文义项是题干条件，补充显示目标英文词形才是答案泄露。整句翻译总分、自然出现但未考查的词，以及立即重复同一答案，都不能直接批量推进词汇的复习状态。

本次预算约束新增目标、预计用时或题量、附带陌生词和补救次数。允许暂停、减少负荷和顺延；昨天的高学习量不自动提高今天预算。用户明确调整目标后更新未开始部分，AI 的临时教学兴趣不自动增加待学项目。

## AI 如何查询数据并组织学习

AI 能按需查询本人的全部学习数据，包括任意单词及义项的完整历史、原始答案、评分修正、过去课程、学习会话、材料来源和能力摘要。查询接口支持按词、时间、题型等过滤和分页，不把完整数据库一次放入上下文；摘要之外必须保留进一步追查原始记录的入口。

开始时向 AI 提供今日目标、个人上下文和关键历史摘要。AI 自行查询需要的详情，再返回结构化课程：目标身份、题型、材料、提示、评分要点、要观察的能力及可接受表达。程序校验目标属于当前计划、材料来源标注正确、题型受支持且负荷未超限，然后展示。

每次回答由程序先保存。需要语义判断时，AI 返回结构化评价与依据；程序保留评价版本，按固定规则更新符合条件的复习状态。AI 可以根据刚才的表现调整下一题教法和支持程度，但不能直接修改原始作答、累计次数、掌握状态或下次复习日期。

首字母、答案揭晓等帮助通过平台工具展示并记账。陪伴聊天若解释了正在测验的目标或泄露答案，也要关联当前测验，转为有支持的练习，必要时另安排独立检查；无法确认是否受帮助的结果暂不用于过关或调度。不能只依赖 Agent 在总结中自报是否给过提示。

阶段小结记录背词轮次与每词首次成功、错误和回看、复习中的订正与补测、提示依赖、句子表现、用户偏好变化及剩余任务，区分事实与教学建议，并关联原始记录。两个 Agent 可以据此协作，但普通闲聊、鼓励或小结中的“掌握了”不直接修改成绩。

查询范围完整不等于无限制读写。学习数据对 AI 可查询；数据库凭据和模型密钥不进入教学上下文。模型服务暂不可用时，保留当前答案和待评分状态，恢复后继续处理。

## 真实原文与材料难度

《哈利·波特》可以作为兴趣材料来源，但不能保证任意一组今日词汇都能在原文中找到合适、简短且易懂的片段。小说还有专名、魔法词和复杂叙述，不能仅因面向年轻读者就当作低难度材料。

建议支持用户导入有权使用的文本或电子书。先在本地检索和切分章节、段落，保存作品、版本、章节、段落标识及文本范围；给 AI 提供当前准备练习所需的片段。首版可以先从少量用户选定的短文开始，完整电子书解析与索引后置。

选段时综合检查目标词是否以目标义项出现、非目标陌生词数量、句法负担、长度、上下文完整度和个人兴趣。词汇覆盖率只能作筛选信号，不能单独保证材料难度适合。

每份材料明确区分三种来源：

- 原文摘录：能定位回实际导入的文本，引用必须与原文匹配。
- 基于原文的改写：保留出处关联，同时明确标注已改写。
- AI 自拟例句：明确标注生成，不伪称来自某本小说。

找不到合适原文时，使用简单自拟句或其他已选材料；不强行把所有目标词塞进一段不自然的文字。点击释义优先显示当前语境义，其他义项按需展开，减少额外认知负荷。

## 学习记录与个人能力上下文

个人能力文档适合作为 AI 的摘要入口，包含目标、感兴趣的材料、偏好口音、可用时间、已观察到的能力与困难。用户主动填写的目标和偏好由用户拥有；系统推导的能力描述应能追溯到学习证据，定期刷新并标注更新时间。

学习事实保存在结构化记录中，不依赖聊天窗口是否还保留历史。最少包含：

| 记录           | 主要内容                                                                                         |
| -------------- | ------------------------------------------------------------------------------------------------ |
| 学习范围       | 词表及版本、目标词或义项、来源身份、人工加入的项目                                               |
| 学习会话       | 日期、预算、今日队列、课程版本、各角色线程关联、当前阶段、总拼写轮次与逐词结果、完成或中断状态   |
| 看词与自评     | 观看和回看、隐藏与揭晓、自评变化、所在轮次与真实时间；不当作客观掌握成绩                         |
| 消息与处理事件 | 消息身份、角色与展示用途、关联题目版本、处理状态、完整回复与中断状态；支持重连恢复与防止重复处理 |
| 接触与作答     | 事件身份、目标义项、题型、实际答案、提示或揭晓、重试、时间、材料来源                             |
| 评分           | 规则版本、模型或人工判断、目标词表现、附带反馈、待确认或修正结果                                 |
| 调度状态       | 对应能力、调度算法与版本、下次复习时间及必要参数                                                 |
| 能力摘要       | 从记录归纳的理解、拼写、运用状态，以及用户确认的目标和偏好                                       |

一次作答的保存与对应调度更新应有可靠的提交边界，重试不得重复计次。若 AI 批改尚未完成，先保存待评分作答，再按固定版本更新评分和调度；不能因模型断线丢失答案。评分被修正后应支持重算相关状态。

聊天历史、生成材料、展示缓存和能力摘要都不能成为第二份学习事实来源。重要数据提供带版本的导出与恢复。首版单用户使用同一个服务和数据库，不维护多套设备本地副本；更换 AI 服务或迁移部署时，应能带走学习记录。

## 选择独立应用的依据

载体已确定为独立网页应用。以下保留 OmniFlow 对比的工程依据；插件接入不属于本项目的开发范围。

### 当前插件路径的两个主要缺口

**第一，现有插件工作区不具备本需求所需的学习状态提交接口。** M2 工作区绑定单个源文件，只开放当前文件读取、生命周期和命令准备；实际 broker 会拒绝工作区的通用 state/settings 请求。W3 文件产物链路只另存新文件，不覆盖源文件。因此，不能直接用这些能力完成每次作答后对同一学习档案的可靠更新。

**第二，已有聊天表单不等于完整学习界面已经能接入 Agent。** Agent 已有受控 choice/form，插件也能提供独立页面；但当前受控展示协议并不自动接受任意模型生成的交互组件。工作区领取课程、提交作答、按需请求 AI 反馈，仍需要明确的会话关联与受控提交桥。

这些是本需求与当前能力之间的差距，不是现有插件功能的故障。将学习档案存为文件本身没有问题，缺少的是确定性、可恢复的读改写契约，而不是一定要引入复杂数据库。

### 现有能力与可复用部分

| 能力                | 当前依据与边界                             | 对本方案的意义                                       |
| ------------------- | ------------------------------------------ | ---------------------------------------------------- |
| Agent 调用插件工具  | 已有安装、批准和工具执行链路               | 可承载选词计算、查询计划等工具                       |

独立应用的核心价值来自通用词表、个人复习计划和 AI 教学，个人资料库只是可选材料来源。程序提供稳定的学习会话和数据查询工具，AI 负责课程与互动即可；不需要为此复制完整的通用 Agent 平台。

## 通过材料与 Skill 扩展学习

长期方向是让用户在平台内把材料交给 Agent，利用已有数据和工具组织学习。例如词根 PDF 可整理出词根解释、关联词义和例句；常用表达材料可整理成句子或句式计划。Skill 指导提取、查询历史、组织草稿与教学，平台提供文件处理、来源引用、目标、计划、练习与记录能力。

后续 PDF 流程为：登记原文件与版本 → 提取文字或 OCR 并保留页码定位 → Agent 整理有出处的内容 → 查询并复用已有目标与学习历史 → 用户预览、选择范围并启用计划 → 算法按当前容量安排学习。重复导入不重复造词，新材料中的已有词义继续使用原有记忆记录。原文、基于材料整理和 AI 补充分开标记，识别不清的内容保持待核对。

词根作为构词概念，句子作为具体材料，句式作为可迁移的表达结构，均与单词义项区分。它们可先作为教学材料使用；若要独立考查与复习，需要定义对应目标、测量规则和证据，不能把阅读完成或整句翻译总分直接当成单词 Good。单词的总拼写门槛也不自动套到未来所有对象。

Demo 先保留稳定对象身份、来源引用、类型和规则版本、能力查询、课程提交与完整历史。PDF 上传、OCR、材料检索、计划草稿工具和词根或句式专用训练按后续版本增加。新增 Skill 可以组合平台已有能力；若需要新解析器、题型或界面，仍需实现相应平台功能。具体实施边界见 [Demo 扩展设计](../archive/demo-plan-2026-11-03.md)。

## 首版验证范围

先选 30～50 个词及其常用义、一小份有出处的材料，跑通“开始学习 → 预算内复习 → 算法选新词并准备材料 → 自助看词与自评 → 总拼写循环 → AI 分析 → 英译中或带支持的简单中译英 → 小结与下次恢复”。这个规模用于验证流程，不用于推算真实学习效果。

首版包含：一个学习范围、简短能力说明、可解释的复习队列、供 AI 查询的完整历史、英译中与简单中译英等有限题型、点词释义、提示记录、学习负荷上限、持久保存、导出恢复，以及语音接口的占位。长篇翻译和自由写作作为后续拓展，不成为开始学习的门槛。

首版暂缓：完整电子书管线、大型公开内容库、实时口语对话、自动发音评分、复杂跨设备同步、用户社区，以及无边界的语法课程生成。语音接口不可用时，明确显示当前仅支持文字和可用的音标资料。

先验证数据和状态，再打磨教学，再扩大材料范围：

1. 对候选词表与词典做一组代表性抽查，覆盖常见词、多义词、词形和多读音，确定来源与许可处理方式。
2. 用固定小词集完成学习事件、FSRS 调度和今日目标生成，验证保存、重试和恢复。
3. 完成自助看词、自评、总拼写循环及阶段统计；接通后台 Codex、出题与陪伴角色、教学 Skill 和业务工具，跑通网页流式聊天、公开进度、阶段后分析、句子教学、提示记账与结构化批改。
4. 接入真实短文，观察多次学习后 AI 是否能据历史调整教法，再逐步扩展文本长度和题型。

## 首轮验收场景

| 场景                               | 预期结果                                                            |
| ---------------------------------- | ------------------------------------------------------------------- |
| 同一天看同一词十次                 | 保留接触记录，不直接标为长期掌握                                    |

这些场景验证产品行为；学习效果还需要通过持续使用中的延迟回忆、提示依赖、阅读理解和实际输出表现观察，不能靠一次演示或词数增长宣称有效。
