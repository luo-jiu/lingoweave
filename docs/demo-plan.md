# LingoWeave 首个 Demo 实施方案

日期：2026 年 11 月 3 日

状态：Demo v0.1 实施计划。F0 基础工程已完成，当前实现 D0 的备课、数据保存与 Agent 接入。完整背词、复习和陪伴教学仍是后续目标；本轮实测结果见 [D0 验收记录](d0-acceptance.md)。

首个 Demo 要让一个基础较弱的用户在本机完成一次真实学习，并在次日继续复习：看词和自评、整组总拼写、AI 分析、简单句子练习、可靠保存和恢复。采用 30～50 个经过核对的词义，先验证完整体验，再扩展材料范围。

产品长期方向是可由 Agent 使用的语言学习平台。词汇是第一种学习对象，未来可从词根 PDF、常用表达和阅读材料组织计划。Skill 负责指导 Agent 使用平台能力；资料处理、题型、数据保存与复习规则由程序提供。

关联文档：[产品与学习规则](product.md)、[架构](architecture.md)、[开发指南](development.md)。本文收敛首个 Demo 的实现范围、接口与开发顺序。

## 当前 D0 范围

已实现 30 个来源可追溯的种子词义、SQLite 版本 1 迁移、网页备课工作区、真实 Codex 适配器、两个学习 MCP 工具、备课 Skill 与第一版测量分类器。当前只准备一个固定五词组；材料经整批校验与事务提交后展示，支持取消、重试和服务重启后读取。模型与协议验证结果在验收记录中单独列出。

D0 使用临时 Codex 线程；平台保存线程 ID 与任务记录，重试从已保存事实重新构建上下文。本文后续章节中两个角色的持续会话、全量历史工具、总拼写、FSRS 与导出恢复属于后续 Demo 目标。数据许可见 [词条来源](lexicon-sources.md)，证据分类和配置见 [测量规则](measurement-rules.md)。

## Demo 完成后能够做什么

用户打开网页，设置本次时间、新词上限和简单的难度偏好，先完成预算内的复习，再选择是否开始新词。默认每组 5 个词，可以只推进一个词，也可以暂停后继续。

新词材料准备好后，用户自主看词、隐藏或揭晓内容、标记是否记住。这个阶段不出现拼写、填空或翻译输入，AI 不实时干预。全组都标记记住后才进入总拼写；每轮覆盖整组，未过关则回看错词，再开始下一轮。当前轮全部目标取得合格的无答案提示拼写成功后，进入 AI 阶段分析和句子练习。

AI 读取每词的首次结果、第一次拼对所在轮次、错误与回看记录，再组织简单英译中或带支持的中译英。学习界面旁有聊天框，解释、提示、难度调整和反馈都在网页内完成。退出、网络中断或 Codex 进程退出，都不丢失已经提交的答案。

| 范围     | Demo 要完成的内容                                                         |
| -------- | ------------------------------------------------------------------------- |
| 使用方式 | 单用户、单台电脑、本地网页与 Node.js 服务，日常学习无须切换 Codex 窗口    |
| 学习资料 | 30～50 个词义、每词一个当前常用义、词性、可用音标、简单中英例句及来源     |
| 学习流程 | 预算内复习、自助看词与自评、整组总拼写循环、阶段后 AI 教学、暂停恢复      |
| 练习形式 | 中文提示拼写、简单英译中、句式框架或填空支持的中译英                      |
| AI 能力  | 真实 Codex 调用、出题与陪伴两个角色、历史查询、结构化课程和评价、网页聊天 |
| 数据能力 | 每词历史、总拼写轮次、FSRS、学习小结、可恢复的导出包                      |
| 点词交互 | 词条与用户提交的英文可点击查询；提交后标记已确认的错误，保留原文          |

PDF 上传与 OCR、词根专用教学、句式独立调度、完整词典、大型材料检索、音频服务、公开部署、多用户与跨设备同步留到后续版本。Demo 对未支持能力明确返回结果，不用示意按钮或固定回复冒充实现。

## 页面与交互

首版以一个学习工作区为中心，首页、历史和设置可以先用简单页面或抽屉。

| 页面或区域 | 必备内容                                                                     |
| ---------- | ---------------------------------------------------------------------------- |
| 今日首页   | 本次容量、到期复习数量、继续未完成组、开始复习、选择开始新词                 |
| 单词区     | 当前词义、词性、音标、例句、隐藏与揭晓、自评按钮；看词阶段没有答题框         |
| 总拼写区   | 中文题干、输入框、当前轮和进度；隐藏包含英文答案的卡片、历史与聊天内容       |
| 句子练习区 | 当前题、输入框、提交、提示、难度调整、反馈、下一题                           |
| 陪伴聊天区 | 公开回复流式展示、真实进度、停止与重试；在自助背词循环中不触发 Agent         |
| 历史与小结 | 每词首次结果、各轮错误、首次正确轮次、当前复习安排、组进度和阶段小结         |
| 设置与诊断 | Codex 可用状态、支持的登录入口、角色模型选择、新词量和时间偏好、数据导出恢复 |

总拼写每题先保存原始答案，整轮结束后集中反馈。不能用修改后的输入覆盖首次错误；回看阶段只有观看和自评，新的拼写发生在下一轮。已有词典可直接响应点词查询；未收录词显示待查，不一律标红。合法词形先关联词目，语义用错与拼写错误分别处理。

总拼写前的观看可以使用预先准备的 AI 例句。缺少必备材料时在准备阶段解决，不能进入看词阶段后又逐卡等待 AI 补充内容。

## 阶段与过关规则

平台保存教学包的 `stage`，暂停状态独立保存；拼写的 `round_id` 与一次打开网页的学习会话分开。

| 当前阶段   | 进入下一阶段的条件                             | 失败或中断如何处理                                     |
| ---------- | ---------------------------------------------- | ------------------------------------------------------ |
| 准备材料   | 当前组所需词条、题干、答案规则和例句已校验保存 | 保持准备失败或待准备，可重试，不假定用户已接触材料     |
| 看词与自评 | 本组全部目标都已自评记住，用户开始总拼写       | 恢复原自评与观看位置，自评不写 Good                    |
| 总拼写     | 当前轮全部目标有合格的无答案提示成功           | 未过则回看错词；暂停恢复当前轮未答位置，新轮才重测整组 |
| 阶段分析   | AI 读取真实统计并发布预算内的可用练习          | 保留已过关事实，允许稍后重试分析                       |
| 句子练习   | 本轮约定练习已完成，评价已处理或明确待核对     | 保留草稿、答案与待评分状态，继续或暂停                 |
| 小结       | 学习阶段状态已保存，小结可读取                 | 小结失败可以补写，不回滚已保存成绩                     |

总拼写过关是当前教学门槛，不代表长期掌握。看答案后立即重输不能过关；需要隐藏答案并安排分隔后的真实回忆。平台集中维护测量规则与版本，记录最近揭晓、实际间隔和是否有其他目标穿插；首批验收样例要覆盖立即照写、五词交错和单词组暂停后再测。具体短期间隔参数是产品配置，不宣称为科学最优值。

D0 已产出 [第一版测量规则](measurement-rules.md)及分类器回归样例，区分未测量、受支持、过早回忆、独立成功/失败与待核对；当前备课流程不产生测量成绩，D1 按该规则实现。阶段过关与 FSRS 的证据资格判定共用同一分类结果，不能由两处分别猜测是否独立。规则后续调整保留版本与原始事件，避免改配置后静默改变旧成绩。

未作答、待核对或有答案帮助的结果都不能充当该轮独立成功。退出或跨日不清空当前轮；重复提交同一个答案不产生新尝试。一个词在第 1 轮就正确，即使全组第 3 轮才过关，也要保留该词的首次正确轮次。

复习采用另一条流程：先无答案提示首测，错误后可订正一次，之后默认最多一次额外间隔补测。订正不覆盖失败，补测仍不会可结束。新词总拼写循环由用户继续或暂停，预算耗尽时提醒暂停，主动继续才增加本次预算。

## 技术栈与模块

| 层             | Demo 选择                                                        |
| -------------- | ---------------------------------------------------------------- |
| 前端           | React、TypeScript、Vite                                          |
| 服务           | Node.js、TypeScript、Fastify，首版仅监听本机回环地址             |
| 保存           | SQLite 与普通文件目录；数据库迁移、数据格式和课程格式均有版本    |
| 网页通信       | HTTP 提交命令，SSE 推送消息与状态；先实现一条通道                |
| Agent 运行时   | Node.js 管理 Codex App Server，通过 stdio 协议创建和续接角色会话 |
| Agent 业务工具 | 本地 stdio MCP 薄层，调用同一套学习业务接口                      |
| 教学说明       | 出题与陪伴两个 Skill，描述流程、证据要求和工具用法               |
| 调度           | FSRS-6，锁定 `ts-fsrs@5.4.2`；目标保持率从 0.90 起步             |

基础工程固定 Node.js 22.22.0 与 pnpm 11.25.0；D0 按实际 Codex CLI 0.153.4 的协议验证，后续升级需要重新联调。模型从运行时返回的可用列表选择；两个教学角色后续可以使用同一个模型，不以固定型号或费用假设作为前提。

建议代码按以下职责组织，名称为规划示例，不表示文件已经创建：

```text
apps/web                 页面、卡片、练习、聊天和 SSE 恢复
apps/server              HTTP、持久化、任务恢复、Codex 生命周期
packages/domain          状态转换、词级证据、预算和业务校验
packages/scheduler       FSRS 适配与今日目标选择
packages/contracts       网页、业务工具和课程的共享结构
packages/agent-bridge    App Server 协议与公开消息映射
packages/learning-mcp    学习工具到服务端业务命令的薄层
skills/lesson-author     出题角色说明与资源
skills/study-companion  陪伴角色说明与资源
data                    数据库、材料文件、导出包；与源代码分开管理
```

网页与 MCP 不能各自维护一套评分或调度逻辑，均调用 `domain` 的业务命令。MCP 层不直接修改数据库；Skill 也不能绕过程序把词标为已掌握。首版任务恢复使用 SQLite 中的待处理事件和 Agent 任务记录即可。

## 网页和 Codex 怎样连接

```text
网页 ──HTTP──> Node.js ──stdio──> Codex App Server
网页 <──SSE── Node.js <──事件─── 出题或陪伴会话
                  ↑                  │
                  └──业务接口──学习 MCP 工具
```

App Server 提供线程、轮次和消息事件；Codex 可连接本地 stdio MCP 工具。Demo 使用这两种接口分别承担会话通信和学习动作，接入实现以锁定版本的协议为准。[App Server 官方文档](https://learn.chatgpt.com/docs/app-server)、[MCP 官方文档](https://learn.chatgpt.com/docs/extend/mcp)

Node.js 为平台学习会话保存出题与陪伴线程关联。普通追问默认发给陪伴角色；课程准备和阶段分析发给出题角色。两者按需运行，不让用户选择收件人。Agent 当前轮次结束后等待平台的新事件，用户思考时不调用模型轮询。

同一角色线程串行启动轮次，新聊天先保存并排队；停止操作中断当前轮，保留已经确认的业务结果，迟到输出仍按题目版本处理。重试前先查询已有回执，避免重复操作。登录失效或运行时需要用户处理授权时，在设置与当前任务中显示可操作的等待状态，不能静默挂起。

面向用户的回复接收 App Server 文本事件后流式显示，不额外要求 Agent 调用“发送聊天”工具。题目、提示、评价和小结通过业务工具提交后生效。公开进度只需“准备例句”“读取学习记录”“检查答案”等简短真实状态；后台参考答案和内部日志不推送到学生界面。

首版网页接口按以下职责提供，路径名称可在编码时统一：

| 接口职责               | 最小行为                                                                    |
| ---------------------- | --------------------------------------------------------------------------- |
| 获取今日计划与会话快照 | 返回预算、候选目标、阶段、当前轮、未完成位置、版本与一致的 `last_event_seq` |
| 提交学习动作           | 自评、答案、开始新轮、暂停或继续；带请求身份和预期版本，返回保存回执        |
| 提交聊天               | 先保存消息，绑定当前题目和版本，再创建对应 Agent 任务                       |
| 订阅事件               | SSE 推送消息片段、业务状态和任务结果，带事件序号                            |
| 查询词条和历史         | 按词形查词；按目标、时间和能力分页追查原始记录                              |

快照返回与其状态一致的 `last_event_seq`，客户端从该序号之后接续 SSE，服务端补发期间已经产生的事件；游标失效时重新获取快照。已处理事件不重复显示或结算。最终完整消息更新原消息草稿，不在后面再追加一份。中断消息有明确状态。题目更新、答案保存、业务事件与待处理任务在可靠提交后才确认成功；任务重试先检查已有业务回执，避免 Agent 重复发布或重复评分。

## 最小学习工具

以下为完整 Demo 计划的业务能力。D0 已实现 `learning_get_context` 与 `learning_publish_materials` 的固定五词组备课子集，其余能力及表中的完整学习契约仍待实现。所有写入须返回对象身份、版本与处理状态，校验当前会话、计划范围、目标、题目版本和重复请求。

| 能力                         | 用途                                     | 首版边界                                           |
| ---------------------------- | ---------------------------------------- | -------------------------------------------------- |
| `learning_get_capabilities`  | 查询支持的对象、题型、测量规则和工具版本 | 返回真实能力；不支持的类型明确拒绝                 |
| `learning_get_context`       | 读取当前计划、目标、预算、阶段和关键统计 | 包含真实阶段门槛，Agent 不能自行跳过               |
| `learning_query_history`     | 查询每词原始作答、自评、回看、提示和评分 | 支持分页与事件引用，不只返回摘要                   |
| `learning_lookup_lexicon`    | 查词形、义项、词性和可用音标             | 返回来源，缺失字段明确为空                         |
| `learning_publish_materials` | 保存当前组的例句与卡片材料               | 限准备阶段；区分原文和 AI 自拟内容                 |
| `learning_publish_exercises` | 发布句子练习、私有参考答案和评分要点     | 需要总拼写过关，题量和目标受预算限制               |
| `learning_show_hint`         | 展示分级提示或揭晓                       | 记录实际展示内容、目标与测量影响                   |
| `learning_submit_assessment` | 提交语义评价、依据和待核对状态           | 程序决定采用结果及是否更新调度，同一作答只结算一次 |
| `learning_save_summary`      | 保存阶段小结和原始证据引用               | 不直接修改成绩、过关或到期时间                     |

确定性拼写比较由程序完成。语义评价分别判断目标词、主要意思和附带语法；正确同义表达可能是翻译成功但目标词未测到。陪伴聊天如果给出了当前答案，也要关联帮助记录；帮助情况不清楚时不记独立成功。评价被纠正时保留旧版本，并按实际作答时间重算受影响的状态。

## 数据与调度

数据库可以按以下业务对象组织。表结构可在编码时细化，但身份和状态不能只留在模型聊天中。

| 对象              | 必须保存的事实                                                             |
| ----------------- | -------------------------------------------------------------------------- |
| 材料与来源        | 数据集或文件身份、版本、引用位置、来源链接与许可信息；生成内容另标生成来源 |
| 学习对象          | 稳定 ID、类型、词目及义项身份、词形关系和材料引用；Demo 实际支持词义对象   |
| 目标与计划        | 对象、待观察能力、规则版本、学习范围、计划版本及预算                       |
| 教学包与轮次      | 固定目标集合、阶段、暂停状态、总拼写轮号、题目版本和当前进度               |
| 学习事件与作答    | 观看、自评、揭晓、原始答案、重试关系、实际时间、支持条件和请求身份         |
| 评价与记忆状态    | 评价版本、采用结果、FSRS 参数、真实 due、更新所依据的原始作答              |
| 消息与 Agent 任务 | 公开或内部用途、角色线程关联、事件序号、状态、重试和业务回执               |
| 阶段摘要          | 每词首次正确轮次、各轮错误、提示依赖、教学建议与原始记录引用               |

单词身份以词目和义项为基础，同一词来自多个计划或材料时增加关联，复用原有能力记录。不能仅按中文释义相同合并，也不能为每个新计划复制一份记忆历史。

同步拼写判定时，原始作答、采用结果和调度变更在事务中保持一致；AI 批改先保存待评分答案，之后再事务结算。界面成功回执依据数据库提交，而不是 Agent 自然语言里的“保存好了”。

调度遵守 [产品规则](product.md)：理解和拼写分别记录；未检验的新词不伪造 FSRS 参数；时间经过只改变当前可提取性估计；今天学 100 个、明天只学 1 个时只更新实际发生的作答，其余保留真实到期时间。初次检验提醒恢复原组，不绕过全组自评就插入拼写。

每日预算按词目去重，并同时约束题量、时间和复习补测。到期目标优先，默认每第 5 个已服务位置照顾等待最久的候选；该规则沿用现有设计，属于待使用验证的产品策略。总拼写中的额外轮次记录为教学尝试，不能把每轮短期正确不分条件地转换为长期熟练。

## 首批词条与材料怎么准备

首批从 NGSL 1.2 或已选核心词表中选取 30～50 个常用词义，优先选择中文提示清楚、词形规则明确的样本。核心词表来源继续保留版本和身份；Demo 不以获得整部商业词典的授权为前提。

以可使用的词典数据为基础整理小型种子包，逐条核对中文义、词性、音标及允许词形；已有来源不足的字段保持缺失，不能让 AI 编造后当作权威数据。词典候选与来源约定见 [产品文档](product.md)。首批不下载整部词典作为开工前提，按最终选用来源保留相应署名和使用条件。

种子包包含稳定目标 ID、词条来源、当前义项、展示信息、拼写题干、可接受词形和少量经核对的简单例句。例句可由 AI 准备，但必须标为自拟，并尽量使用已知词；同义词歧义、英美拼写、大小写与词形政策在进入测验前确定。

开发夹具可以包含固定例句和模拟历史，明确标为测试数据，不写入真实用户成绩。最终验收必须有实际 Codex 备课、查询、聊天与结构化写入；预录回复只用于开发过程，不能作为已接通 Agent 的证据。

## 开发顺序与每步交付

| 阶段              | 要做的工作                                                                                                                           | 该阶段完成的证据                                                             |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------- |
| F0 基础工程       | 建立 pnpm workspace、React 网页、Fastify 服务、共享契约及工程检查                                                                    | 已完成；通过真实健康检查、构建与启动验证                                     |
| D0 接入与资料准备 | 建立最小工程和数据迁移；锁定运行时与第一版测量规则；整理首批词条；最小网页通过 Node 调用真实 Codex，并使用一个读工具和一个业务写工具 | 当前实现；真实备课与保存恢复结果见 D0 验收记录；包含来源种子包与测量分类样例 |
| D1 自助背词       | 看词、自评、整组总拼写、回看、新轮、暂停恢复和原始事件保存                                                                           | 看词无输入测验，循环中无模型调用；当前轮恢复和首次正确轮次可核对             |
| D2 动态复习       | 接入实际 FSRS、预算、待首次检验、复习纠错、跨日恢复和导出恢复                                                                        | 固定历史可重复；容量骤降、停学、重复提交不会伪造结果或丢历史                 |
| D3 AI 教学        | 出题和陪伴 Skill、阶段分析、句子课程、网页追问、提示、结构化评价与小结                                                               | 真实 Agent 根据不同错误记录给出相应教学；工具回执与页面状态一致              |
| D4 连续使用验收   | 从新用户开始完成一组，暂停重启，次日继续；处理中断、重连和重复请求                                                                   | 全部核心验收通过，能够导出并恢复这一段学习记录                               |

可以并行推进前端页面和来源核对；阶段转换、学习事实和评分契约先统一。D0 尽早暴露 Codex 登录、版本、工具配置和流式通信问题，避免界面完成后才发现接入不通。

测试集中验证学习状态、真实时间、评分边界和恢复；端到端覆盖一组完整流程。跨日逻辑可用测试时钟验证，但仍补一次实际跨日使用记录。构建、类型检查和必要测试通过后再交付 Demo；基础工程检查不替代本文学习流程与 Agent 的真实验收。

## Demo 验收场景

| 场景                         | 必须观察到的结果                                    |
| ---------------------------- | --------------------------------------------------- |
| 全组点击记住                 | 进入总拼写条件满足，尚不算客观掌握或完成教学        |
| 看词或回看错词               | 没有拼写、填空、翻译输入，也没有 AI 实时干预        |
| 首轮某词错误，第三轮全组通过 | 首次错误保留；其他词的首次正确轮次不被改成第三轮    |
| 总拼写做到第三词退出         | 重新打开恢复第四词；开始新轮才重新覆盖全组          |
| 揭晓后立即照写或请求答案提示 | 不充当独立成功或过关条件                            |
| 今天只愿练一个词             | 在当前阶段推进一个目标后可暂停，其他目标不伪造失败  |
| 组还没完成但已发生有效回忆   | 词级记录与调度立即保存，不等整组通过                |
| 熟练词停学后回来             | 根据真实间隔再安排，不清空历史或制造缺席失败        |
| 提交后 Node 或 Codex 退出    | 已确认保存的答案仍在，待处理评价可以续接            |
| 重发提交或两个角色重复评价   | 同一次作答只结算一次；旧版本结果不覆盖新题          |
| SSE 断线后重连               | 恢复消息和业务状态，最终回复不重复追加              |
| 后台备课有参考答案           | 学生页面只收到允许展示的内容                        |
| 用户在网页问当前句子的意思   | 陪伴 Agent 收到正确题目上下文，真实回复回到同一页面 |
| 译文合理但不同于参考答案     | 按意义评价，目标词未测到时不自动判熟练              |
| 词典没有该拼写或存在合法词形 | 正确关联或待查，不把所有未知词标成错误              |
| AI 不在线                    | 已有材料的自助流程可继续，未准备课程保持待处理      |
| 导出到新的本地数据目录后恢复 | 来源、轮次、答案、评分版本、调度和必要材料可核对    |

交付包含可启动的本地应用、来源明确的种子包、设置与运行说明、必要的数据迁移和导出恢复方式，以及上述验收记录。模型调用次数、实际等待时间和失败原因需要可观察，暂不预设未经测量的速度承诺。

## 未来如何从词根 PDF 组织学习

用户把 PDF 交给平台内的 Agent，表达想学的范围和预算。未来材料 Skill 可以指导 Agent 完成以下过程：

1. 平台接收并登记原文件、内容哈希和版本，提取可读文字；扫描页使用 OCR，保留实际 PDF 页序、书面页码、提取器或 OCR 版本与可定位片段。同一文件重新提取保留对应片段版本。低质量识别标为待核对，不用模型猜测补齐后冒充原文。
2. Agent 检索相关片段，整理词根、词缀、解释、例词与例句，分别标记原文摘录、基于原文整理和 AI 补充。原文件内容作为学习资料处理，不改变平台工具规则。
3. Agent 查询已有词条和学习历史，复用相同词目、义项与能力的记录。重复导入同一文件不重复建目标，新版本保留旧来源与已发生的学习。
4. Agent 生成可预览的计划草稿，列出范围、目标、来源和预计负荷。用户选择范围并启用计划；算法依据当下容量安排实际新学和复习，不把整本 PDF 一次塞进今日任务。
5. 平台按已支持的对象和题型执行学习，复用卡片、作答、历史、Agent 教学和小结能力。需要新测量规则的内容先补平台能力，再启用对应训练。

例如一份讲构词法的材料，可以先形成“理解某个词根解释＋学习若干关联词义”的计划。已有单词仍沿用原学习历史；词根说明先作为材料和关系保存。拼写相似不自动构成词源关系，原文断言、可靠词典支持与 AI 推测分别记录。

| 对象            | 应如何建模                     | 不能直接等同的内容                   |
| --------------- | ------------------------------ | ------------------------------------ |
| 原始 PDF 与片段 | 有版本、可定位的学习材料       | 不等于学习目标已经完成               |
| 单词义项        | 可关联理解和拼写目标的稳定对象 | 不能因换一本材料就成为全新词         |
| 词根或词缀      | 构词概念及来源明确的关联       | 不能直接当成单词拼写卡或读完即 Good  |
| 具体句子        | 原文或生成材料中的一次表达     | 不等于抽象句式已经掌握               |
| 常用表达或句式  | 可在不同场景练习的语言对象     | 不能用一个整句翻译分数结清所有关联词 |

常用句子未来可以沿用“材料 → 目标 → 计划 → 练习 → 证据 → 复习”的流程，但需分别定义理解、表达和迁移使用的测量规则。词根或句式的复习状态不能直接复制单词参数，单词总拼写门槛也不强制套用到所有未来对象。

## 为扩展保留什么

Skill 提供可复用的工作流程，MCP 提供实时数据与受控动作；这是两者的职责边界。[OpenAI 官方 Skills 说明](https://developers.openai.com/plugins/concepts/skills)

Demo 需要实现稳定对象身份、来源引用、内容与计划版本、能力查询、通用课程提交和完整历史查询。课程结构保留目标类型与测量规则身份，首版实际支持词义对象；未知类型明确返回不支持，不能默默转成拼写题。

后续材料扩展再增加文件登记、提取任务、片段检索、计划草稿与启用等工具。初次 PDF 导入可以先只生成已有词义类型的计划，从而复用背词流程；词根和句式专用目标、题型与调度随后增加。已有 Skill 能组合新工具，但单独新增一份 Skill 文本不会自动获得上传、OCR、词源核对或新界面能力。

新增能力的最小交付应同时包含：平台可执行动作、类型与规则版本、Skill 用法、来源和历史处理，以及一条实际学习验收。这样每次扩展都能复用当前事实记录，不需要重建整套 Agent。
