## Demo 完成后能够做什么

用户在 mini 设置每日新词目标、每组数量和难度偏好，先完成到期与积压复习，再开始新词。复习不占新词目标；50 词/组 20 是分为 20、20、10 的示例，不自动修改真实设置。时间不足可以暂停，原始进度和到期任务保留。

新词按每词独立的三个阶段在滑动窗口中交错。默认窗口 5，处理至少 3 个其他不同词后允许再现；回答不会退回完整词卡，仍留窗口，三个阶段全过才腾位并优先补新。达到本组数量后进入拼写、翻译，窗口尾部最多 4 词保留到下一组或次日。每日完成只统计走完三阶段、结束拼写并提交翻译确认下一词的目标。

阶段 1/2 的初选只展开完整词卡核对并自动读词、停半秒、读例句；「记错了」保存改判，「下一个」才推进阶段或退回 0、换词和补位。移除三阶段卡的通用撤销和保存成功提示，保留保存失败反馈与核对态恢复。该交互用于新词和复习三轮未清晰后的重学，复习窗口只能补待重学复习词，普通复习判断仍保持原流程。

复习判断清晰则退出，模糊/遗忘下一轮重新遮挡；三轮仍不清晰转三阶段重学，再拼写，不增加翻译。两类拼写统一为最多三轮首答，下一轮只练上一轮首答错误的词；前两轮错误需订正，第三轮错误展示答案后允许继续。正确或订正成功显示绿色，下一次回车前进。

翻译原答案先保存，用户可查看反馈或主动讨论，点击下一词直接进入下一题。后台逐题持久任务可合并小批处理；完成计数不等评分，处理状态只在首页展示。AI 综合学习历史与原译文给出结构化评价，由程序校验采用，原答、帮助、评价理由和排期变更可追溯。断线、退出、半组暂停不丢失已提交答案或待评分任务。

## 页面与交互

首页保留概览与备课入口，点击「开始学习」进入独立学习页。学习页顶部用圆点和短标签表示本次实际阶段：有复习时为「复习 → 学习 → 句子练习 → 小结」，无复习时「学习」就是第一点。回忆词义、拼写和错词巩固是复习内部步骤，不增加顶层圆点。

学习页随视口变化，顶部阶段和底部操作保持可见，卡片内容与右侧细长聊天区各自滚动，避免整页滚动让主要操作离开视野；窄屏调整布局。原型的具体行为与范围见[学习工作区说明](study-workspace-prototype.md)。

显示设置提供持久化的简约模式，隐藏学习标题与说明、装饰性小标题和聊天介绍等辅助引导；真实错误、暂停、轮次、进度、演示未保存与 AI 未连接提示保留。关闭后恢复，不重置学习或草稿。焦点样式统一紧凑单圈，组合控件由外壳显示。

| 页面或区域 | 必备内容                                                                   |
| ---------- | -------------------------------------------------------------------------- |
| 今日首页   | 新词目标和完成数、到期/积压量、保留进度、后台评价处理中/待重试             |
| 单词区     | 复习先仅英文并自评后揭晓；新词展示材料与自评，标记后可主动开启单卡默写     |
| 总拼写区   | 整批中文题干、输入框、不会选项、当前轮和进度；提交前隐藏英文答案与相关历史 |
| 句子练习区 | 当前题、原答、提示、反馈/讨论、下一词；不显示后台评分进度，不等待评分      |
| 陪伴聊天区 | 公开回复流式展示、真实进度、停止与重试；在自助背词循环中不触发 Agent       |
| 历史与小结 | 每词首次结果、各轮错误、首次正确轮次、当前复习安排、组进度和阶段小结       |
| 设置与诊断 | Codex 可用状态、登录入口、模型选择、词库和时间偏好，导出恢复暂缓           |

总拼写每题保存原始答案并给出当前结果，正确后绿色停留，下一次回车前进。不能用修改后的输入覆盖首次错误；回看阶段默认观看和自评，主动单卡默写只作额外支持练习，后续正式错词拼写使用下一轮身份。已有词典可直接响应点词查询；未收录词显示待查，不一律标红。合法词形先关联词目，语义用错与拼写错误分别处理。

材料准备与学习目标分开：按剩余新词目标加窗口大小维护候选池，复用已有例句与音频并滚动补缺。当前所需材料未齐时展示真实准备状态；不能为等待整个候选池阻塞已就绪的当前学习，也不能把准备完成记成学习完成。

## 阶段与过关规则

完整状态、调度示例和边界以 [学习流程与评价规则](learning-flow-rules.md) 为准。阶段推进、每词记忆进度、拼写轮次、完成计数和后台评价是不同状态，由服务端保存；打开应用不创建新的学习事实。

| 当前阶段 | 进入下一阶段的条件                                      | 失败或中断如何处理                                       |
| -------- | ------------------------------------------------------- | -------------------------------------------------------- |
| 到期复习 | 当日到期及积压词完成判断/必要重学与拼写，才开放新词     | 保留尚未处理任务；三轮判断未清晰转三阶段重学，无翻译     |
| 准备材料 | 当前所需词条与例句可用，音频按既有准备/文字优先规则处理 | 只补缺项，预取不计入窗或完成，不等待整个候选池           |
| 窗口记忆 | 初选展开核对后确认前进，本组足量词分别通过三个阶段      | 记错待确认退0；核对态可恢复，组满暂停，尾部跨组/跨日保留 |
| 总拼写   | 每词首答成功，或第三轮首答失败后确认继续                | 后续轮仅上一轮首答错词；保存订正和绿色确认状态           |
| 新词翻译 | 原译文及下一词确认可靠保存，进入下一题或下一组          | 允许停留讨论，未提交不制造完成，评分等待不阻塞           |
| 后台评价 | 固定证据输入得到校验结果，并保存采用决定及调度记录      | 首页显示处理中/待重试；逐题恢复，迟到结果按事件时间重算  |
| 小结     | 读取已保存事实，可标明评价仍在处理                      | 小结失败不回滚学习完成，也不伪造最终评价                 |

新词完成后次日本地自然日必复习，未完成新词仅保留进行中状态。拼写三轮失败结束本次拼写，不等于已掌握；新词仍进入翻译，复习仍可结束本次，失败证据用于更近排期。FSRS 与新综合评价的适配不把自评、看答案后的订正或聊天讨论伪装成独立成功。

D0 的 [第一版测量规则](measurement-rules.md) 与现有分类器保留版本，已用于 mini 显式独立拼写检验。新评价要同时保留客观独立证据、自评与受支持练习的区别；不能为推进新流程静默修改旧分类结果。当前锁定的 FSRS-6 / `ts-fsrs@5.4.2` 是实现基线，综合评级、次日首复习与错峰已有新增隔离测试，长期效果继续评估。

迁移前明确旧组政策和切换点，保留每词阶段、各轮首答、订正、帮助、草稿、题目与实际时间。旧事件按原规则解释，不能重放成新规则的三轮上限或阶段退0。重复确认和重试只产生一次完成或评价采用。

建议代码按以下职责组织，名称为规划示例，不表示文件已经创建：

```text
apps/web                 页面、卡片、练习、聊天和 SSE 恢复
apps/server              HTTP、持久化、任务恢复、Codex 生命周期
packages/domain          状态转换、词级证据、预算和业务校验
packages/scheduler       FSRS 适配与今日目标选择
packages/contracts       网页、业务工具和课程的共享结构
packages/agent-bridge    App Server 协议与公开消息映射
packages/learning-mcp    学习工具到服务端业务命令的薄层
skills/lesson-author     出题角色说明与资源
skills/study-companion  陪伴角色说明与资源
data                    数据库、材料文件、导出包；与源代码分开管理
```

网页与 MCP 不能各自维护一套评分或调度逻辑，均调用 `domain` 的业务命令。MCP 层不直接修改数据库；Skill 也不能绕过程序把词标为已掌握。首版任务恢复使用 SQLite 中的待处理事件和 Agent 任务记录即可。

## 网页和 Codex 怎样连接

```text
网页 ──HTTP──> Node.js ──stdio──> Codex App Server
网页 <──SSE── Node.js <──事件─── 出题或陪伴会话
                  ↑                  │
                  └──业务接口──学习 MCP 工具
```

App Server 提供线程、轮次和消息事件；Codex 可连接本地 stdio MCP 工具。Demo 使用这两种接口分别承担会话通信和学习动作，接入实现以锁定版本的协议为准。[App Server 官方文档](https://learn.chatgpt.com/docs/app-server)、[MCP 官方文档](https://learn.chatgpt.com/docs/extend/mcp)

Node.js 保存学习会话、Agent 任务和需要续接的聊天关联。普通追问使用学习顾问 Skill，课程准备使用备课 Skill，提交后的反馈使用写作反馈 Skill；共用一个运行时，用户不必选择收件人。任务结束后等待平台的新事件，用户思考时不调用模型轮询。持久上下文来自平台事实、有限近期聊天和后续可追溯摘要，不以永远存活的模型线程作为保存前提；当前 mini 已保存聊天和明确偏好，自动摘要仍未实现。

同一聊天线程串行启动轮次，新聊天先保存并排队；停止操作中断当前轮，保留已经确认的业务结果，迟到输出仍按题目版本处理。重试前先查询已有回执，避免重复操作。登录失效或运行时需要用户处理授权时，在设置与当前任务中显示可操作的等待状态，不能静默挂起。

面向用户的回复接收 App Server 文本事件后流式显示，不额外要求 Agent 调用“发送聊天”工具。题目、提示、评价和小结通过业务工具提交后生效。材料准备或用户主动请求的任务可显示“准备例句”“读取学习记录”等简短真实状态；后台调度评价只在首页显示汇总状态，不进入翻译页面的进度或消息流。后台参考答案和内部日志不推送到学生界面。

首版网页接口按以下职责提供，路径名称可在编码时统一：

| 接口职责               | 最小行为                                                                    |
| ---------------------- | --------------------------------------------------------------------------- |
| 获取今日计划与会话快照 | 返回预算、候选目标、阶段、当前轮、未完成位置、版本与一致的 `last_event_seq` |
| 提交学习动作           | 自评、答案、开始新轮、暂停或继续；带请求身份和预期版本，返回保存回执        |
| 提交聊天               | 先保存消息，绑定当前题目和版本，再创建对应 Agent 任务                       |
| 订阅事件               | SSE 推送消息片段、业务状态和任务结果，带事件序号                            |
| 查询词条和历史         | 按词形查词；按目标、时间和能力分页追查原始记录                              |

快照返回与其状态一致的 `last_event_seq`，客户端从该序号之后接续 SSE，服务端补发期间已经产生的事件；游标失效时重新获取快照。已处理事件不重复显示或结算。最终完整消息更新原消息草稿，不在后面再追加一份。中断消息有明确状态。题目更新、答案保存、业务事件与待处理任务在可靠提交后才确认成功；任务重试先检查已有业务回执，避免 Agent 重复发布或重复评分。

## 最小学习工具

以下为完整 Demo 计划的业务能力，名称与最终接口可以不同。网页 D0 已实现 `learning_get_context` 与 `learning_publish_materials` 的固定五词组备课子集。mini 当前有 `learning_get_context`、`learning_get_history`、`learning_get_word`、`learning_commit` 四个基础工具，接入语音服务时顾问额外有 `learning_get_audio` 和 `learning_generate_audio`。基础工具覆盖计划与真实历史查询、例句、独立写作、定性反馈、重点和明确偏好。音频工具可查已有资产、请求生成或单条重生成，播放和开始事件来自原生操作。上下文返回当前任务允许的动作；下表仍包含待实现的完整教学能力。所有写入须返回对象身份、版本与处理状态，校验当前会话、计划范围、目标、题目版本和重复请求。

| 能力                         | 用途                                     | 首版边界                                                    |
| ---------------------------- | ---------------------------------------- | ----------------------------------------------------------- |
| `learning_get_capabilities`  | 查询支持的对象、题型、测量规则和工具版本 | 返回真实能力；不支持的类型明确拒绝                          |
| `learning_get_context`       | 读取当前计划、目标、预算、阶段和关键统计 | 包含真实阶段门槛，Agent 不能自行跳过                        |
| `learning_query_history`     | 查询每词原始作答、自评、回看、提示和评分 | 支持分页与事件引用，不只返回摘要                            |
| `learning_lookup_lexicon`    | 查词形、义项、词性和可用音标             | 返回来源，缺失字段明确为空                                  |
| `learning_publish_materials` | 保存当前组的例句与卡片材料               | 限准备阶段；区分原文和 AI 自拟内容                          |
| `learning_publish_exercises` | 发布句子练习、私有参考答案和教学要点     | 绑定本组拼写阶段结束的目标，含三轮失败词；题量受组目标限制  |
| `learning_show_hint`         | 展示分级提示或揭晓                       | 记录实际展示内容、目标与测量影响                            |
| `learning_submit_assessment` | 保存教学反馈或结构化调度评价、理由与证据 | AI 不直接改 due；程序校验后采用，保留版本与回执且不重复结算 |
| `learning_save_summary`      | 保存阶段小结和原始证据引用               | 不直接修改成绩、过关或到期时间                              |

确定性拼写比较由程序完成。写作反馈分别说明目标词、主要意思和附带语法；正确同义表达可能表达成立但目标词未测到，不能据此修改掌握或排期。聊天如果给出了当前答案，也要关联帮助记录；帮助情况不清楚时不记独立成功。教学反馈与调度评价分别保存，后者引用固定原答和帮助证据，由统一规则决定采用。修订保留旧版本与排期前后状态，不能把聊天里新写出的正确答案当成原始首答。

## 数据与调度

数据库可以按以下业务对象组织。表结构可在编码时细化，但身份和状态不能只留在模型聊天中。

| 对象              | 必须保存的事实                                                             |
| ----------------- | -------------------------------------------------------------------------- |
| 材料与来源        | 数据集或文件身份、版本、引用位置、来源链接与许可信息；生成内容另标生成来源 |
| 学习对象          | 稳定 ID、类型、词目及义项身份、词形关系和材料引用；Demo 实际支持词义对象   |
| 目标与计划        | 每日新词目标、组大小、学习范围、计划/规则版本、到期队列与暂停状态          |
| 教学包与轮次      | 准备池、入窗目标及各词阶段、记忆通过组、拼写首答队列、尾部与题目版本       |
| 学习事件与作答    | 观看、自评、揭晓、原始答案、重试关系、实际时间、支持条件和请求身份         |
| 评价与记忆状态    | 固定证据范围、模型/规则版本、结论理由、采用决定、FSRS 参数与排期前后值     |
| 消息与 Agent 任务 | 公开或内部用途、角色线程关联、事件序号、状态、重试和业务回执               |
| 阶段摘要          | 每词首次正确轮次、各轮错误、提示依赖、教学建议与原始记录引用               |

单词身份以词目和义项为基础，同一词来自多个计划或材料时增加关联，复用原有能力记录。不能仅按中文释义相同合并，也不能为每个新计划复制一份记忆历史。

确定性拼写保存首答和订正事实；翻译下一词确认先可靠保存原答、完成事实与逐题待评价任务，再立即前进。评价可后台逐题或合并小批执行，采用决定与对应调度变更保持事务一致；跨库继续采用固定回执恢复协调，不宣称跨库原子事务。界面成功回执依据数据库提交，而不是 Agent 自然语言里的“保存好了”。

调度遵守 [学习流程与评价规则](learning-flow-rules.md)：新词次日首复习，后续基于实际时间和证据更新；未作答不制造失败。每日目标只计最终完成新词，到期复习未清不开放新词；尾部和未完成组保留，用户可暂停，不把昨天的新词目标变成欠账。

后台评价记录题目、原答、词级学习过程、帮助及讨论引用，明确证据时间截断。模型/强度、Skill/规则版本、可读结果理由、采用/拒绝/待核对原因、排期前后值和修订关系均可追溯，不要求保存模型隐式推理。重试复用请求身份，迟到结果按原事件时间重算，不覆盖后来的真实复习。评分状态只在首页呈现，翻译页不出现等待进度。

## 首批词条与材料怎么准备

首批从 NGSL 1.2 或已选核心词表中选取 30～50 个常用词义，优先选择中文提示清楚、词形规则明确的样本。核心词表来源继续保留版本和身份；Demo 不以获得整部商业词典的授权为前提。

以可使用的词典数据为基础整理小型种子包，逐条核对中文义、词性、音标及允许词形；已有来源不足的字段保持缺失，不能让 AI 编造后当作权威数据。词典候选与来源约定见 [产品文档](product.md)。首批不下载整部词典作为开工前提，按最终选用来源保留相应署名和使用条件。

种子包包含稳定目标 ID、词条来源、当前义项、展示信息、拼写题干、可接受词形和少量经核对的简单例句。例句可由 AI 准备，但必须标为自拟，并尽量使用已知词；同义词歧义、英美拼写、大小写与词形政策在进入测验前确定。

开发夹具可以包含固定例句和模拟历史，明确标为测试数据，不写入真实用户成绩。最终验收必须有实际 Codex 备课、查询、聊天与结构化写入；预录回复只用于开发过程，不能作为已接通 Agent 的证据。

| 核对中退出、下一词重试或音频未播完 | 恢复同一核对态；只推进一次，可立即换词并取消旧播放，不显示通用撤销和保存成功提示          |
| 复习三轮后重学腾位                 | 只补待重学复习词；普通复习判断仍是清晰/模糊/忘记，不提前引入新词                          |
| 日目标50、每组20的隔离示例         | 分20/20/10完成，复习不扣新词名额，真实个人设置不被测试修改                                |
| 组满或当日目标完成而窗口还有词     | 最多4个尾部保留原阶段，次日先清复习再继续，不计入已完成                                   |
| 复习三轮未清晰                     | 进入三阶段重学再拼写，无翻译，不计新词完成数                                              |
| 拼写首轮错、第二轮首答对           | 第二轮后退出，不因首轮错误进入第三轮；订正不计首答错误次数                                |
| 第三轮拼写首答仍错                 | 展示答案后可继续，新词进翻译、复习完成本次，失败证据保留用于近排期                        |
| 到期复习尚未处理完                 | 新词入口保持不可开始，可暂停；不通过展示上限隐藏积压                                      |
| 新词最终完成                       | 次日本地自然日安排首次复习，窗口中进行中词不假冒完成                                      |
| 翻译点击下一词而上一题还在评分     | 立即进入下一题；仅首页显示处理中/待重试，不在翻译页显示后台进度                           |
| 半组翻译后退出或服务重启           | 已确认完成和逐题评价任务仍在，不等整组结束才补建任务                                      |
| 评价晚于后来的真实复习返回         | 按原作答时间和版本核对/重算，旧结果不直接覆盖当前排期                                     |
| 追溯一次复习日期变化               | 可查原答、学习/帮助证据、模型规则版本、结论理由、采用决定与排期前后值                     |
| 看词或回看错词                     | 默认观看与自评，无 AI 实时干预；单卡默写由用户主动开启                                    |
| 单卡默写正确或撤销标记             | 只反馈当前练习，不增加整批轮次或通过数量；撤销后收起                                      |
| 首轮某词错误，第三轮错词通过       | 首次错误保留；其他词的首次正确轮次不被改成第三轮                                          |
| 总拼写做到第三词退出               | 重新打开恢复当前未答词或绿色确认状态，后续新轮只重测错词                                  |

| 今天只愿练一个词                   | 在当前阶段推进一个目标后可暂停，其他目标不伪造失败                                        |
| 只打开 mini 首页或学习计划         | 只读预览，不创建学习组、预算或 AI 任务                                                    |
| 今日休息或结束本次                 | 暂停并保留原组；今日覆盖按当地日期失效，不补记失败                                        |
| 原组写作未完但今日只复习           | 保留原组，另开实际到期复习组且不要求写作                                                  |
| 缺席后选择少量恢复                 | 建议不超过 3 词且不增加原容量，保留旧进度和真实间隔                                       |
| 组还没完成但已发生有效回忆         | 词级记录与调度立即保存，不等整组通过                                                      |
| 熟练词停学后回来                   | 根据真实间隔再安排，不清空历史或制造缺席失败                                              |
| 提交后 Node 或 Codex 退出          | 已确认保存的答案仍在，待处理评价可以续接                                                  |
| 重发提交或多个任务重复处理         | 同一次作答只保存一次；旧版本结果不覆盖新题                                                |
| SSE 断线后重连                     | 恢复消息和业务状态，最终回复不重复追加                                                    |
| 后台备课有参考答案                 | 学生页面只收到允许展示的内容                                                              |
| 用户在网页问当前句子的意思         | 陪伴 Agent 收到正确题目上下文，真实回复回到同一页面                                       |
| 译文合理但不同于参考答案           | 按意义评价，目标词未测到时不自动判熟练                                                    |

## 未来如何从词根 PDF 组织学习

用户把 PDF 交给平台内的 Agent，表达想学的范围和预算。未来材料 Skill 可以指导 Agent 完成以下过程：

1. 平台接收并登记原文件、内容哈希和版本，提取可读文字；扫描页使用 OCR，保留实际 PDF 页序、书面页码、提取器或 OCR 版本与可定位片段。同一文件重新提取保留对应片段版本。低质量识别标为待核对，不用模型猜测补齐后冒充原文。
2. Agent 检索相关片段，整理词根、词缀、解释、例词与例句，分别标记原文摘录、基于原文整理和 AI 补充。原文件内容作为学习资料处理，不改变平台工具规则。
3. Agent 查询已有词条和学习历史，复用相同词目、义项与能力的记录。重复导入同一文件不重复建目标，新版本保留旧来源与已发生的学习。
4. Agent 生成可预览的计划草稿，列出范围、目标、来源和预计负荷。用户选择范围并启用计划；算法依据当下容量安排实际新学和复习，不把整本 PDF 一次塞进今日任务。
5. 平台按已支持的对象和题型执行学习，复用卡片、作答、历史、Agent 教学和小结能力。需要新测量规则的内容先补平台能力，再启用对应训练。

例如一份讲构词法的材料，可以先形成“理解某个词根解释＋学习若干关联词义”的计划。已有单词仍沿用原学习历史；词根说明先作为材料和关系保存。拼写相似不自动构成词源关系，原文断言、可靠词典支持与 AI 推测分别记录。

| 对象            | 应如何建模                     | 不能直接等同的内容                   |
| --------------- | ------------------------------ | ------------------------------------ |
| 原始 PDF 与片段 | 有版本、可定位的学习材料       | 不等于学习目标已经完成               |
| 单词义项        | 可关联理解和拼写目标的稳定对象 | 不能因换一本材料就成为全新词         |
| 词根或词缀      | 构词概念及来源明确的关联       | 不能直接当成单词拼写卡或读完即 Good  |
| 具体句子        | 原文或生成材料中的一次表达     | 不等于抽象句式已经掌握               |
| 常用表达或句式  | 可在不同场景练习的语言对象     | 不能用一个整句翻译分数结清所有关联词 |

常用句子未来可以沿用“材料 → 目标 → 计划 → 练习 → 证据 → 复习”的流程，但需分别定义理解、表达和迁移使用的测量规则。词根或句式的复习状态不能直接复制单词参数，单词总拼写门槛也不强制套用到所有未来对象。

## 为扩展保留什么

Skill 提供可复用的工作流程，MCP 提供实时数据与受控动作；这是两者的职责边界。[OpenAI 官方 Skills 说明](https://developers.openai.com/plugins/concepts/skills)

Demo 需要实现稳定对象身份、来源引用、内容与计划版本、能力查询、通用课程提交和完整历史查询。课程结构保留目标类型与测量规则身份，首版实际支持词义对象；未知类型明确返回不支持，不能默默转成拼写题。

后续材料扩展再增加文件登记、提取任务、片段检索、计划草稿与启用等工具。初次 PDF 导入可以先只生成已有词义类型的计划，从而复用背词流程；词根和句式专用目标、题型与调度随后增加。已有 Skill 能组合新工具，但单独新增一份 Skill 文本不会自动获得上传、OCR、词源核对或新界面能力。

新增能力的最小交付应同时包含：平台可执行动作、类型与规则版本、Skill 用法、来源和历史处理，以及一条实际学习验收。这样每次扩展都能复用当前事实记录，不需要重建整套 Agent。
